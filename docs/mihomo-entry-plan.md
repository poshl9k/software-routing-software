# План внедрения: вход через mihomo + клиентский split + роли нод

**Статус:** план принят к исполнению, ни один срез ещё не начат. Документ — единственный источник истины о прогрессе этой работы: следующий агент читает раздел «Журнал статуса» и продолжает с первого незакрытого среза.

**Границы:** ничего не коммитить, не пушить и не деплоить без отдельного разрешения. Сохранять существующие незакоммиченные изменения. `docs/master-portal-plan.md` не редактировать. Не трогать `rg3.poshl9k.ru` и production-ноды. Платежи Stars держать выключенными.

## 1. Задача и критерий успеха

Абонент подключается через клиент на ядре **mihomo** (Clash Meta). Трафик к российским ресурсам уходит **напрямую через провайдера абонента** и не попадает ни на одну нашу ноду. В туннель идёт только «нужное» (заблокированное и зарубежное), и уже оно уходит на зарубежный выход.

Критерий успеха среза: на одноразовой ноде абонентский клиент с нашим YAML открывает российский сайт, и **в счётчиках/журнале ноды этого потока нет**; при этом зарубежный сайт открывается через туннель.

## 2. Принятые решения

| # | Решение | Почему так |
| --- | --- | --- |
| D1 | Сплит делается **на клиенте**, а не на сервере | Только так РФ-трафик не появляется на нашей инфраструктуре; блокировка на ноде — страховка, а не механизм |
| D2 | Сплит по принципу **«в туннель только нужное»** (`MATCH, DIRECT`) | Устаревший список даёт неработающий сайт, а не РФ-выход с нашей ноды |
| D3 | Клиентский формат — **mihomo YAML** (основной) | Единственный клиент с AWG 3.1: `header-protection-key`, `random-trailers`, `disable-cookies`, `S1–S4` |
| D4 | Новый inbound-протокол (VLESS/Reality) **не делаем**, пока mihomo на iOS не провалится на живом тесте | Не строить второй серверный контур без доказанной нужды |
| D5 | Нода остаётся на sing-box; mihomo — только клиент | Не менять серверный сертифицированный контур |
| D6 | Подписка — **per-device токен, хранимый хешем**, отзываемый | Устройство удаляют — ссылка обязана перестать работать |
| D7 | Наборы правил **версионируются и хешируются**, версия видна в админке | Иначе «у клиента ушло в туннель, нода заблокировала» станет необъяснимым |
| D8 | Инвариант согласованности: **клиентский direct-set ⊇ нода-block-set** | Всё, что нода блокирует, клиент уже отправил напрямую |
| D9 | Перенос устройства на другую **зарубежную** ноду = переключение маршрута на входной ноде, а не миграция пира | Клиентский конфиг не меняется вообще |
| D10 | В S1 (до доменных наборов) промежуточные правила: `GEOIP,RU → DIRECT`, `ведомые private → DIRECT`, `MATCH → PROXY` | Работоспособно сразу; это временная инверсия, целевое состояние — включение по набору (D2) на S2 |
| D11 | DNS клиента — `fake-ip`, РФ-домены резолвятся локальными резолверами через `nameserver-policy` | Доменные правила S2 требуют fake-ip; резолвинг РФ-доменов не уходит на нашу ноду |
| D12 | Выдача YAML — и в портале, и в Telegram-боте (`/mihomo <id>`, документ) | Абоненту не нужен вход в веб, чтобы получить профиль |
| D13 | Deep-link «открыть в клиенте» (`clash://install-config?url=…`) — только после S3 | Схема требует **URL подписки**, которого пока нет; inline-конфиг в deep-link ненадёжен |
| D14 | Наборы правил публикуются **неизменяемыми версиями** и отдаются публично по `/{kind}/{version}.yaml` (RFC-style `payload:`), хеш в `sha256`/`ETag` | Клиент пиннит версию в `rule-providers`; список РФ/доменов не секрет, поэтому чтение без авторизации, а исправление — новая версия |
| D15 | Подписка — **один токен на устройство**, хранится `sha256`, URL показывается один раз, перевыпуск заменяет токен | Отзыв при компрометации без влияния на другие устройства; сырой токен не лежит в БД |
| D16 | Доставка профиля по ссылке — `GET /api/portal/sub/{token}` **без сессии** | Клиент mihomo забирает по URL сам, cookie ему недоступны; токен и есть credential |
| D17 | Deep-link `clash://install-config?url=…` появляется в портале вместе со ссылкой | Клиент скачивает профиль по URL, поэтому deep-link возможен только после S3 |
| D18 | Ссылка умирает автоматически: устройство `removed` → 404, подписка истекла → 403 `portal.subscription_expired` | Не нужен отдельный «сборщик мусора»: проверка на каждом запросе, а удаление устройства становится немедленным отзывом |
| D19 | Роль ноды — `entry`/`egress`/`both`, по умолчанию `both`; устройства назначаются только на `entry`/`both` | Сохраняет поведение существующих установок и включает топологию «вход в РФ → выход за рубежом» без миграции данных |
| D20 | Переключение выхода при аварии — **на входной ноде**, а не в клиентском профиле; поэтому `url-test` в YAML не появляется | У клиента один proxy (вход), резервные выходы выбирает sing-box на входе; правка профиля не нужна |
| D21 | Источник списков РФ — **объявленные источники панели** (geoip/домены с автообновлением), а не сторонний community-список | Список уже ведётся и обновляется панелью; мастер не заводит второй источник истины |
| D22 | Мастер импортирует источник по HTTPS один раз (`/rulesets/import`) или держит его как **автообновляемый источник** (`master_rule_set_sources`), публикуя новую версию только при изменении хеша | Клиенты пиннят версию; автообновление не переписывает историю и не требует ручных действий |
| D23 | Импорт отклоняет `keyword:`/`regexp:` и бинарные `srs` | mihomo `behavior: domain` не выражает эти матчеры; тихая публикация изменила бы смысл правил |
| D24 | Встроенные пресеты панели (`sing-geoip`/`sing-geosite`) отдаются как `.srs`/geosite — `.srs` **не импортируется** (его не декодирует и нода: `rulesets.py:179–188` помечает набор `activatable=False`) | Декодер `.srs` создал бы возможность, которой нет даже на ноде; список всё равно не совпадал бы с применяемым |
| D25 | Мастер принимает **sing-box JSON rule-set** (`{"version":3,"rules":[…]}`): `domain`, `domain_suffix` → `+.suffix`, `ip_cidr`; прочие матчеры (`domain_keyword`, `domain_regex`, `network`, …) отклоняются | Это формат, который панель реально активирует; один и тот же URL источника у панели и у мастера. `domain` в sing-box точный, а в mihomo payload — суффиксный, то есть клиентский direct-set расширяется, что не нарушает D8 |
| D26 | Дефолтные источники (миграция `0011_master`): `ru-ips` — **RIPE delegated stats** (страна RU, официальные данные реестра), `ru-domains` — `v2fly/domain-list-community data/tld-ru` | Панель не содержит текстового списка РФ: её `geoip-ru` — `.srs` (непригоден), а `category-ru` состоит из `include:`, который импортёр не разворачивает. RIPE — авторитетный и лицензионно чистый источник адресов; tld-ru даёт `+.ru/.su/…` |
| D31 | DNS в профиле разделён: `+.ru`/`+.su` резолвит `system` (DNS провайдера), остальное — резолвер ноды; `respect-rules: true` гонит запросы через туннель. Плюс `sniffer` (`parse-pure-ip`, `override-destination`) и `mtu: 1280`, если нода не задала MTU | Браузеры с собственным DoH подключаются по IP и ломали RU-раздел; MTU 1408 по умолчанию «чернит дыру» на крупных TLS ClientHello |
| D30 | Пир мастера **без** `PresharedKey`: mihomo 1.19.33 с AWG 3.1 не может завершить handshake против `amneziawg-go` v3.1, если у пира есть PSK (`invalid response message`) | Воспроизведено локально на эталонном сервере: (PSK сервер/клиент) нет/нет → handshake ok, да/да → invalid, нет/да → ok, да/нет → invalid. На живой ноде `rg3` ровно два пира с PSK — оба созданы мастером и оба не работали; все рабочие пиры без PSK. Эталонный клиент `amneziawg-go` с PSK работает, то есть это дефект клиента mihomo, а не ноды |
| D29 | Ссылка в кабинет постоянная (до ротации пользователем), сессия 30 дней; одноразовый `magic` (10 мин) сохранён как запасной путь | Пользователь не должен запрашивать вход каждый раз; плата — постоянный credential в переписке, поэтому ротация по кнопке и предупреждение «не пересылайте» |
| D28 | Токен подписки хранится **двумя** копиями: `token_hash` для поиска и `token_secret` (Fernet, тот же мастер-ключ, что у `bridge_token` и ключей устройств) — чтобы кабинет показывал ту же ссылку и QR; ротация только по кнопке | Без расшифровываемой копии ссылку нельзя перерисовать, и каждый просмотр означал бы новый токен. Компромисс: утечка БД + мастер-ключа даёт доступ к ссылкам — как и к ключам устройств, которые там уже лежат |
| D27 | В импортёре один-лейбл запись трактуется как TLD и превращается в `+.label`; `include:` — явная ошибка `master.ruleset_format_unsupported` | Голый `ru` в mihomo payload неоднозначен; молчаливое разворачивание `include` меняло бы набор |

Следствие D9: раздел «перенос пира» в `docs/future-work-master-platform.md` в прежнем виде устарел — он нужен только для случая «клиент подключается напрямую к зарубежной ноде без входной».

## 3. Открытые вопросы

- O1. iOS: проходит ли `amnezia-wg-option` c `version: 3` в App Store-клиенте на mihomo и в Stash. Проверяется только на устройстве.
- O2. Доменный набор: `GEOIP` работает из встроенной базы mihomo, а `GEOSITE` зависит от geodata-файлов клиента — решается своим `rule-provider`.
- O3. Роли нод: одна нода может быть одновременно входом и выходом или это запрещено моделью.
- O4. Точка распространения Android-клиента: ссылаться на официальный FlClash / Clash Meta (нет GPL-обязательств) или собирать свой APK (GPL-3.0).

## 4. Целевая схема

```
абонент (mihomo)
 ├─ RU / private / local ──► напрямую через провайдера абонента   (нода не видит)
 └─ нужное ──AWG 3.1──► нода-вход (РФ) ──AWG client──► нода-выход (за рубежом) ──► интернет
                            │
                            └─ страховка: dest ∈ ru_set → block (fail-closed)
```

## 5. Срезы

Каждый срез — отдельный проверяемый шаг. Срез не считается закрытым, пока не выполнены все его критерии и не записана строка в «Журнал статуса» с указанием уровня доказательства (unit / Linux / живой хост).

### S1. Экспорт `mihomo` (без схемы, без ноды)

**Состояние: реализован (см. журнал).**

**Цель:** абонент скачивает рабочий YAML для текущего AWG-устройства.

- `backend/src/vs_master/exports.py`: `device_export` принимает `format='mihomo'`; новый рендер `_mihomo_yaml(device, tunnel, key)` из того же `state['tunnel']`, что `_conf_text` (строки 34–88) и `_amnezia_uri` (91–126).
- YAML: `proxies[0]` `type: wireguard` + `amnezia-wg-option` **на верхнем уровне прокси**, `version: 3`, поля `AWG_ORDER` + `header-protection-key` + `random-trailers` + `disable-cookies`; `proxy-groups` c `url-test`; `rules`: `GEOIP,RU,DIRECT`, `IP-CIDR,<private>,DIRECT`, `MATCH,DIRECT`; `dns` без утечки РФ-доменов к нам.
- Отказ `portal.export_unavailable`, если для AWG 3.1 нет `header_protection_key` (как в `_conf_text`, строки 66–68).
- Роут `GET /api/portal/devices/{identity}/export?format=mihomo` — уже общий обработчик (`exports.py:159–167`); заголовок `Cache-Control: no-store` обязателен.
- `frontend-master/src/api.ts`: расширить тип формата; `SubscriberPortal.tsx:149–165` — добавить ветку скачивания `.yaml`.
- `backend/src/vs_master/device_bot.py:126–129`: `mihomo` как документ, расширить карту суффиксов.

**Приёмка:** golden-YAML в `backend/tests/golden/`; тесты на отказ без HPK, на отсутствие секретов в сообщениях об ошибках, на `no-store`; frontend-тест кнопки; `npm run typecheck`, `npm run build`, focused pytest. Живой хост не нужен.

**Не входит:** подписка, наборы правил по URL, роли нод, изменения на ноде.

**Изменённые файлы:** `backend/src/vs_master/exports.py` (`_mihomo_yaml`, `_awg_option`, `_yaml_lines`, `_host_port`), `backend/src/vs_master/device_bot.py` (action `mihomo`, кнопка «Clash»), `backend/tests/test_master_portal.py`, `backend/tests/test_master_bot_devices.py`, `backend/tests/golden/master-mihomo-awg31.yaml`, `frontend-master/src/api.ts`, `frontend-master/src/SubscriberPortal.tsx`, `frontend-master/src/App.test.tsx`.

### S2. Доменный набор правил (`RuleSet`)

**Состояние: backend реализован; админ-UI вынесен в S2b.**

Факт реализации: модель `RuleSet` (`master_rule_sets`, миграция `0007_master`), нормализация и хеширование в `vs_master/rulesets.py`, публичная выдача `GET /api/rulesets/{kind}/{version}.yaml` (`rulesets_api.py`), админ-API `GET|POST /api/master-admin/rulesets`, подстановка `rule-providers` в mihomo-YAML при заданном `master_public_url`. Правила `RULE-SET,ru-domains,DIRECT` и `RULE-SET,ru-ips,DIRECT` идут **перед** `GEOIP,RU,DIRECT`.

**Цель:** доменные правила не зависят от geodata-файлов клиента.

- Миграция мастера (следующая после `0006_master`): таблица `master_rule_sets` (`kind`, `version`, `sha256`, `path`, `published_at`).
- Публичный роут выдачи набора по версии; содержимое неизменяемо, хеш сверяется при чтении.
- В YAML: `rule-providers` c точной версией в URL + `RULE-SET, blocked, <group>` перед `MATCH`.
- Админка мастера: вкладка «Наборы правил» — версия, хеш, источник, публикация/откат.

**Приёмка:** тест неизменяемости (хеш не совпал → отказ), тест подстановки версии в YAML, тест админ-эндпоинтов; публикация набора не требует перезапуска сервисов.

### S3. Подписка с токеном (`DeviceSubscription`)

**Состояние: реализован.**

Факт реализации: модель `DeviceSubscription` (`master_device_subscriptions`, миграция `0008_master`), `vs_master/subscriptions_api.py`: `POST|GET|DELETE /api/portal/devices/{id}/subscription` (сессия) и публичный `GET /api/portal/sub/{token}`; портал — кнопка «Ссылка-подписка», диалог с выдачей/копированием/перевыпуском/отзывом и deep-link `clash://install-config?url=…`.

- Миграция: `master_device_subscriptions` (`device_id`, `token_hash`, `created_at`, `last_used_at`).
- `GET /api/portal/sub/{token}` → YAML (YAML генерируется на мастере, ключи расшифровываются только в памяти), `no-store`, без логирования токена.
- Портал: кнопка «Ссылка-подписка», «перевыпустить», «отозвать», «последнее обновление».
- Отзыв при удалении устройства и при истечении подписки.

**Приёмка:** истёкший/отозванный токен → 404 без раскрытия; повторный запрос не продлевает срок; удаление устройства отзывает подписку; токен не попадает в логи/аудит.

### S4. Роли нод и цепочка выходов

**Состояние: мастерская часть реализована; настройка цепочки на самой ноде вынесена в S4b (нужны одноразовые ноды).**

Факт реализации: `Node.role` (`entry|egress|both`, default `both`) и `Node.public_entry`, `Device.egress_node_id` (миграция `0009_master`); админ-API валидирует роль и адрес входа; `PATCH /api/master-admin/subscribers/{account}/devices/{id}` задаёт предпочтительный выход (только `egress`/`both`, не собственная нода устройства, не отключённая); удаление ноды блокируется, если она используется как выход; назначение новых устройств ограничено нодами `entry`/`both`; в админке — чип роли, адрес для клиентов и поля при создании ноды.

- Мастер: `Node` + `public_entry`, роли `entry`/`egress`; `Device.egress_node_id`.
- Нода: несколько туннелей `role: client` (уже есть, `schema.py:235`) + правило «субъект → выход-туннель»; переключение выхода выполняется на входе (D20), клиентский YAML не меняется.
- Админка мастера: бейджи ролей, публичный адрес отдельно от `bridge_url`.
- Failover выхода = переключение маршрута на входе; клиентский конфиг не меняется (D9).

**Приёмка:** на двух одноразовых нодах выход падает → новые соединения идут через второй; клиентский YAML побайтно не изменился (хеш).

### S5. Fail-closed на ноде для РФ-назначений

- Нода: набор РФ-префиксов + правило «абонентские пиры → ru_set → block» (тип выхода `block` уже в модели).
- Соблюдение D8: нода блокирует **подмножество** того, что клиент отправляет напрямую.
- Диагностика: журнал блокировок без адресов абонентов.

**Приёмка:** клиент с `AllowedIPs 0.0.0.0/0` (искусственно сломанный сплит) не выпускает РФ-трафик через ноду; счётчик блокировок растёт; обычный сплит-клиент блокировок не вызывает.

### S6. Резерв, только если O1 провалится

VLESS+Reality inbound на ноде. Требует отдельного ADR: новый серверный контур, users/UUID, лимиты, apply/revert, секреты. Не начинать без результата теста iOS.

## 7. Ловушки

1. `amnezia-wg-option` кладётся **в прокси**, не в `peers` — самая частая ошибка генерации.
2. Без `version: 3` mihomo берёт legacy-реализацию и не примет `header-protection-key`/`random-trailers`.
3. Нельзя смешивать v1.5-параметры (`j1–j3`, `itime`) с v3 — реализация их отвергает. Наш генератор их не выдаёт, не добавлять.
4. YAML содержит приватный ключ устройства и HPK: `no-store`, никаких секретов в логах, аудите, тексте ошибок.
5. `GEOSITE` зависит от geodata на клиенте — домены только через свой `rule-provider`.
6. GPL-3.0 у mihomo: раздача собственного APK создаёт обязательства по исходникам.
7. Клиентский direct-set должен быть шире нода-block-set (D8), иначе абонент получает обрыв вместо сайта.
8. `MATCH, DIRECT` последним правилом: правило-«инверсия» (`всё кроме РФ`) запрещено принимать как решение.

## 8. Протокол проверки

- Windows: focused pytest с `--basetemp` в scratch Hermes; полный suite на Windows падает на `pwd`/`grp` — не выдавать за провал продукта.
- Linux-проверка: полный suite в контейнере на копии репозитория с нормализованными CRLF и восстановленными exec-битами.
- Сетевые срезы (S4–S5): только одноразовые ноды, отдельный `known_hosts` с независимо подтверждённым ED25519-ключом, backup и rollback до изменений.
- Каждый срез фиксируется в журнале с уровнем: **unit** / **Linux** / **живой хост**. Уровни не смешивать.
