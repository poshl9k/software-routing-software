# Composite exit — implementation contract

Status: implementation slice; existing ADR-0029 and CONTEXT.md semantics prevail.

## Intent

A routing rule may target an existing `ProxyGroup` with `type=urltest`, whose ordered member exits can be existing **client tunnels**, host interfaces, or declared proxy outbounds. One group tag remains the rule's `Exit{kind: group, tag: ...}`. The sing-box URL-test periodically probes each member THROUGH that member's outbound and chooses an available/low-latency member for new connections. This is not strict ordered failover: native `urltest` selects by probe latency/tolerance. Existing connections may not migrate. Never imply a successful WireGuard handshake alone proves Internet reachability.

## Data / generation

Extend the EXISTING `ProxyGroup` with optional `exits: tuple[Exit,...] = ()` (JSON `exits` array). Each `Exit` reuses ADR-0029's exact shapes; allow only `kind=tunnel|interface|outbound`, with a distinct target for every member. Existing `outbounds` continues to mean legacy tag members. A group has exactly one nonempty member representation (`outbounds` OR `exits`), not both. `exits` requires `type=urltest` (no silent manual selector). Preserve old documents and old proxy group behavior unchanged. Generate a deterministic sing-box outbound for each tunnel/interface via existing `routing_exit_tag` and `bind_interface`; proxy references reuse their existing tag. Render group's `outbounds` as member tags in original order; keep the existing URL/interval/tolerance fields. A rule that references the group must cause ALL member outbounds, including bound tunnel/interface outbounds and proxy exits, to be rendered even when `proxies.enabled=false`. Do not add a second naming scheme or mutate the tunnel/default host routes. Validate tunnel exists AND role=client, interface exists (and is not an inbound/server tunnel's interface), proxy outbound exists, collision with all generated and declared tags, no empty/duplicate/mixed/invalid references. Preserve fail-closed: do not implicitly add `direct` or WAN to a composite; an operator may explicitly include an existing WAN interface, and UI warns of that choice. Unreferenced groups retain existing behavior when proxies.enabled=true.

## Tunnel visibility

`GET /api/tunnels/availability` (authenticated, read-only) returns a map keyed by **configured tunnel name** with `{state: "recent_handshake"|"stale_handshake"|"never_handshaked"|"unknown", last_handshake: int|null}`. Only client tunnels; derive the server public key from `Tunnel.server_public_key`, match it to live `tunnel_activity` agent output for the configured interface; compare the timestamp to current time with an explicit 180-second threshold. `unknown` on agent failure/malformed telemetry/unapplied tunnel; `never_handshaked` only if the live device is observed and its server peer is present with timestamp 0. Do not label handshake as probe availability or assert the URLtest-selected member from this endpoint. No secrets/endpoint exposed. Existing `/api/tunnels/activity` unchanged.

Frontend `ProxyGroup.exits?: RoutingExit[]` mirrors backend. In the existing group editor, for `urltest` offer explicit existing client tunnels, interfaces, proxy outbounds as member choices in user-controlled order; do not present server tunnels. Save the exact `exits` shapes; existing tag-based groups remain editable unchanged. Warn that URL-test chooses by probe latency, not fixed priority, and WAN is used only when explicitly included. In tunnel list, show the new read-only handshake signal for client tunnels and distinguish unknown, never, stale, recent; keep a visible note that it is NOT an end-to-end availability probe. In the read-only group view, use existing `/api/runtime/proxies` (Clash API) to display the running group's selected member and each member's last URL-test sample; only a fresh positive sample is labelled reachable, stale/missing/error remains unknown. Distinguish running configuration from draft. Poll via existing TanStack Query conventions, surfaced errors, no invented green status. No new dependencies. Russian strings; follow docs/ui-rules.md and all-design-stack.
