# Черновой DNS split: два изолированных Unbound-конфига

## Реализация без активации

`backend/src/vs_router/generators/unbound.py:generate_tproxy_unbound_split` — **offline-only** генератор двух строк конфигурации. Исходный `generate_unbound()` и действующий apply не меняют свою семантику; новый код не подключён к bundle, сервисам, агенту, preview или boot restore. Для генерации требуется test-only `model_copy(enabled=True)`; публичный `tproxy.not_available` остаётся.

- `selected`: слушает IPv4-адреса всех `tproxy.ingress_interfaces`, повторяет локальные записи и явные доменные forwards, остальные запросы направляет на предполагаемый loopback DNS-stub `127.0.0.1@15353`. Конфиг добавляет `do-not-query-localhost: no` **только здесь**: без этой настройки Unbound игнорирует такой upstream, хотя `unbound-checkconf` завершается успешно.
- `ordinary`: слушает остальные адреса из `dns.interfaces` (либо loopback, если их нет); использует неизменённые локальные записи, явные forwards, глобальные upstream/recursion. Не содержит нового stub.
- Генератор отвергает отсутствующий DNS listener на выбранном ingress, повторные IPv4-адреса (включая другие интерфейсы), IPv6 DNS listener, `recursive=True` и явный root `forward-zone "."`: нельзя без отдельного решения молча изменить их семантику. Все прочие поля тестового `model_copy` повторно валидируются с временно снятым битом enabled.

**Критично:** два текстовых конфига ещё не дают изоляцию источника. Для настоящего split нужны два процесса с раздельными кэшами и правами на OUTPUT, INPUT/PREROUTING-проверка `iifname` и IP listener до `established` (иначе клиент может обратиться к IP другого экземпляра), реальный DNS-stub sing-box, независимый fail-closed при отказе, безопасный порядок apply/boot/rollback. Явные forwards должны сохранять доступ даже при отказе движка, но требуют отдельной авторизации по сокету и адресу назначения. Доступ к stub нельзя открыть со стороны LAN. В схеме допускаются источники на одном интерфейсе по устройству, но текущая draft-модель выбирает только интерфейсы; при устройственном выборе такой IP split неприменим без новой границы.

## Проверка

На одноразовой Debian VM `vsr-verify-20261002` в госте временно установлен Unbound 1.26.1-0+deb13u1, отдельно переданы оба сгенерированных конфига. `unbound-checkconf` для `selected` и `ordinary` завершился без ошибок. Первая проверка выбранного конфига предупредила: `do-not-query-localhost: yes means that the address will not be used for lookups`; после исправления повторная проверка прошла **без предупреждения**. Host-free тесты проверяют раздельные listener/root, общие локальные записи/явные forwards, недопустимые конфигурации и закрытый публичный gate.

Это **синтаксическая проверка** двух конфигов, не запуск двух Unbound-процессов и не пакетное доказательство DNS split, отказа или отсутствия утечек. VM возвращена к снимку `pre-singbox-20261002` и выключена. Не включать TProxy на основании этой проверки.
