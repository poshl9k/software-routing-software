# Спeцификация агента — сбор референсов Keenetic UI

Ты — исследовательский агент. Работаешь в репозитории `software-routing-software`.
Твоя задача: собрать референсы ОДНОГО блока разделов веб-интерфейса Keenetic
(KeeneticOS web configurator) по официальной документации и зафиксировать UX/UI-логику.

## Жёсткие правила

1. Пиши ТОЛЬКО под `docs/ui-refs/keenetic/` (markdown + `screenshots/`). Никакого кода,
   никаких правок frontend/backend, никаких коммитов.
2. Только реальные данные из документации. Ничего не выдумывать. Каждое утверждение
   о UI — из статьи или скриншота. В конце документа — список источников (URL).
3. Скриншоты: скачивай реальные PNG (`curl`) в `screenshots/<твой-префикс>/` и
   описывай их через `vision_analyze`. Не описывай картинку, которую не загрузил.
4. Отчёт по работе = файл. Не пересказывай процесс.

## Как добывать материал

- TOC: `docs/ui-refs/keenetic/keenetic-toc.txt` (поля: `<slug> | <название>`).
  Ищи свои статьи: `grep -iE '<ключ>' docs/ui-refs/keenetic/keenetic-toc.txt`.
- URL статьи: `https://support.keenetic.ru/eaeu/ultra/kn-1811/ru/<slug>`
  (slug уже включает числовой id, напр. `13914-system-dashboard.html`).
- Скачать статью: `curl -sSL -m 30 '<url>' -o /tmp/art.html`
- Вытащить скриншоты: `grep -oE 'src="[^"]*asset/images/[^"]+\.(png|jpg)"' /tmp/art.html`
  → абсолютный адрес: `https://support.keenetic.ru/eaeu/asset/images/<файл>`
  (префикс `../../../` отбросить). Часть картинок — иконки 28x28, отбрасывай по размеру.
- Текст статьи: `python3 -c "import re,html; s=open('/tmp/art.html',encoding='utf-8',errors='replace').read(); s=re.sub(r'<script.*?</script>','',s,flags=re.S); s=re.sub(r'<style.*?</style>','',s,flags=re.S); print(html.unescape(re.sub(r'<[^>]+>',' ',s)))" | tr -s ' \n' ' \n' | head -c 20000`
- Скачать картинку: `curl -sSL -m 30 '<url>' -o docs/ui-refs/keenetic/screenshots/<prefix>/<name>.png`
  Проверить: `file <path>` должен показать `PNG image data`, иначе удалить.
- Разглядывать: инструмент `vision_analyze` (локальный путь png).

Если статья 404 или содержит не то — ищи другую статью по TOC.

## Шаблон выходного файла (строго)

```markdown
# Keenetic UI — <название блока>

Краткая суть блока в 1–3 предложениях.

## Навигация
Где блок в интерфейсе Keenetic, как выглядит левое меню/подменю/вкладки.

## Экраны и структура
Для каждого экрана: сверху вниз — что за блоки, заголовки, порядок.

## UX/UI-логика (паттерны)
Нумерованный список конкретных решений: разметка списков, inline-редактирование vs
отдельная форма, «применить/сохранить», статусы сервисов, фильтры/поиск, группировка,
раскрытие «дополнительно», модальные окна, пустые состояния, тексты кнопок.

## Элементы управления
Таблица: назначение → тип контрола → поведение (напр. «вкл/выкл сервиса → переключатель
в шапке → сразу пишет в конфиг»).

## Состояния и обратная связь
Пустое состояние, ошибки, индикаторы работы сервиса, подтверждения.

## Скриншоты
Список скачанных файлов + 1–2 строки, что на каждом видно (по результату vision_analyze).

## Что переносим в vs-router
Отображение нашим разделам: что берём, что не подходит и почему.

## Источники
- <url статьи> — «<название>»
```

Стиль: по-русски, плотно, без воды. Технические термины — латиницей (firewall, NAT, DHCP).
