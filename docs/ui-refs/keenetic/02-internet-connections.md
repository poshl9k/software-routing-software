# Keenetic UI — Интернет: подключения и сетевые порты

Раздел объединяет проводные, мобильные и WISP-подключения, настройку их физических портов, адресации и резервирования. Политики определяют приоритет каналов и то, какие клиенты/сегменты ими пользуются; локальные сегменты настраиваются отдельно в «Мои сети и Wi-Fi».

## Навигация

- В дереве документации: «Интернет» → «Способы подключения к Интернету» → «Проводной» (Ethernet, WAN MAC, PPPoE, PPTP/L2TP), «Mobile» (5G/4G/3G), «Wireless ISP», «Приоритеты подключений». «Интернет», «Проводной», «Mobile» — рубрики документации; экранные названия точнее: «Подключения к интернету по Ethernet-кабелю», «Подключения к интернету через сотовую сеть», «Подключение к интернету через публичную/соседнюю сеть Wi-Fi». [13228, 13229, 13230, 13231, 13777, 14488, 17892]
- WISP на двухдиапазонных моделях: вкладки «WISP 2,4 ГГц» / «WISP 5 ГГц». Приоритеты: «Политики доступа в интернет» / «Применение политик». [14488, 17892]
- «Мои сети и Wi-Fi» → «Сегменты» / «Домашняя сеть» — локальные IP, DHCP, членство портов в сегментах и VLAN; не путать с WAN VLAN провайдера. «Общие настройки системы» → «Сетевые порты» — скорость, дуплекс, отключение физического порта. «Системный монитор» → «Интернет» — сводка активного и резервного подключения. [14006, 14628, 14629, 16485, 42408]

## Экраны и структура

1. «Подключения к интернету по Ethernet-кабелю»: заголовок и пояснение → горизонтальные вкладки по провайдерам («Ethernet-подключение» и «+» добавления) → строка включения, текстовый статус → «Порты и VLAN'ы» со схемой пронумерованных разъёмов и их назначением → «Параметры IPv4» (авто/ручная/не используется; адрес, маска, шлюз, DNS, MTU) → «Требования провайдера» (MAC) → «Аутентификация у провайдера (PPPoE / PPTP / L2TP)» → Ping Check; внизу доступно «Удалить подключение». Порядок последних секций может зависеть от конфигурации и версии снимка; подтверждены названия и состав, а не универсальная последовательность. [13231, 13772, 13773, 13774, 16485, 19727; скриншоты 13231-01, 16485-02, 16485-05]
2. IPoE: кабель в порт 0; обычно DHCP без логина. Для статического адреса в «Параметры IPv4» выбрать «Ручная» и заполнить IPv4-адрес и выданные провайдером параметры. PPPoE: в «Тип (протокол)» выбрать PPPoE, указать имя пользователя/пароль; «Показать дополнительные настройки PPPoE» раскрывает имя сервиса, имя концентратора и дополнительные параметры IP. Есть «Импорт настроек из прежнего маршрутизатора». PPTP/L2TP: выбрать протокол, адрес сервера, имя пользователя/пароль; дополнительные настройки содержат метод проверки подлинности, MPPE для PPTP, IP/IPv6. [13231, 13773, 13774]
3. Проводные порты/VLAN: у каждого разъёма своя пиктограмма и выпадающий список «По умолчанию», «Провайдер», «ТВ-приставка», «Телефония»; ниже раскрываемые «VLAN для интернета, IP-телефонии и IP-телевидения» с соответствующими полями VLAN ID. Роль LAN→WAN задаётся в форме провайдера, а не отдельным inline-переключателем в общем списке. У SFP-моделей для дополнительного провайдера сначала «+». Отдельно «Общие настройки системы» → «Сетевые порты» показывает режимы скорости/дуплекса каждого порта (по умолчанию авто). [16485; скриншоты 16485-01, 16485-02, 16485-04]
4. «Подключения к интернету через сотовую сеть»: заголовок → вкладка оператора → переключатель подключения и статус → селекты расписания, приоритета («Основное подключение»/резервное), типа подключения, имя провайдера → «Метрики сигнала», статус SIM → настройки модема (сканирование эфира, сеть, APN, аутентификация, roaming, IPv6/DNS) → Ping Check. Доступность отдельных полей/метрик зависит от модема. [13777; скриншот 13777-03]
5. Wireless ISP: заголовок → вкладки диапазонов → строка переключателя/статуса → расписание, приоритет, тип подключения и имя провайдера → «Обзор сетей» (окно списка доступных Wi-Fi) → SSID/защита сети подставляются при выборе; пароль вручную → IPv4 авто или вручную → включение. BSSID можно указать для выбора точки с одинаковым SSID; Ping Check при резервировании. [14488; скриншоты 14488-01, 14488-02]
6. «Приоритеты подключений»: заголовок и пояснение → две вкладки. «Политики доступа в интернет» — таблица: слева политики («Политика по умолчанию», созданные вручную, «Добавить политику»), справа подключения с чекбоксами, индикаторами и ручками перетаскивания, затем «Управление полосой пропускания» с иконкой редактирования; внизу «Добавлять новые подключения автоматически». Вкладка «Применение политик» — слева политики с количеством объектов, справа перетаскиваемые чипы зарегистрированных клиентов и сегментов; «Показать все объекты», при выделении — «Переместить в», «Подтвердить», «Отменить». [17892, 37129; скриншоты 17892-01—03, 37129-01]
7. «Мои сети и Wi-Fi» → «Сегменты»: «+» добавления сегмента, имя → Wi-Fi сети → «Порты и VLAN» / «Разъемы сегмента и VLAN» (матрица портов × сегментов и VLAN ID) → «Параметры IP» (IPv4/IPv6, DHCP, NAT) → «Правила использования интернет-трафика» (политика для сегмента, ограничение скорости). В базовом Home порты и основная Wi-Fi точка объединены; Guest изолирован. Названия/расположение секций отличаются на снимках старой «Домашней сети» и новой «Сегменты». [14628, 14629; скриншоты 14628-01, 14628-08, 14629-02]

## UX/UI-логика (паттерны)

1. Подключение — не одна inline-строка с редактируемыми полями: вкладка-провайдер открывает длинную форму со сгруппированными секциями. На вкладке рядом «+»; прямо под ней компактная строка «Ethernet-подключение» с переключателем и статусом. Сводка «Системный монитор» → «ИНТЕРНЕТ» — вертикальный список строк: тумблер, имя, тип, зелёный бейдж «ПОДКЛЮЧЕНО», длительность, chevron раскрытия; у модема подпись «Резервное соединение». Нет единого обязательного отдельного «карточного» редактора на каждый параметр. [16485, 42408; скриншоты 16485-03, 42408-04]
2. Статус различает работоспособность и административное включение: Ethernet показывает включённый синий тумблер и красное «Проверьте кабель» при отсутствии линка; WISP с выключенным тумблером — серое «Отключено»; подключённый мобильный канал — зелёное «Подключено». В мониторе у основного и резервного возможны одновременно зелёные «ПОДКЛЮЧЕНО», но только резервный помечен текстом «Резервное соединение». Не сводить все состояния к бинарному «включено/выключено». [16485, 14488, 13777, 42408; скриншоты 16485-05, 14488-01, 13777-03, 42408-04]
3. WAN VLAN — раскрытие внутри формы Ethernet: поле(я) VLAN ID для услуг + визуальное назначение разъёмов выпадающими списками; локальный VLAN сегмента — отдельное поле в форме сегмента, а членство порта в сегменте выбирают в матрице («Не входит в сегмент», «Входит в сегмент», «Входит в сегмент с VLAN»). MAC — селект в «Требования провайдера»: «По умолчанию», «Взять с вашего ПК», «Вручную»; ручное значение вводится в поле формы, не inline в строке списка. Клонирование с ПК возможно при Ethernet-подключении ПК. MTU — поле «Размер MTU» прямо в «Параметры IPv4», для PPPoE/PPTP/L2TP — после «Показать дополнительные настройки» в той же форме; диапазон 64–1500, для IPoE рекомендуется 1500. [16485, 14629, 13772, 19727; скриншоты 16485-02, 14629-02, 13772-01, 19727-01—02]
4. TTL: статья «Управление значением TTL» говорит, что с KeeneticOS 3.1 изменение входящего/исходящего TTL — только CLI (`interface {name} ip adjust-ttl send|recv {ttl}`); старое «Не уменьшать TTL» в веб-интерфейсе относилось к версиям до 3.1. При этом снимок формы мобильного подключения показывает селект «Установить TTL» = «Отключено». Это расхождение версий/контекстов источников: не делать вывод, что WAN IPoE сейчас имеет такой селект или что CLI-ограничение статьи относится ко всем мобильным экранам. [19729, 13777; скриншот 13777-03]
5. Приоритеты — порядок строк подключений внутри политики меняется drag-and-drop за ручку, верхнее соединение основное. Политика отмечает нужные подключения чекбоксами; дополнительная политика может содержать только VPN или резервный канал. Отдельная вкладка назначает политику клиентам/сегментам перетаскиванием; также политику отдельного клиента можно выбрать в его настройках. «Политика по умолчанию сегмента» у клиента позволяет наследовать выбор сегмента. Не смешивать приоритет канала и приоритет пользовательского трафика. Не более 16 политик. [17892, 14628; скриншоты 17892-01—03, 17892-05]
6. Ограничения входящей/исходящей скорости задаются в дополнительной политике: «Управление … трафиком» → «Вручную», далее два лимита в кбит/с или Мбит/с; в таблице видны стрелки ↓/↑ и карандаш. Для политики по умолчанию недоступно; действует только для IPv4. [37129; скриншот 37129-01]
7. Резерв: Ethernet + модем или второй Ethernet/WISP; более высокий приоритет → основной, потеря линка, сбой Ping Check либо отключение интерфейса → следующий доступный шлюз; после восстановления основного канала — возврат. Ping Check при сценарии Ethernet→модем настраивается только на основном. Резервный порт второго проводного провайдера добавляют «+» в Ethernet; мобильный канал может автоматически определиться после подключения совместимого модема. [42408, 17893, 17892]
8. Расписание IPoE, WISP, мобильных, VPN и Wi-Fi подключений: «Добавить расписание» открывает редактор с названием и сеткой дней недели × часов; выделены часы работы, пустые — нерабочие. Нужны верные часы/часовой пояс роутера. [14039; скриншот 14039-02]
9. Смена WAN→LAN в приведённом сценарии модема: «Удалить подключение» на странице Ethernet → порт 0 автоматически входит в домашний сегмент; перед операцией статья советует сохранить startup-config.txt. Для LAN→WAN сначала отсоединить кабель провайдера, назначить порт «Провайдер», сохранить, затем подключить кабель. Одинаковый WAN VLAN ID на нескольких проводных портах некоторых моделей невозможен из-за аппаратного коммутатора. [16485, 38469]

## Элементы управления

| Назначение | Контрол | Поведение |
|---|---|---|
| Добавить Ethernet-провайдера | «+» рядом с вкладкой | Открывает отдельную форму нового проводного подключения; дополнительный WAN-порт назначается в «Порты и VLAN'ы». [17893, 16485] |
| Включить канал | Тумблер под вкладкой/в мониторе | Отдельно от текстового статуса соединения. [16485, 13777, 14488, 42408] |
| Роль порта | Выпадающий список под иконкой порта | «По умолчанию», «Провайдер», «ТВ-приставка», «Телефония»; затем сохранить. [16485] |
| WAN VLAN | Раскрываемый подраздел + поля VLAN ID | Значения провайдера вводятся в форме проводного подключения. [16485] |
| WAN MAC | Селект + условное поле ввода | По умолчанию / взять с ПК / вручную. [13772] |
| IPv4 и MTU | Селект авто/ручная и текстовые поля | Ручная адресация раскрывает поля IP; MTU в «Параметры IPv4» или дополнительных настройках протокола. [13231, 19727] |
| PPPoE, PPTP/L2TP | Селект протокола + поля учётных данных | PPTP/L2TP требуют адрес сервера; «Показать дополнительные настройки» раскрывает специфичные поля. [13773, 13774] |
| Выбрать WISP | «Обзор сетей» → окно выбора | Выбор подставляет SSID/защиту; пароль вводят отдельно. [14488] |
| Задать расписание | Селект «Расписание работы» / «Добавить расписание» | Редактор с сеткой рабочих интервалов. [14039] |
| Резерв/выбор канала | Селект «Приоритет подключения», таблица политик | Роль основного/резервного и порядок подключений задаются в соответствующих формах. [13777, 14488, 17892] |
| Назначить политику | Drag-and-drop чипа или селект в настройках клиента | Привязка клиента/сегмента; доступны «Без доступа в интернет» и наследование политики сегмента. [17892, 14628] |
| Сегмент/VLAN LAN | «+», матрица портов и поле VLAN ID | Выбор членства разъёма, затем адресация/DHCP сегмента. [14628, 14629] |

## Состояния и обратная связь

- Подтверждённые состояния: «Подключено»/«ПОДКЛЮЧЕНО» — зелёный текст/бейдж; «Отключено» — серый рядом с выключенным WISP; «Проверьте кабель» — красный при включённом Ethernet без кабеля. Длительность подключения и пометка резервного соединения видны в мониторе. [13777, 14488, 16485, 42408]
- У WISP пустое обязательное поле SSID подсвечено красным с текстом «Заполните это поле»; конкретные тексты ошибок ручного IP, PPP-учётных данных и вид пустого списка провайдеров в изученных источниках не показаны. [14488; скриншот 14488-02]
- При ручной смене LAN IP на пересекающуюся с WISP подсеть возможен конфликт; после смены адреса локального сегмента доступ к старому адресу веб-интерфейса пропадает. [14488]
- Удаление Ethernet-подключения меняет роль порта 0: это не просто скрытие строки. В примере «Удалить подключение» показано внизу справа красным; сведения о диалоге подтверждения в источнике нет. [16485; скриншот 16485-05]

## Что переносим в vs-router

- В наш «Подключения и адреса» (`/network`): компактный список подключений с независимыми признаками «включено», «линк/доступность», «основное/резервное» и типом; по выбору — отдельная форма IP/MTU/MAC/VLAN/порта. Формы динамические по типу (PPPoE → учётные данные; PPTP/L2TP → сервер; mobile/WISP → специальные поля). Не выдавать MAC/MTU/VLAN за inline-редактирование строки. [13231, 13772—13774, 13777, 14488, 16485, 19727]
- Показывать привязку физического WAN-порта и WAN VLAN рядом с конкретным проводным подключением; LAN VLAN, DHCP и сегменты держать в настройках локальной сети, а не маскировать под провайдерский WAN VLAN. [16485, 14628, 14629]
- В `/network` разместить управление порядком/политиками подключений рядом с подключениями; привязка клиента/сегмента — отдельное действие. Вкладка маршрутов — для маршрутов, а не синоним таблицы PBR-политик: Keenetic разделяет «Приоритеты подключений» и «Маршрутизация». Не переносить ограничение Keenetic «16 политик» как требование нашего продукта. [17892, 15879, 37129]
- Не копировать аппаратно-зависимые SFP, встроенный модем, номера физических портов 0—4 и ограничения конкретного коммутатора, если их нет в нашей модели. TTL не добавлять как якобы обязательное поле WAN-формы: источники показывают разные возможности CLI и мобильного экрана. [16485, 19729, 13777, 38469]
