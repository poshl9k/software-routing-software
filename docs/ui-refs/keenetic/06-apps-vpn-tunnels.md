# Keenetic UI — Приложения, VPN-серверы, туннели и политики маршрутизации

«Приложения» — панель установленных служб с отдельными плитками, статусом и переключателем; VPN-клиенты и IP-туннели размещены в «Интернет → Другие подключения», а правила выбора выхода — в «Приоритеты подключений». Это разные поверхности: сервер WireGuard как приложение не равен ручной конфигурации WireGuard-интерфейса.

## Навигация

- «Приложения»: панель служб, включая WireGuard VPN-сервер, L2TP/IPsec, SSTP, IKEv1/IPsec, IKEv2/IPsec, «Личное облако» (FTP) и «Медиатека DLNA». Ссылка-заголовок плитки открывает настройки; переключатель остаётся на плитке. Плитка появляется после установки компонента через «Общие настройки системы → Обновление и компоненты → Изменить набор компонентов». Статьи `18483-applications.html` и `20531-applications.html` — оглавления разделов документации, НЕ снимки страницы приложения.
- «Интернет → Другие подключения»: разделы WireGuard, «VPN-подключения» (IKEv1/IKEv2, L2TP/IPsec, SSTP, OpenVPN) и «IP-туннели» (IPIP/GRE/EoIP). Создание здесь через «Добавить подключение»; WireGuard также предлагает «Загрузить из файла».
- «Приоритеты подключений»: вкладки «Политики доступа в интернет» и «Применение политик». Страница «Список клиентов» также позволяет изменить политику конкретного устройства.
- «Сетевые правила → Маршрутизация» и «Межсетевой экран»: дополнительные статические маршруты и разрешения для межсетевого VPN. «Доменное имя → KeenDNS → Доступ к веб-приложениям домашней сети» — отдельный путь к публикации локального web-сервиса; это не плитка VPN.

## Экраны и структура

1. **Список приложений.** Не сплошная таблица и не маркетплейс одинаковых квадратов: отдельные прямоугольные плитки служб с подчёркнутым кликабельным названием слева, переключателем справа и строками состояния/условий ниже. «Личное облако» показывает вложенный FTP-сервер, «Отключено» и пользователей с доступом; «Медиатека DLNA» — «Не настроено»; L2TP/IPsec — «Не настроено», «Доступ пользователям закрыт»; IKEv2/IPsec может вместо настроек показывать «Требуется прямой режим KeenDNS» и ссылку для исправления. У работающего WireGuard плитка показывает «РАБОТАЕТ», переключатель и «Статистика подключений». Отдельно экран установки компонента показывает строку «WireGuard VPN-сервер» с галочкой «Установлен» — это НЕ сама плитка приложений.
2. **WireGuard VPN-сервер (из плитки).** Открывается окно «WireGuard VPN-сервер»: вводный текст → выпадающий «Доступ к сети» (сегмент) → «IP-адрес сервера» в CIDR → флажок «NAT для клиентов» с пояснением → «Клиентские пиры» и «+ Добавить клиента». При отсутствии пиров блок «Нет клиентов». После добавления — табличная форма с колонками «Имя», «Доступ», «Разрешенные подсети», «IP-адрес», удалением ×; снизу «Сохранить»/«Отменить». После сохранения открывается отдельное окно «Настройки клиентского пира»: имя, QR-код, текст `.conf` с копированием и «Скачать конфигурацию». Затем включение переключателем на плитке; «Статистика подключений» открывает таблицу «Пир», «Последнее появление», «Адрес и порт пира», «Отправлено / Принято». Пароли/ключи из картинок не переносить.
3. **WireGuard как ручной tunnel/site-to-site.** В «Другие подключения → WireGuard» пустое состояние «Нет подключений» плюс «Добавить подключение»/«Загрузить из файла»; при наличии — таблица «Подключение», «Адрес», «Пир» с цветовым индикатором, «Отправлено», «Принято», «Адрес и порт пира», «Последнее рукопожатие». Форма задаёт адрес, порт прослушивания, генерирует пару ключей и добавляет пир с публичным ключом, Allowed IPs и endpoint; для двух подсетей нужны ещё маршрут через интерфейс туннеля и разрешение firewall. В сценарии приложения WireGuard site-to-site серверный peer получает «Разрешенные подсети» удалённой LAN, клиент импортирует `.conf`, меняет маску адреса, задаёт подсети пира и создаёт маршрут/правило firewall. Приложение упрощает удалённый доступ, ручной интерфейс — более гибкая схема site-to-site.
4. **Другие VPN-серверы и клиенты.** Серверы IKEv1/IKEv2, L2TP/IPsec, SSTP открываются из отдельных плиток «Приложений»: параметры общего ключа (IKEv1/L2TP), «Доступ к сети», «NAT для клиентов», адресный пул, раздел «Пользователи», иногда «Множественный вход» (IKEv2/L2TP/SSTP); сервис включают плиткой, активные сессии — по «Статистика подключений». Для IKEv2 нужен KeenDNS в прямом режиме; при выключенном «Множественный вход» возможен постоянный IP клиента. Клиенты IKEv1/IKEv2, L2TP/IPsec, SSTP: «Другие подключения → VPN-подключения → Добавить подключение», имя, тип, сервер, учётные данные, при необходимости ключ/сертификат, «Использовать для выхода в интернет», «Показать дополнительные настройки», затем включение соединения. OpenVPN в статье настраивается в том же клиентском разделе: имя, тип OpenVPN, поле «Конфигурация OpenVPN»; роль server/client определяется самим конфигом, НЕ отдельной плиткой «OpenVPN-сервер» в показанном сценарии.
5. **IPIP/GRE/EoIP и ZeroTier.** «Другие подключения → IP-туннели»: заголовок, краткое описание, пустой блок «Нет подключений. Добавить подключение»; форма IPIP/GRE задаёт локальный «IP-адрес» и «Удаленная сторона», при необходимости IPsec/общий ключ и дополнительные параметры. Туннели включаются на обоих концах; маршруты и firewall добавляются отдельно. IPIP/GRE — L3, EoIP — L2; сами по себе не дают шифрования. Документация ZeroTier создаёт интерфейс через CLI (`network-id`, `accept-addresses`, `accept-routes`, `up`), авторизует узел в ZeroTier Central; отдельного веб-редактора ZeroTier в этой статье НЕ показано.
6. **Приоритеты подключений.** Верх страницы: заголовок и пояснение, две вкладки. «Политики доступа в интернет»: слева строки «Политика по умолчанию», созданные политики и «+ Добавить политику», справа табличный блок колонок «Подключение» и «Управление полосой пропускания»: на строках соединений — маркер перетаскивания, checkbox участия, зелёный статус, имя/тип интерфейса и карандаш ограничения скорости; внизу checkbox «Добавлять новые подключения автоматически». Это **список соединений по приоритету внутри политики**, а не одна глобальная таблица с числовым полем приоритета. Порядок меняется перетаскиванием. «Применение политик»: слева политики с количеством объектов, справа плитки-плашки клиентов и сегментов с drag handle; доступен «Показать все объекты», перетаскивание в политику, а при выборе — «Переместить в»/«Подтвердить»/«Отменить». В карточке клиента есть выпадающая «Политика доступа». Пример GamePal: отметить только IKEv2-VPN и назначить PS4pro; остальные остаются на основном подключении. Ограничение из статьи: не более 16 политик.
7. **Удалённые ресурсы и медиа.** KeenDNS публикует web-приложение через «Добавить → Настройки доступа»: зарегистрированное «Устройство», латинское «Имя» поддомена, «Доступ из интернета», «Порт TCP». Удалённый USB: встроенный файловый менеджер через KeenDNS либо «Приложения → Личное облако» с разрешением WebDAV из интернета, правами пользователя/каталога и отдельным включением сервера. «Личное облако»/FTP: отдельные параметры порта, доступа из интернета, анонимного доступа и списка пользователей; «Медиатека DLNA»: имя, порт TCP, сегменты, папки, обновление медиатеки и отдельный переключатель. «DLNA через VPN» разрешается в учётной записи пользователя, а не на экране политик.

## UX/UI-логика (паттерны)

1. Установка компонента → появление плитки → настройка по ссылке → явное включение переключателем. «Установлен», «Не настроено», «Отключено», «РАБОТАЕТ» — разные состояния, не синонимы.
2. Настройка WireGuard peer остаётся внутри одного окна в табличной строке с checkbox и удалением; сохранение создаёт конфиг и открывает отдельное окно QR/экспорта. QR относится к клиентскому пиру, не к общей плитке сервера.
3. Пустые блоки в VPN-сервере и IP-туннелях содержат «Нет клиентов»/«Нет подключений» и соседнюю кнопку добавления. Назначение политики — drag-and-drop либо dropdown в клиентской карточке; состав соединений политики — checkbox + drag handle.
4. Политика маршрутизации для клиентов локальной сети и маршрут до подсети — разные операции. Для соединения через VPN включают «Использовать для выхода в интернет», добавляют его в политику, затем назначают клиенту/сегменту. Маршрут site-to-site задаёт сеть назначения и конкретный интерфейс туннеля с «Добавлять автоматически».
5. Статья «Изменение политики маршрутизации на стороне VPN-клиента» про системные настройки Windows («Использовать основной шлюз в удаленной сети»), macOS и Android, НЕ про страницу Keenetic «Приоритеты подключений».
6. Сетевой статус показан иконкой/цветом у подключения, а статистика WireGuard — отдельной таблицей с последним появлением, endpoint и объёмом трафика. Для IPIP/GRE/EoIP документация прямо предупреждает о stateless-природе: по одному факту настройки нельзя заключить, что трафик проходит.

## Элементы управления

| Назначение | Тип контрола | Поведение |
| --- | --- | --- |
| Включить сервер | Переключатель на плитке | После настройки переводится в «Включено»; у работающего WireGuard появляется «РАБОТАЕТ» и ссылка статистики. |
| Ограничить локальный доступ VPN | Выпадающий «Доступ к сети» | Выбор сегмента, доступного клиентам сервера. |
| Выдать клиентам интернет | Checkbox «NAT для клиентов» | По умолчанию включён; отвечает за source NAT клиентского трафика. |
| Создать WireGuard peer | «+ Добавить клиента» → строка → «Сохранить» | Имя, доступ, Allowed IPs; после сохранения окно QR и `.conf`. |
| Добавить клиентское подключение | «Добавить подключение» либо «Загрузить из файла» | Новый VPN-профиль или импорт WireGuard `.conf`; затем отдельное включение. |
| Назначить выход через VPN | Checkbox соединения в политике + drag-and-drop клиента/сегмента | Отмеченное соединение входит в политику; объект прикрепляется к этой политике, порядок определяет приоритет. |
| Указать маршрут в удалённую LAN | «+ Добавить» → «Маршрут до сети», «Адрес сети назначения», «Интерфейс» | Выбирается интерфейс VPN-туннеля; «Добавлять автоматически» привязывает маршрут к его доступности. |
| Публиковать локальный web-сервис | KeenDNS «Добавить» → форма | Выбор зарегистрированного устройства, поддомена, доступа и TCP-порта. |

## Состояния и обратная связь

- «Нет клиентов» в окне WireGuard; «Нет подключений» у WireGuard-клиента и IP-туннелей; «Не настроено» у неготового приложения. В плитке IKEv2 при отсутствии нужного режима KeenDNS — блокирующее объяснение и ссылка на настройку.
- Серверный WireGuard: «РАБОТАЕТ» и таблица статистики активных сессий; клиентский WireGuard: зелёная точка в колонке «Пир», последние handshake и трафик. Ошибки подключения конкретного peer на выбранных снимках не показаны — не выводим из них сообщения об ошибках или toast после сохранения.
- Удалённый VPN-сервер требует публичный IP и прямой режим KeenDNS; облачный режим KeenDNS для публикации web-приложений — отдельный сценарий, его нельзя выдавать за способ сделать WireGuard-доступным без публичного IP. Подсети site-to-site не должны пересекаться.

## Что переносим в vs-router

- `/tunnels`: различать серверные службы и клиентские/межсетевые туннели внутри одного понятного каталога; сохранять паттерн карточки с явным включением, статусом и отдельными настройками. Для WireGuard — peers, Allowed IPs, QR/экспорт `.conf`, handshake/трафик; для IPIP/GRE/EoIP — «Нет подключений» с действием и отдельное указание маршрута/firewall. Не обещать шифрование у IPIP/GRE/EoIP и не рисовать веб-редактор ZeroTier по статье, где его нет.
- `/routing`: две задачи не смешивать: приоритет и состав выходов в политике; назначение политики устройствам/сегментам. Дать выбор интерфейса выхода, статусы и явный порядок; отдельно — статический маршрут до удалённой сети через tunnel. Drag-and-drop Keenetic не обязателен: для доступности обеспечить также выбор из списка/кнопки перемещения.
- Не переносить требования KeenDNS, USB/DLNA и ограничения конкретного железа как обязательные сущности vs-router. Сохранять их лишь как референс для зависимостей, прав и блокирующих состояний. Не объявлять клиентскую настройку Windows отдельной вкладкой нашего `/routing`.
