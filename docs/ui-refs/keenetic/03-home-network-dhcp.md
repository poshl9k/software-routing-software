# Keenetic UI — Домашняя сеть: IP-адреса, DHCP, устройства и аренды

IP-сеть и DHCP настраиваются в параметрах сегмента «Домашняя сеть»; устройства просматриваются и регистрируются отдельно, в «Списках клиентов». Постоянный IP привязывается в карточке зарегистрированного клиента, а не в отдельной таблице аренд.

## Навигация

- «Мои сети и Wi-Fi» → вкладка «Домашняя сеть» → блок «Параметры IP» → «Показать настройки DHCP»; время аренды находится там же. Поддержка DHCP options, кроме показанных полей, документирована через CLI, не как экран веб-интерфейса.
- «Мои сети и Wi-Fi» → «Списки клиентов»/«Список клиентов» (в статьях встречаются оба названия): группы «Незарегистрированные клиенты», «Зарегистрированные клиенты», «Заблокированные клиенты». Нажатие строки открывает карточку. Пункт «Настройки для незарегистрированных клиентов» раскрывается прямо под первой группой.
- Для запрета интернета целому сегменту незарегистрированных клиентов: «Интернет» → «Приоритеты подключений» → «Применение политик» → «Политика по умолчанию», либо «Мои сети и Wi-Fi» → «Сегменты» → сегмент «Основной» → «Правила использования интернет-трафика». Не путать с настройками DHCP.

## Экраны и структура

1. «Домашняя сеть» → «Параметры IP»: заголовок и пояснение сегмента, checkbox «Включить IPv4», поля «IP-адрес» (пример 192.168.1.1), «Маска подсети» (dropdown), группа radio «DHCP-сервер»: «Включен»/«Выключен»/«Relay» с подсказкой. Далее раскрывающая ссылка «Показать настройки DHCP». Ниже — «Использовать NAT», «Ретранслировать mDNS». После раскрытия DHCP-параметров: «Начальный адрес пула», «Размер пула адресов», «Время аренды, сек», «Адрес шлюза», «Сервер DNS 1», «Сервер DNS 2»; ссылка меняется на «Скрыть настройки DHCP». Эти изображения — фрагменты страницы, кнопку сохранения на них не видно. Источники: 15224, 22349.
2. «Списки клиентов»: заголовок с пояснением поиска клиентов по имени, IP/MAC, статусу подключения и приоритизации трафика. Далее незарегистрированные: таблица «Клиент»/«Адрес»/«Сегмент»/«Подключение»/«Политика» (в другом снимке последняя колонка — «Приоритет трафика»); ссылка раскрытия настроек под таблицей. Затем зарегистрированные: «Добавить клиента», счётчик «В СЕТИ: 4/7», переключатель «Клиенты не в сети», таблица с колонками «Клиент», «Адрес», «Сегмент», «Подключение», «Трафик», «Политика» (вариант снимка — «Приоритет трафика»). Ниже «Заблокированные клиенты», на примере — сообщение «Нет заблокированных клиентов». Строки содержат цветную точку online/offline, имя, IP над MAC, сегмент и способ подключения (Wi-Fi/порт), скорость, для Wi-Fi также шкалу сигнала и технологию; у online-клиента видны объёмы ↓/↑. Это таблицы клиентов, не отдельная таблица DHCP-аренд: срок истечения аренды в их строках не показан. Источники: 14007, 33344.
3. Карточка незарегистрированного клиента открывается нажатием строки: заголовок с именем и крестиком, пояснение регистрации, редактируемое «Имя клиента», «Политика доступа», «Разбудить по сети»; далее read-only сведения «Имя устройства», «Подключение», «MAC-адрес», «IP-адрес», «В сети», «Сессия Wi-Fi», отправлено/получено. Ниже настройки контроля Wi-Fi/разрешённых диапазонов и кнопки «Зарегистрировать», «Отменить». Источник: 14008.
4. Карточка зарегистрированного клиента: «Основные настройки» (имя, WoL, политика доступа, расписание, интернет-фильтр, приоритет трафика, ограничение скорости и при необходимости расписание ограничения, checkbox «Постоянный IP-адрес» → поле «IP-адрес»); ниже сворачиваемые блоки контроля доступа к Wi-Fi, разрешённых диапазонов и узлов Mesh, UPnP, переадресации портов, «Дополнительные сведения», действие «Удалить регистрацию». В Wi-Fi-карточке отдельным предупреждением выводится «Этот клиент использует частный MAC-адрес». Источники: 14008, 33344.
5. «Настройки для незарегистрированных клиентов» внутри списка: текст о действии настроек на всех незарегистрированных, селекторы профилей контентной фильтрации по сегментам (на одном снимке), поле «Ограничение скорости» с выбором единиц, checkbox «Ассиметрично», checkbox «Автоматически регистрировать новых клиентов в основном сегменте сети». Источники: 38331, 14010.

## UX/UI-логика (паттерны)

1. DHCP-параметры скрыты за раскрытием; IP роутера и выбор режима DHCP остаются видимыми до раскрытия. Старт пула должен находиться в подсети адреса роутера. Изменение адреса роутера после сохранения разрывает текущий доступ к конфигуратору: клиенту требуется обновить IP и открыть новый адрес. Источник: 15224.
2. Время аренды — числовое поле в секундах; в статье указано значение по умолчанию 25200 сек для домашней и гостевой сети и максимум 259200 сек через CLI. Это динамическая аренда; её не следует смешивать с «Постоянный IP-адрес» для конкретного клиента. Источник: 22349.
3. Постоянная привязка IP выполняется через регистрацию (идентификация по MAC), затем checkbox «Постоянный IP-адрес» и ввод IP в карточке зарегистрированного клиента; на снимке таблицы такой IP помечен маленькой синей звёздочкой. Для незарегистрированного клиента сначала «Зарегистрировать». Статья описывает назначение адреса, но не отдельный реестр static leases. Источник: 14008.
4. Открытие карточки — клик по строке, не inline-редактирование ячеек. Регистрация — кнопка «Зарегистрировать» в карточке; в примере изменения политики для существующего клиента инструкция явно требует кнопку «Сохранить». Для DHCP на просмотренных фрагментах расположение и текст кнопки сохранения не установлены. Источники: 14008, 14193, 15224.
5. Список явно группирует клиентов по регистрации и блокировке; переключатель «Клиенты не в сети» относится к показу offline зарегистрированных клиентов. Пиктограмма рядом с «Клиент» напоминает управление списком/сортировкой, но ни порядок сортировки, ни механизм поиска статьями и снимками не раскрыты. В тексте экрана заявлен быстрый поиск по имени, IP, MAC, статусу и приоритету; отдельное поле поиска или набор фильтр-кнопок на просмотренном скриншоте отсутствуют — не воспроизводить их как подтверждённые детали Keenetic. Источник: 14007.
6. Начиная с KeeneticOS 4.2.1 новые клиенты основного сегмента автоматически регистрируются по умолчанию; для отключения раскрывают настройки незарегистрированных и снимают checkbox. На снимке списка отмечено исключение для частных/случайных MAC-адресов. Источники: 14007, 38331.
7. Смена MAC у клиента может создать новую запись и лишить прежнюю регистрацию/правила эффекта. Карточка предупреждает о частном MAC; статья рекомендует отключать рандомизацию на клиенте для данной домашней Wi-Fi-сети. Стратегии контроля: ограничить скорость незарегистрированным либо запретить им интернет; это разные действия. Источники: 14009, 14191, 33344.
8. В карточке клиента доступны WoL и подробности подключения; WoL допускается для зарегистрированного и незарегистрированного устройства, требует поддержки клиентом и администраторских прав на роутере. Примерные функции списка: лимит скорости индивидуально/для всех незарегистрированных, расписание зарегистрированного клиента, «Без доступа в интернет» через политику клиента — не отдельные колонки DHCP-аренд. Источники: 14192, 14010, 14052, 14193.
9. Дополнительные DHCP options (в частности option 121) задаются через CLI для пула/класса клиента; option 15 (DNS Domain Name) — командой `ip dhcp pool _WEBADMIN domain local`, затем `system configuration save`. Не рисовать для них веб-форму: документация прямо говорит о CLI. Источники: 47174, 47175.

## Элементы управления

| Назначение | Тип контрола | Поведение |
|---|---|---|
| IPv4 в сегменте | checkbox «Включить IPv4» | Включение IPv4; показан в блоке параметров IP. |
| Адрес роутера/маска | input IP + dropdown маски | Изменение сети сегмента; после сохранения нового IP доступ по старому адресу теряется. |
| Режим DHCP | radio «Включен»/«Выключен»/«Relay» | Выбор режима DHCP-сервера. |
| Диапазон/аренда/DNS | ссылка раскрытия + input-поля | Показ/скрытие начального адреса, размера пула, времени аренды в секундах, шлюза, DNS 1/2. |
| Просмотр клиентов | группированные таблицы, счётчик online, переключатель offline | Показывают IP/MAC, сегмент, тип подключения, статус и в отдельных снимках трафик/политику. |
| Регистрация | клик строки → карточка → «Зарегистрировать» | Перенос клиента в группу зарегистрированных; вручную — при отключённой авторегистрации. |
| Static lease | checkbox «Постоянный IP-адрес» + input «IP-адрес» в карточке | Закрепление введённого IP за зарегистрированным клиентом. |
| Правила незарегистрированных | раскрытие + checkbox автоприсвоения регистрации, лимит скорости | Настройки для всех незарегистрированных, не для одной строки. |
| Блокировка одного клиента | select «Политика доступа» → «Без доступа в интернет» + «Сохранить» | Политика клиента; альтернативно перенос в политику запрета на странице приоритетов. |
| WoL | кнопка «Разбудить по сети» в карточке | Отправка magic packet; результат включения зависит от устройства. |

## Состояния и обратная связь

- Empty state подтверждён текстом «Нет незарегистрированных клиентов» и «Нет заблокированных клиентов» внутри обрамлённой области под заголовком соответствующей группы. Пустое состояние зарегистрированной группы отдельно не найдено на просмотренных изображениях.
- Online — зелёная точка; offline — серая точка и «Не в сети» вместо сегмента, прочерки у подключения и трафика в примере. Счётчик «В СЕТИ: 4/7» показывает текущую долю online на снимке. При WoL успешное появление устройства в списке отмечается статусом «В сети»; сама отправка пакета не гарантирует пробуждение.
- Частный MAC показан как пометка «(частный)» в списке и отдельное предупреждение в карточке. После смены LAN IP нужен новый адрес страницы и переподключение клиента; ошибки валидации полей и toast-подтверждения не показаны в изученных материалах.

## Что переносим в vs-router

- `/dhcp`: компактные настройки сегмента (адрес/маска, режим DHCP), раскрываемые пул/время аренды/шлюз/DNS; постоянные назначения связать с клиентом по MAC, чётко отделить от динамических аренд. Если показывать таблицу аренд или время их истечения, это проектное решение vs-router: отдельная такая таблица и expiry в изученном Keenetic UI не подтверждены.
- «Подключения и адреса»: группировка устройств по online/offline и регистрации, диагностическая строка IP/MAC/сегмент/подключение, карточка устройства по клику, явное пустое состояние; возможность быстро находить клиентов по имени/IP/MAC — заявленная цель Keenetic, но конкретный поисковый контрол нельзя копировать без подтверждения.
- Не переносим как обязательное поведение DHCP: Wi-Fi/mesh-подробности, интернет-фильтр, приоритет трафика, WoL, расписания, политики интернет-доступа и CLI-only DHCP options. Автоматическую регистрацию Keenetic и исключение для случайных MAC не принимать за универсальную семантику DHCP-сервера vs-router.
