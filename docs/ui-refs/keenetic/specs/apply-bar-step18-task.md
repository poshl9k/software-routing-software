## Что хочет пользователь

1. Кнопка применения сейчас висит **внизу меню** (`configurationRail` → `ApplyStatusRail`
   рендерит fallback-кнопку «Проверить изменения») и **ведёт на страницу применения**. Это
   не нравится.
2. Нужно: кнопка висит **в верхней части, под верхней панелью, справа**.
3. По нажатию **конфиг применяется**, а не открывается страница применения.

## Что сделать

### 1. Полоса действий под шапкой (глобальная, справа)

- Добавь в `<main>` сразу после `<header className="topbar">…</header>` полосу
  `<Box className="page-actions">` (можно `component="div"`), выровненную по правому краю,
  `position: sticky` под шапкой (класс добавь в `styles.css`, цвета/границы — из
  `theme.ts`/токенов, без хардкод-hex).
- Внутри — РОВНО два элемента: primary-кнопка фазы применения (`ApplyTopButton`, см. п. 2) и
  secondary-ссылка `Проверить изменения` (`<Button component={Link} to="/apply" variant="outlined">`)
  — она сохраняет разбор diff как отдельный осознанный шаг.
- Убери `<ApplyTopButton checking={checking} />` из строки шапки (строка ~226), чтобы кнопка
  не дублировалась (§4). Прочие элементы шапки (`Поиск раздела`, статус версии, `Обновить`,
  пользователь, mobile-кнопка `Конфигурация`) не трогай.
- Когда `noConfiguration` или роль не `admin` — полоса не рендерится вообще.

### 2. Кнопка применяет напрямую

Фазы (сохрани существующую логику `pending`/`active`/`uncertain` и подписи):

- `pending` → `Подтвердить · mm:ss` (как сейчас, `command("confirm")`).
- `active || uncertain` → `Выполняется…`, но теперь это НЕ ссылка на /apply: кнопка
  `disabled` с тем же текстом и Tooltip («Результат последней команды неизвестен; проверьте
  состояние на странице «Применение»» сохранить). Ссылку на разбор даёт secondary-кнопка.
- **есть неприменённый черновик** (новый случай, сейчас функция возвращает `null`) →
  primary-кнопка `Применить v<draft.id>` (вариант `contained`), по клику:
  1. открывается `ConfirmDialog` с честным текстом: `Применить черновик v<id>?` плюс абзац-риск:
     при `safe_mode` — «Через <timeout> с потребуется подтверждение, иначе автоматический откат
     к стабильной версии»; если подтверждённой версии нет вообще — «Стабильной версии нет: это
     первое применение, откатывать будет некуда»;
  2. по подтверждению — `void command("apply", draft.id)`; при ошибке текст ошибки показывается
     существующим механизмом (`ErrorNotice`/`setNotice`), новая обработка ошибок не изобретается.
- Логику `command` в `state.tsx` НЕ менять: `safe_mode` уже вычисляется там
  (`safe_mode: confirmed ? preferences.safe : false`).

### 3. Убрать кнопку из нижней части меню

- В `configurationRail` (App.tsx:180–187) передавай в `ApplyStatusRail` явное «без действия»,
  чтобы fallback-кнопка не рендерилась: статус «Черновик vN не применён / стабильная vM» остаётся,
  кнопки внизу меню больше нет. Мобильный ящик ведёт себя так же.
- Если для этого нужно расширить `ApplyStatusRailProps.action` (`ReactNode` уже есть) — просто
  передавай `null`, но тогда поправь `ApplyStatusRail.tsx`: `action === undefined` остаётся
  fallback-кнопкой, `action === null` — ничего не рендерится. Это один минимальный пропс, ничего
  больше в этом компоненте не меняй.
