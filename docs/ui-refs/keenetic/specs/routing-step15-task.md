## Что сделать

Каждый редактор — модальное окно (`Dialog` `fullWidth maxWidth="md"` → `DialogTitle` с именем
объекта → `DialogContent` с `FormGrid` и секциями `PageSection` → `EditorFooter` в конце):

1. **«Новый набор» / набор** — `Идентификация` (имя), `Содержимое` (домены/IP-набор,
   существующий textarea/`Field` и его валидатор без изменений).
2. **DNS-сервер (строка таблицы)** — `Идентификация` (адрес), `Транспорт` (`DoT`/`DoH`/`UDP`,
   порт/путь).
3. **DNS-правило (строка таблицы)** — `Условие` (домен/набор), `Решение` (upstream/блокировка).
4. **Визард правила** — остаётся пошаговым, но живёт В ОКНЕ: шаги (`ruleStep`) внутри
   `DialogContent`, футер с `Назад`/`Далее`/`Сохранить` и существующей логикой
   `ruleStep`/`allValid`/сохранением — как есть по смыслу. Никаких изменений в порядке шагов
   и в текстах шагов.

Вкладки/сегменты страницы, которые переключают РЕЖИМ просмотра (`Конфигурация` / `Эксперт`),
оставить — это законные разные режимы, а не поля одного объекта. Верхние (`configure`/`expert`)
и таблицы (`DataTable`, пустые состояния шага 7) не трогать.

Никаких функциональных изменений: валидаторы, `save`, порядок строк, пустые состояния
(«Пользовательских правил нет — выбранный трафик идёт к конечному действию.» и прочие),
`Radio`/`RadioGroup` исключение оставить как есть.
