## Что именно сделать (три пункта)

### 1. Осмысленные пустые состояния у обеих таблиц

Сейчас `DataTable` «Локальные имена» и «Домены с отдельным DNS» без `empty` печатают
безликое «Нет записей». Передай конкретный текст:
- локальные имена → `Локальных имён нет.`
- домены с отдельным DNS → `Доменов с отдельным DNS нет.`

Стиль формулировок согласуй между собой (как в остальных пустых состояниях панели).

### 2. Тип DNS-сервера должен быть виден

В карточке «Режим и доступ» в списке `DNS-серверы` сейчас печатается
`u.address || u.doh_server`, то есть у зашифрованного сервера видно только имя/URL, а тип
теряется: по строке `https://dns.google/dns-query` или `1.1.1.1` нельзя понять, шифруется
запрос или уходит открытым UDP. У `DNSUpstream` есть поле `mode: "udp" | "tls" | "https"`.

Покажи тип явно в одной строке на сервер:
- `udp` → `DNS (UDP) · <address>:<port>`
- `tls` → `DoT · <tls_name> (<address>:<port>)`  (если `tls_name` пуст, только адрес)
- `https` → `DoH · <doh_server>`

Тот же формат применяй и в строке `Домены с отдельным DNS` (там upstreams того же типа)
и для `DNS-серверы` в kv-списке — сделай ОДНУ локальную функцию-форматтер, а не три копии.
Форматтер держи в `DNSReadOnly` (он специфичен для DNS); в `format.ts` выноси только если
он получается действительно общим — тогда напиши об этом в отчёте.

### 3. Сообщение про журнал запросов — в своё место

Сейчас в карточке «Режим и доступ» внизу висит `InfoNote`
«Просмотр DNS-запросов здесь пока недоступен.» — это про другую сущность (журнал запросов),
внутри карточки про режим и доступ. Keenetic держит журнал отдельно.

Убери этот `InfoNote` из «Режим и доступ» и сделай отдельную карточку
`Card title="Журнал запросов DNS"` с одним честным `EmptyState`:
текст — `Просмотр DNS-запросов пока не подключён к API.`
Никаких вторых сообщений рядом с ним.
