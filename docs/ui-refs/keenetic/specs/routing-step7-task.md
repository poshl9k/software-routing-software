## Что именно сделать (только пустые состояния; структуру не менять)

Сейчас шесть read-only таблиц без `empty` печатают безликое «Нет записей». Keenetic в каждом
списке называет, чего именно нет.

1. **`expert` → «Правила · первое совпадение»** (в строке ~428, шапка `["#", "Действие",
   "Условия", "Выход", "Действия"]`). Пустой список здесь НЕ означает «не настроено»:
   встроенные стадии (sniff/DNS/локальные адреса/UDP) действуют всегда, а трафик без
   совпавшего правила уходит к конечному действию. Поэтому пустое состояние должно объяснять
   это, а не просто констатировать пустоту, например:
   `Пользовательских правил нет — выбранный трафик идёт к конечному действию.`
2. **`expert` → «Наборы правил»** (~464) → `Наборы правил не объявлены.`
3. **`expert` → «Выходы»** (~477) → `Прокси-выходов нет.`
   (карточка «Прокси-выходы не настроены» выше остаётся как есть; текст не противоречит ей)
4. **`expert` → «DNS-серверы и правила»**, таблица серверов (~485) → `DNS-серверов нет.`
5. Та же карточка, таблица DNS-правил (~489) → `DNS-правил нет.`
6. **Список исключений (bypass) в режиме редактирования** (~684, `current.bypass.map`):
   при `current.bypass.length === 0` покажи перед кнопкой добавления `EmptyState`
   с текстом `Исключений нет.` — ровно один раз, кнопку добавления не дублировать.
   Формулировка должна совпадать с read-only сводкой, где уже написано «Исключений нет».

**НЕ добавляй** пустое состояние таблице правил в представлении `configure` (~586): там
всегда есть четыре системные строки S1–S4, и пустое состояние будет мёртвым кодом.
