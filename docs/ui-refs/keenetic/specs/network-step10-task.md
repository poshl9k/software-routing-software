## Проблема, которую надо устранить

Сейчас выбор интерфейса раскрывает **резидентную карточку-форму прямо на странице**: список
уезжает вверх, поля выстраиваются линейной полосой из пяти инпутов
(«Дружественное имя» / «Системное имя» / «Описание» / «Тип» / «Роль / зона» / «MAC хоста»),
плюс полоса вкладок одного объекта. Keenetic так не делает: правка объекта — **отдельное
окно**, страница остаётся списком.

## Что сделать

### 1. Редактор интерфейса — модальное окно

- Убери резидентную `Card` редактирования и `ValueTabs` внутри неё (`detailTab` больше не нужен;
  убери и `setDetailTab` из `addRow`/`addVirtual`/`addQuick`).
- Клик по строке (существующая кнопка в первой колонке, плюс те же вызовы из `addRow`,
  `addVirtual`, `addQuick`) открывает **модальный `Dialog`**:
  - `Dialog` (`fullWidth`, `maxWidth="md"`, `open={…}` по выбранному ключу),
  - `DialogTitle` — имя объекта: `Интерфейс: <дружественное имя || системное имя>`, справа —
    существующий `DeleteButton` (`Удалить интерфейс …`, тот же `setDeleteKey`),
  - `DialogContent` — форма, сгруппированная секциями (см. п. 2),
  - в конце формы — существующий `EditorFooter` (`saving`/`valid`/`cancel`/`save`) — так
    выполняется правило «редактор заканчивается EditorFooter».
- Закрытие окна (`Отмена`, Esc, клик по фону) = `cancel`, как сейчас.
- Страница при закрытом окне содержит **только список** — никакой формы в потоке страницы.

### 2. Одна форма с секциями внутри окна (не полоса инпутов)

Внутри `DialogContent` — `FormGrid`, разбитый на секции заголовками (`PageSection`),
в этом порядке:

1. **Идентификация** — сначала то, что дано железом и не редактируется (`Field readOnly`):
   `Системное имя`, `MAC`, `Состояние кабеля/хоста` (честный текст как в списке:
   «Кабель: подключён/отключён», «Состояние хоста недоступно»/«загрузка»). Затем единственное
   редактируемое имя — `Дружественное имя` (`Field`, `maxLength={64}`, тот же `onChange`).
2. **Роль** — `Роль / зона` (тот же `Select`, тот же текст «Не назначен — транзит запрещён»)
   и существующий `InfoNote` про запрет транзита без зоны и применение через черновик.
3. **Адресация** — `Режим адресации` (Статический IP / DHCP / PPPoE — те же значения и та же
   логика очистки полей), затем поля режима: статический адрес + дополнительные адреса,
   либо полученный по DHCP (`InfoNote`), либо логин/пароль PPPoE (`SecretField`).
4. **Тип и подключение** — `Тип` (Физический / Мост / VLAN), `Родительский интерфейс` и
   `VLAN ID` (для VLAN), участники моста (для Моста) — существующие контролы и валидация.
5. **Дополнительно** — `ExpertDisclosure` «Показать дополнительные настройки»: справочные
   read-only значения (`Родитель`, `Участники`, `VLAN ID`, `Состояние хоста`) и существующий
   `InfoNote` про первичный LAN.

### 3. Убрать дублирование значения

Read-only `Описание`, повторяющее `Дружественное имя`, удалить — значение показывается один раз (§9).

### 4. Действия создания — в одном месте

В шапке карточки «Интерфейсы и зоны» сейчас по кнопке на каждый NIC (`+ VLAN на enp1s0`, …).
Заменяй на: `Быстро подключить` (оставить), `Добавить интерфейс` (оставить) и ОДНУ кнопку
`+ Виртуальный интерфейс`, открывающую небольшой `Dialog` выбора типа (`VLAN` / `Мост`) и,
для VLAN, родительского порта из `physicalNics`; по подтверждению — тот же вызов
`addVirtual("vlan", name)` / `addVirtual("bridge")`, что и раньше.

## Чего НЕ делать

- Никаких функциональных изменений: `allValid`, `save`-маппер (очистка адресов при DHCP,
  сброс PPPoE), `addQuick`, `usedByOtherRows`, `candidates`, `nameOptions`, `QuickConnectDialog`,
  `ConfirmDialog`, `StaticRoutes`, вкладки «WAN-адреса» и «Диагностика» — по смыслу как есть.
- Не менять `schema.py`, типы, API, backend, маршруты страницы.
- Верхние `ValueTabs` страницы (Интерфейсы / WAN-адреса / Маршруты / Диагностика) оставить:
  это разные списки, а не поля одного объекта.
- Не добавлять зависимости и примитивы. Разрешённые импорты MUI в страницах: `Alert`, `Button`,
  `Checkbox`, `Dialog*`, `FormControlLabel`, `Switch`, `Typography`.
- Подписи полей не переименовывать (`Дружественное имя`, `Роль / зона`, `Режим адресации`,
  `Основной адрес (CIDR)`, `VLAN ID`, `Тип`) — на них тесты.
- Никаких хардкод-hex, inline-стилей цвета, эмодзи. Не коммить.
