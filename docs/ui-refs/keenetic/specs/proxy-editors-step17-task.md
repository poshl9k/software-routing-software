## Что сделать

Каждый редактор элемента списка — модальное окно (`Dialog` `fullWidth maxWidth="md"` →
`DialogTitle` с именем объекта → `DialogContent` с `FormGrid` и секциями `PageSection` →
существующий `EditorFooter` в конце; удаление — в заголовке окна, если оно сейчас внутри
редактора, и **ровно в одном месте**: если у строки списка уже есть своя кнопка удаления,
в окне её быть не должно, и наоборот):

- **Прокси-выход** — `Идентификация` (тег/имя), `Подключение` (тип, сервер, порт/пароль или
  ссылка), `Правила` (существующие поля выхода). Текущий `id="outbound-editor-<index>"` можно
  сохранить как `id` окна, чтобы не ломать якорную навигацию.
- **Подписка** — `Идентификация` (имя), `Обновление` (URL, интервал), `Параметры`
  (существующие поля; второстепенные — под `ExpertDisclosure`).
- **Группа выходов** — `Идентификация` (имя), `Состав` (список выходов/порядок).

Списки и вкладки страницы (`outbounds` / `subscriptions` / `rule-set`) остаются как есть — это
законные разные списки. При закрытом окне страница содержит только списки: никаких форм и
никаких «висящих» значков удаления в потоке.

Никаких функциональных изменений: `patch`/`updateOutbound`/`updateSubscription`/`updateGroup`,
валидаторы, `save`-маппер, `summary`, порядок, импорт ссылок, честные состояния — по смыслу
как есть.

## Чего НЕ делать

- Не менять вкладки страницы, таблицы `DataTable`, кнопки создания и импорт ссылок.
- Не менять `schema.py`, типы, API, backend, генераторы.
- Не добавлять зависимости и примитивы. В страницах допустимы только `Alert`, `Button`,
  `Checkbox`, `Dialog*`, `FormControlLabel`, `Switch`, `Typography`.
- Не переименовывать подписи полей и кнопок (тесты).
- Никаких хардкод-hex, inline-стилей цвета, эмодзи. Не коммить.
