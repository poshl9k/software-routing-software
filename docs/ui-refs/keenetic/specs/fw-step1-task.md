## Что именно сделать

Только вкладки зон (где `zone === true`, карточка `Правила зоны ${tab}`).
Вкладки «Port Forward», «Outbound NAT», «Псевдонимы» НЕ трогать.

### 1. Одна склеенная колонка → явные колонки

Сейчас таблица правил — `["Правило по порядку", "Состояние", "Действия"]`, всё правило
склеено в одну строку текста. Нужны отдельные колонки, как в Keenetic:

| Колонка | Значение |
| --- | --- |
| `№` | позиция правила в порядке проверки: 1, 2, 3… (для неявного правила — «—») |
| `Имя` | `r.name \|\| "Без имени"` |
| `Действие` | `ruleActionLabel(r.action)` |
| `Протокол` | `r.protocol.toUpperCase()` |
| `Откуда` | `endpointLabel(r.src)` |
| `Куда` | `endpointLabel(r.dst)` |
| `Порт` | `r.destination_ports ?? "—"` |
| `Состояние` | словами: `Включено`, `Включено · журнал`, `Выключено` |
| `Действия` | в режиме редактирования — `Изменить` + `DeleteButton`; иначе пусто |

Сортировка строк — как сейчас, по `order` внутри выбранной зоны.
`DataTable` уже подставляет «—» вместо `null` — пользуйся этим, не дублируй вручную.

### 2. Порядок и неявное правило

- Колонка `№` = место правила в списке (порядок проверки). Единственный способ
  переставить правило — существующий селект «Позиция» в форме-композере.
  Drag-and-drop НЕ добавлять: новых зависимостей нет.
- Сохранить внизу таблицы строку про неявное правило: в колонке `Действие` —
  `Запретить (по умолчанию)`, остальные ячейки — «—». Это честная маркировка
  нашего default deny, а не выдуманное правило.

### 3. Удаление прямо из строки

В режиме редактирования у каждого правила в колонке `Действия` рядом с `Изменить`
появляется `DeleteButton` с label `Удалить правило ${r.name || "#" + (position + 1)}`.
Удаляет тем же способом, что и кнопка в композере: через `setZoneRules` без
удаляемого правила (с перенумерацией `order` через `map((r, order) => …)`),
и если удаляется правило, открытое в композере — `setComposerIndex(null)`.

Периодический `Toggle` в таблицу НЕ добавлять: компонент `Toggle` требует видимую
подпись, а в ячейке таблицы подпись дублировала бы заголовок колонки. Это нарушило бы
`docs/ui-rules.md` («label XOR ariaLabel»). Включение/выключение остаётся в форме.

### 4. Пустое состояние

Если в выбранной зоне нет пользовательских правил (`rules.length === 0`):
- вместо таблицы — `EmptyState`:
  - `title` = `Нет правил.`
  - текст = `Действует только неявное правило: запретить всё остальное.`
- Своей кнопки добавления у пустого состояния НЕТ.

КРИТИЧНО: в любой момент на странице должна быть ровно ОДНА кнопка с доступным
именем «Добавить правило», иначе существующий тест
`screen.getByRole("button", { name: "Добавить правило" })` упадёт.
Таблица и пустое состояние взаимоисключающие, кнопка живёт вне них.

### 5. Чего не делать

- Никаких drag-and-drop, новых зависимостей, новых компонентов-примитивов.
- Не трогать `PageHeader`, `ValueTabs`, композер (кроме возможного устранения
  кнопки-дубликата «Добавить правило»), логику `save`, валидаторы, типы, API.
- Не переименовывать `label` в композере («Имя», «Откуда», «Куда», «Протокол»,
  «Порт / @алиас», «Действие», «Позиция») — на них завязаны тесты.
- Не добавлять в таблицу правил `Field`/`Select` с aria-label «Имя», «Протокол»,
  «Действие» — эти имена должны остаться уникальными для композера.
- Никаких хардкод-hex, inline-стилей цвета, эмодзи-иконок. Цвета только из `theme.ts`.
- Удаление — только через `DeleteButton`, не красной текстовой кнопкой.
- Не коммить.

## Тесты

Все существующие тесты остаются зелёными. Добавь в `frontend/src/test/editors.test.tsx`
два теста в стиле соседних (используй `emptyConfiguration` и `mockApi` из того же файла):

   пусто).
