## Что именно сделать (4 пункта, не больше)

### 1. Карточка «Службы · текущее состояние» — из текстовой каши в строки

Сейчас это `<div className="stats">` с `DHCP: <InlineStatus/>   DNS: …` — подпись, двоеточие и
статус в одну строку, вне общего табличного ритма панели. Keenetic показывает службу строкой:
имя и отдельно состояние.

Сделай `DataTable` с шапкой `["Служба", "Состояние"]` и строками для тех же служб
(`DHCP`→`kea`, `DNS`→`unbound`, `Caddy`→`caddy`, `DDNS`→`ddns`), во второй ячейке —
существующий `RuntimeServiceInline`. Никаких `label + ":"` в ячейках.

### 2. Осмысленные пустые состояния у каждой таблицы

`DataTable` без `empty` печатает безликое «Нет записей». Keenetic пишет конкретно
(«Нет правил.», «Нет клиентов»). Передай `empty={<EmptyState>…</EmptyState>}` каждой таблице
обзора с текстом по смыслу списка, например:
- WAN/Интернет: `Интерфейсы WAN не настроены.`
- DHCP-подсети: `Подсети DHCP не настроены.`
- Интерфейсы и VLAN: `Интерфейсы не назначены.`
- Туннели: `Туннелей нет.`
- Прокси: `Сайтов нет.`

Формулировки согласуй по стилю между собой (одна конструкция, не смесь «нет» и «не настроены»).

### 3. «Журнал событий» не должен говорить одно и то же дважды

Сейчас в карточке одновременно `InfoNote` «Просмотр событий пока не подключён к API.» и
`EmptyState` «Журнал пока недоступен» + «События появятся после подключения журнала к панели.»
Это дублирование одного сообщения (одно действие/одно сообщение — одно место). Оставь ОДНО
честное пустое состояние, без `InfoNote`-дубля. Поведение для `standalone` (страница
`/events` с `PageHeader «Журнал событий»`) сохрани: заголовок остаётся только в standalone.

### 4. Главная карточка соединения ведёт в свой раздел

`StatusHero` («Интернет · состояние соединения») сейчас тупиковый. Keenetic: главная сводка
ссылается на детальный экран. Передай в `StatusHero` проп `action` — ссылку на `/network`
(`Button component={Link} variant="outlined"` с текстом `Подключения и адреса`).
Сам честный статус («Телеметрия не подключена», `tone="unknown"`) НЕ трогай: данных у нас нет,
и это правильное состояние. `facts` не выдумывай.
