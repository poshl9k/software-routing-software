# Keenetic UI — DNS: серверы, шифрование, маршруты и KeenDNS

DNS-серверы и профили находятся во вкладке «Настройка DNS» страницы «Интернет-фильтры»; доменная маршрутизация — отдельная вкладка страницы маршрутизации, KeenDNS — страница «Доменное имя». В документации для региона ЕАЭС с марта 2025 года сервис KeenDNS на новых устройствах называется CrazeDNS: скриншоты основной страницы показывают Netcraze/CrazeDNS, а пример удалённого доступа и текст некоторых статей сохраняют KeenDNS и домены `keenetic.pro`. Это разные по времени примеры, не единый экран.

## Навигация

- «Сетевые правила» → «Интернет-фильтры» → вкладки «Контентный фильтр» и «Настройка DNS». Во второй — «Профили DNS» и серверы внутри выбранного профиля; в первой — режим фильтрации, назначение профилей сегментам и зарегистрированным клиентам.
- «Интернет» → «Подключения к интернету по Ethernet-кабелю» → «Параметры IPv4»: DNS конкретного подключения и «Игнорировать DNSv4 интернет-провайдера»; аналогичная опция на страницах Wireless ISP и DSL. «Системный монитор» → «Интернет» → строка «DNS-серверы» показывает полученные от провайдера и вручную заданные адреса, но не DoT/DoH.
- «Мои сети и Wi-Fi» → «Домашняя сеть» → «Параметры IP»: «Сервер DNS 1/2» для выдачи клиентам через DHCP. Не путать с настройкой upstream-резолверов роутера.
- «Сетевые правила» → «Маршрутизация» / страница «Статические маршруты» → вкладки «IPv4-маршруты», «IPv6-маршруты», «Маршруты DNS». Последняя появилась с KeeneticOS 5.0.
- «Сетевые правила» → «Доменное имя» → вкладка KeenDNS (на актуальном снимке — «CrazeDNS»); ниже блок «Доступ к веб-приложениям домашней сети».
- Зависимые компоненты ставятся через «Общие настройки системы» → «Обновления и компоненты KeeneticOS» → «Изменить набор компонентов»: DNS-over-TLS/HTTPS proxy для шифрования, «Фильтрация контента и блокировка рекламы при помощи облачных сервисов» для фильтрации, «Агент облачных служб» для KeenDNS.

## Экраны и структура

### DNS-серверы, профили, фильтрация

1. «Интернет-фильтры»: заголовок с подсказкой, пояснение, две вкладки. «Настройка DNS» → заголовок «Профили DNS» и пояснение об автоматическом добавлении DNS провайдера в системный профиль; таблица с колонками «Имя профиля» и «Серверы». Слева «Системный» с подписью «Разрешен транзит запросов», карандашом редактирования и кнопкой «+ Добавить профиль». Справа карточки существующих серверов с интерфейсом/адресом и кнопка «+ Добавить сервер». Это список серверов **внутри профиля**, а не один общий текстовый список адресов.
2. Добавление обычного сервера — отдельная форма: select «Тип сервера DNS» = «По умолчанию», «Адрес сервера DNS» (пример `77.88.8.8`), необязательный «Домен», select «Любой интерфейс», «Сохранить»/«Отменить». DNS провайдера и введённые вручную адреса опрашиваются параллельно; используется самый быстрый ответ. На WAN-экране отдельно есть строковые поля «IPv4 DNS 1/2» с иконками добавления/удаления и чекбоксом игнорирования DNS провайдера.
3. Шифрование включается не общим тумблером, а установкой компонента и добавлением сервера в «Профили DNS» с выбором протокола в select «Тип сервера DNS»: `DNS-over-TLS` или `DNS-over-HTTPS`. Для DoT форма показывает «Адрес сервера DNS» (`Сервер{:TLS port}`), «Доменное имя TLS», «Сигнатура SPKI», «Домен», интерфейс; порт TLS по умолчанию 853, адрес может быть IP/FQDN. Для DoH вместо адреса/имени TLS виден обязательный «URL сервера DNS», затем SPKI, домен и интерфейс. Включённые DoT/DoH замещают DNS провайдера и ручные обычные серверы; статья советует несколько серверов от разных служб.
4. «+ Добавить профиль» раскрывает inline-форму **в левой колонке**: «Имя профиля», чекбокс «Транзит запросов», «Сохранить»/«Отменить». Пример «Без фильтрации»: созданный профиль выбирают для устройства на вкладке «Контентный фильтр» → «Профили контентной фильтрации для зарегистрированных клиентов» → поле «Профиль»; запросы устройства не перехватываются фильтром, используются провайдерские/ручные DNS (либо включённые DoT/DoH). Профилю можно назначить собственные серверы.
5. «Контентный фильтр»: select «Режим фильтрации»; пагинируемая таблица «Предустановленный профиль | Описание»; «Профили контентной фильтрации по умолчанию» с select на каждый сегмент сети; «Профили контентной фильтрации для зарегистрированных клиентов» с поиском и таблицей «Клиент | Профиль», select на строку. Среди вариантов — предустановленные DNS-профили и собственный «Без фильтрации».

### Маршруты DNS — списки → правила, а не одна строка «домен → интерфейс»

1. На вкладке «Маршруты DNS» сверху «Списки доменных имен» с «+ Добавить»/«Удалить»; ниже «Правила маршрутизации» с отдельными «+ Добавить»/«Удалить». До создания списков кнопка добавления правила неактивна; в обоих пустых блоках «Нет действующих маршрутов».
2. Окно «Списки доменных имен»: поле «Имя списка», большое многострочное поле «Доменные имена, IPv4/IPv6-адреса», «Очистить», «Сохранить»/«Отменить». По одному домену или IP/подсети в строке; поддомены учитываются автоматически, `*` не нужен. Таблица списков показывает **«Имя | Доменные имена | IPv4-адреса | IPv6-адреса»**; в последних колонках — количества, не полный перечень значений.
3. Окно «Параметры DNS-маршрута»: select «Имя списка» → поле «Адрес шлюза» и/или select «Интерфейс» → чекбоксы «Добавлять автоматически» и «Эксклюзивный маршрут» с пояснениями → «Сохранить»/«Отменить». Эксклюзивность означает отсутствие маршрутизации этого трафика при недоступности выбранного интерфейса; автоматическое добавление — применение при доступности указанного шлюза.
4. Таблица **правил**, а не таблица отдельных доменов: «Включено | Имя списка | Адрес шлюза | Интерфейс | Добавлять автоматически | Эксклюзивный маршрут»; первая колонка — переключатель. Следовательно, фактическая связь `домен/IP → список → правило → шлюз/интерфейс`. Одно правило распространяется на весь именованный список.
5. Условия работоспособности из статьи: целевое подключение настроено, включено, статус «Подключено»; клиент относится к «Политика по умолчанию» на странице «Приоритеты подключений»; у клиента DNS-сервером указан **IP роутера**. Если DHCP отдал клиенту публичный DNS из ручной настройки или DoT/DoH, статья требует убрать такую выдачу; DNS через HTTPS в браузере также мешает роутеру видеть запросы. Для проверки рекомендуется сбросить DNS-кэш клиента и открыть тестовый домен.

### Доменное имя KeenDNS / CrazeDNS

1. Страница «Доменное имя» → вкладка «CrazeDNS» на актуальном снимке: описание службы, «Доменное имя Netcraze» с автоматически назначенным именем и отметкой SSL, чекбокс «Разрешить доступ из интернета», поле желаемого имени и «Зарегистрировать». При выборе имени — окно «Выберите доменное имя» со списком свободных вариантов (radio, пометки SSL), «Сохранить»/«Отменить».
2. После регистрации: строка полного доменного имени с индикатором сертификата, «Режим работы» с radio «Авто»/«Через облако»/«Прямой доступ», отдельный статус «Подключено через облако», «Не использовать IPv6», «Разрешить доступ из интернета», кнопки «Получить код передачи» и «Освободить доменное имя». Пока сертификат выпускается, вместо зелёного «С сертификатом SSL» показаны серый замок и «Получение сертификата…». Наличие имени/SSL/статуса отражено явно; авторизация посетителя веб-интерфейса не подменяет регистрацию имени: для удалённого входа нужен пароль администратора, ошибка `No auth set` описана отдельно.
3. «Доступ к веб-приложениям домашней сети» → объяснение, «+ Добавить», таблица «Доменное имя | Удалённый доступ | Назначение | IP-адрес | Протокол | Порт TCP». В отдельной форме «Настройки доступа»: «Имя» с фиксированным суффиксом домена, select «Доступ из интернета», select зарегистрированного «Устройство», radio HTTP/HTTPS, «Порт TCP», «Сохранить»/«Отменить». Пример: `qnap.myrouter01.keenetic.pro` → QNAP → HTTP/80. Раздел есть только в режиме роутера. Облако обслуживает HTTP/HTTPS на поддерживаемых портах, не FTP/RDP/RTSP/Telnet.
4. Статья «Коды ошибок KeenDNS» — справочная таблица «Сообщение | Код | Пояснение | Варианты решения», а не экран настроек. Примеры: `Not Reachable` → 404/503 (роутер/облако недоступны); `Unknown Name` → 410; `Access Denied (0x14)` → 20 (запрещён удалённый доступ); `Direct Only (0x20)` → 32 (прямой режим при частном WAN IP); `No auth set (0x30)` → 48 (нет пароля администратора); `0x91` → 145 (предел 64 облачных соединения на имя). FAQ уточняет: сброс к заводским не освобождает имя, сертификат на 90 дней обновляется автоматически.
5. «Настройка DNS Alias (CNAME)» показывает **внешний интерфейс No-IP** (`Record Type = DNS Alias (CNAME)`, `Target` = DDNS-имя), не отдельный контрол Keenetic. «Обращение к сетевому устройству по hostname» требует CLI `ip dhcp pool _WEBADMIN update-dns` либо `ip host <name> <address>`; переименование клиента через UI меняет `name`, но не DNS `hostname`. Не изображать эти функции как готовые экранные формы Keenetic.

## UX/UI-логика (паттерны)

1. Одна страница DNS объединяет вкладку серверов/профилей и соседнюю вкладку клиентской фильтрации; уровни WAN DNS, upstream-профиля и DHCP DNS разделены по контекстам.
2. Серверы представлены карточками внутри выбранного профиля; отдельные формы управляют типом сервера, адресом/URL и интерфейсом. DoT/DoH выбираются в том же select типа; состав полей меняется по протоколу.
3. Профиль редактируется inline слева; сервер и DNS-маршрут — в отдельных формах с явными «Сохранить»/«Отменить». Карандаш у системного профиля; отсутствующий сервер сопровождается текстовой инструкцией.
4. В маршрутах сначала создаётся переиспользуемый список, потом правило на него. Таблица списка показывает агрегированные счётчики доменов/IPv4/IPv6; таблица правил показывает выбранный список и путь через шлюз/интерфейс. Не заменять это вымышленной плоской таблицей отдельных доменов.
5. Ошибка обязательного поля — красная рамка и «Заполните это поле», «Сохранить» неактивно в пустой форме DoT/DoH. Кнопки действий выключены при отсутствии применимого объекта.
6. KeenDNS показывает режим соединения и фазу сертификата отдельно от переключателя разрешения доступа. Запись доступа к приложению выбирается из таблицы для изменения; у пустого блока остаётся «+ Добавить».
7. Чекбокс «Игнорировать DNSv4 интернет-провайдера» после сохранения переподключает WAN. Это опасно, когда доменное имя сервера PPPoE/PPTP/L2TP разрешается через DNS провайдера.

## Состояния и обратная связь

- DNS-маршруты до настройки: «Нет действующих маршрутов» в двух блоках; «Удалить» неактивно, добавление правила неактивно до появления списка. После настройки таблица содержит включённый переключатель и «Да» для отмеченных опций.
- DNS-профиль без добавленных серверов: пустая правая часть и инструкция нажать «+ Добавить сервер». Пустой обязательный адрес DoT/DoH: «Заполните это поле», неактивное «Сохранить».
- KeenDNS: зарегистрированное имя, реальный режим подключения, отдельная отметка «С сертификатом SSL» либо «Получение сертификата…». Пустое имя приложения валидируется сообщением «Заполните это поле». Коды удалённого доступа сопровождаются причинами/действиями в справочной таблице; при недоступном удалённом подключении диагностику выполняют из LAN.
- При использовании контентного фильтра запросы профиля фильтрации направляются его DNS-службе, обычные DNS провайдера/ручные не используются. Для «Без фильтрации» сохраняется транзит к собственным upstream DNS; с DoT/DoH — к выбранным шифрованным серверам.

## Что переносим в vs-router

- В «DNS» (`/dns`): видимый список upstream-серверов, отдельное добавление/редактирование, тип `обычный / DoT / DoH` с условными полями, явные сохранение/ошибки; различать WAN DNS, DNS для клиентов и upstream. Профили и назначение клиентам — только если наша модель это поддерживает; нельзя считать DoT/DoH обычной галочкой, скрывающей адреса.
- В «Выборочная маршрутизация» (`/routing`): доменные политики как **список доменов/IP → правило → интерфейс/шлюз**, рядом с другими маршрутами; показывать статус правила и сценарий недоступного интерфейса. Полезны счётчики списка, предупреждение о DNS клиента/DoH браузера и отсутствие ложного обещания работать при обходе DNS роутера.
- KeenDNS полезен как образец явного статуса доменного имени, сертификата и удалённого доступа к сервисам; регистрацию в чужой облачной службе, её бренд, режимы и коды ошибок нельзя механически копировать в `/dns`. Доступ к локальным веб-сервисам ближе к «Входящие сайты» (`/proxy`). Внешний CNAME No-IP и CLI-настройку hostname не выдавать за собственные формы DNS-интерфейса.
