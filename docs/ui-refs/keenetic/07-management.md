# Keenetic UI — Управление: доступ, обслуживание и диагностика

Управление разделено между страницами «Пользователи и доступ», «Общие настройки системы» и «Диагностика». Журнал находится внутри «Диагностики», а не на самостоятельной странице; SSH зависит от установленного компонента. Ниже описан именно веб-конфигуратор роутера: одноимённые «Авторизация» и «CLI» в TOC относятся к отдельной системе Netcraze RMM, не к экрану роутера.

## Навигация

- «Управление» → «Пользователи и доступ»: учетные записи, права, службы управления и удаленный доступ. Здесь же порты HTTP/HTTPS/TELNET.
- «Управление» → «Общие настройки системы»: «Обновления и компоненты KeeneticOS», «Режим безопасной настройки», «Системные файлы», «Перезагрузка системы». Безопасный режим расположен **здесь**, а не на странице пользователей.
- «Управление» → «Диагностика»: вкладки «Общая», «Активные соединения»; на поддерживаемых моделях также «Тестер кабеля». На вкладке «Общая» находятся файл диагностики, системный журнал, проверка соединения и захват пакетов. Журнал открывается кнопкой «Показать журнал» внутри этой страницы.
- Web CLI — адрес `/a` вместо `/dashboard` у того же веб-конфигуратора; полноценный CLI подключается по TELNET/SSH. Пункт «CLI» в боковом меню Netcraze RMM — другой продукт: централизованные JSON-запросы к объектам, не навигация роутера.

## Экраны и структура

### Пользователи и доступ

Секция «Учетные записи пользователей»: список пользователей с неизменяемым `admin`, клик по записи открывает отдельное окно редактирования; «Добавить пользователя» открывает окно «Новый пользователь». В окне: «Имя пользователя» (при создании), «Пароль» с индикатором надежности, показом/генерацией/копированием; далее таблица «Доступ к сервису» / «Описание» с checkbox прав. Среди строк — «Командная строка» (Telnet и SSH), «Веб-конфигуратор», «Запретить сохранять настройки системы» (только чтение); кнопка «Сохранить». Набор прав зависит от модели и компонентов; `admin` нельзя удалить/переименовать, лишить доступа к CLI или перевести только на чтение.

Ниже — «Службы управления»: поля порта HTTP (обычно 80), HTTPS (443), TELNET (23). Секция «Удаленное управление» задает доступ из Интернета по HTTP/HTTPS, TELNET и, при наличии компонента «Сервер SSH», SSH. Для веба варианты «Нет доступа», «HTTP и HTTPS», «Только HTTPS». Заводская настройка блокирует внешнее управление. **Не смешивать** флажки прав отдельного пользователя, доступность службы на LAN, ее порт и разрешение доступа из WAN. SSH в документации включается установкой компонента, а для внешних сетей описана также настройка `security-level public` через CLI; скриншот компонента «Сервер SSH» показывает checkbox «Установлен», но это не переключатель удаленного SSH-доступа. Порты HTTP/HTTPS в UI выбираются из готовых списков, произвольный HTTP-порт — через CLI; TELNET-порт допускает ввод номера. Смена порта требует указать его при следующем подключении.

### CLI и безопасная настройка

Обычный CLI — терминальная сессия TELNET/SSH с авторизацией, подсказкой `(config)>`, автодополнением Tab; после команд конфигурации — `system configuration save`. Встроенный Web CLI `/a` имеет вкладку «Parse», поле «Команда», кнопку «Отправить запрос»; это не полноценная замена терминалу. Инструкция о включении Telnet/TFTP в Windows относится к компонентам **клиентской ОС**, не к чекбоксам роутера. SSHv2 требует «Сервер SSH» в наборе компонентов, после установки доступен на private-интерфейсах; WAN-доступ и порт могут настраиваться CLI.

«Режим безопасной настройки» в «Общих настройках системы» включается checkbox. После применения измененной конфигурации меняется работающий конфиг, но не `startup-config`; всплывает перемещаемая подсказка с обратным отсчетом и действиями «Сохранить»/«Отменить». Включение через веб всегда задает **180 секунд**. «Сохранить» в подсказке → диалог подтверждения записи в начальную конфигурацию либо продолжение редактирования; после подтверждения таймер останавливается и подсказка исчезает. «Отменить» → диалог подтверждения перезагрузки с откатом либо продолжение редактирования. При утрате связи в сеансе управления по истечении таймера устройство перезагружается с последней сохраненной начальной конфигурацией; при нескольких сеансах перезагрузка происходит только после потери связи **всех** сеансов. Для иного интервала CLI-команда `system configuration fail-safe timer reboot` принимает 60–86400 секунд. Не представлять этот таймер как свободно редактируемое поле веб-формы и не обещать откат при сохранившемся сеансе.

### Общие настройки системы: обновление, файлы, перезагрузка

«Обновление и компоненты KeeneticOS»: версия ОС, «Изменить набор компонентов»; выбор канала «Основной», «Предварительный», «Канал разработчика», «LTS». В окне компонентов — группы и строки с раскрываемым описанием, checkbox и статусом («Установлен», «Будет обновлен», «Обязательный»); обязательные и требуемые другими компонентами флажки заблокированы. Завершение выбора — «Обновить KeeneticOS». Есть «Автоматическое обновление» и расписание; установка/изменение набора компонентов пересобирает/обновляет ОС и приводит к перезагрузке. Вручную доступны обновление через Интернет и загрузка файла `.bin`; изменение компонентов требует подключения к Интернету. Ошибка 507 означает недостаток внутренней памяти для выбранного набора. Перед сменой канала/обновлением рекомендовано сохранить `firmware` и `startup-config`.

«Системные файлы»: две строки `firmware` (образ ОС, модель и версия) и `startup-config` (набор команд запуска). У каждой строки справа отдельные иконки «Заменить файл» и «Сохранить на компьютер»; загрузка заменяющего файла ведет к перезагрузке. Скачанный конфиг — текстовый `startup-config.txt`; восстановление: в строке `startup-config` нажать «Заменить файл» и выбрать сохраненный файл, затем дождаться перезапуска. Файл `firmware` — отдельный бэкап версии ОС, не копия настроек. Для каждого режима работы устройства используется свой `startup-config`.

«Перезагрузка системы»: соседние кнопки «Перезагрузить» и «Вернуть заводские настройки». Последняя открывает диалог «Удаление пользовательских настроек»: нужно ввести `RESET` заглавными буквами и нажать «Удалить настройки»; сброс стирает пользовательские настройки и перезагружает устройство. При продаже доменное имя KeenDNS освобождается отдельно: заводской сброс его не отвязывает. Восстановление доступа при забытом пароле — приложение (если уже подключено), сохраненный конфиг (для опытных пользователей) или аппаратный сброс с потерей настроек; текущий пароль прочитать нельзя.

### Диагностика и журнал

На вкладке «Общая» последовательно: «Файл диагностики» → «Сохранить файл диагностики» (`self-test.txt`); «Системный журнал» → выбор вывода новых строк «Вверху»/«Внизу», «Показать журнал», checkbox «Использовать Syslog» с появляющимся полем «Адрес сервера»; «Проверка сетевого соединения» → радио «Ping», «Ping IPv6», «Traceroute», «iPerf3», поле «Адрес хоста», ссылка «Показать настройки» для дополнительных параметров, область текстового вывода, «Запустить проверку»; «Захват сетевых пакетов» → пустое состояние «Ни одно правило захвата ещё не создано» и «Добавить правило захвата» (при установленном компоненте).

Окно «Параметры захвата пакетов»: «Подключение» (сетевой интерфейс), «Место хранения» (внутренняя память/USB; при USB появляется каталог), «Размер буфера», «Максимальный размер файла (КБ)», «Максимальный размер пакета (Б)», «Тип захватываемого трафика» (входящий/исходящий/оба), «Фильтр захвата» (строка Berkeley/Capture Filter), «Тайм-аут (мс)», checkbox «Неразборчивый режим». Правило запускают кнопкой «Запустить», затем «Остановить»; для внутренней памяти — «Сохранить на компьютер» (`*.pcap`). Пустой фильтр означает все пакеты, например `udp port 53` — только DNS. Возможны потери при высокой нагрузке; файл циклический. Статья о Wireshark описывает **отдельную программу на ПК** и ее display filters, а не фильтры журнала Keenetic. Мобильная «Диагностика приложения» также не является страницей роутера.

«Активные соединения»: таблица «Активные соединения IPv4», сгруппированная по источнику с раскрытием конкретных соединений; столбцы «Источник», «Соединения», «Адрес назначения», «Служба», поля «Найти» по соответствующим столбцам. «Тестер кабеля» (не все модели/порты): визуальный выбор порта, «Тестировать», таблица результатов по парам A–D со статусом и расстоянием до дефекта.

После «Показать журнал» открывается панель «Системный журнал»: «Скачать» (`log.txt`), «Обновлять в реальном времени», «Очистить журнал», крестик закрытия; записи показывают время, источник (`dhcpd`, `ndm` и др.) и текст, разделенные линиями. В показанных снимках **нет** UI-фильтра по уровням, поисковой строки или селектора severity; не приписывать их Keenetic. Выбор «Вверху»/«Внизу» относится к расположению новых строк, а не уровню событий. В памяти до 3000 записей; для долгого хранения — «Использовать Syslog» + IP сервера, «Сохранить», отправка BSD syslog по UDP/514 (внешний сервер). Защита от перебора включена по умолчанию: пять ошибок за три минуты с одного IP → блок на 15 минут; события блокировки видны в системном журнале, логирование неудачной HTTP-авторизации отдельно включается CLI.

## UX/UI-логика (паттерны)

1. Список пользователей → отдельная форма-окно, а не inline-редактирование; права — таблица checkbox + пояснения, пароль — маска, индикатор, генерация/копирование.
2. Доступ разделен на учетные права, работу сервиса/установку компонента, LAN/WAN-ограничения и порт. Наличие SSH в списке удаленного управления зависит от установки компонента.
3. Рискованные действия не равны обычному «Save»: безопасный режим держит живую, но несохраненную конфигурацию с видимым счетчиком и **двумя подтверждениями** («Сохранить» и «Отменить»); заводской сброс требует буквального `RESET`.
4. Диагностические инструменты сгруппированы на вкладке «Общая»; дополнительные настройки ping свернуты за «Показать настройки», активные соединения вынесены на вкладку. Захват имеет пустое состояние → форма правила → запуск/остановка → экспорт `.pcap`.
5. Журнал открывается по требованию; «Скачать» рядом с заголовком, live-update и очистка в шапке панели, Syslog настраивается на исходной странице. Фильтров уровней на просмотренных экранах нет.
6. Системные файлы представлены строками с двумя действиями на каждой: заменить и скачать. Компоненты представлены раскрываемыми строками с отключенными обязательными checkbox.

## Состояния и обратная связь

- Безопасная настройка: таймер и подсказка о несохраненном; после подтверждения сохранения — исчезновение подсказки; после подтверждения отмены — перезагрузка и возврат предыдущей начальной конфигурации. При потере единственного сеанса откат срабатывает по истечении таймера; при нескольких сеансах ожидается потеря всех.
- Захват: «Ни одно правило захвата ещё не создано» до первого правила; состояния «Запустить»/«Остановить»; экспорт после остановки. Отсутствие компонента скрывает доступность настройки захвата.
- Обновление: статусы компонента «Установлен», «Будет обновлен», «Обязательный», затененный checkbox; сетевой сбой сервера обновлений и ошибка 507 описаны в FAQ. После обновления ОС автоматически перезагружается.
- Журнал: записи добавляются сверху или снизу; live-обновление можно выключить; старые записи вытесняются после лимита, поэтому Syslog — отдельный путь долговременного хранения.
- Сброс: явное текстовое подтверждение `RESET`; восстановление файла вызывает перезагрузку. Без прежнего бэкапа восстановить пароль администратора из хеша нельзя.

## Что переносим в vs-router

- `/ssh`: разграничить учетные права CLI, состояние SSH-сервиса, слушающий порт, LAN/WAN-доступ; показать зависимость от установленного сервиса. Не копировать Telnet как безопасную альтернативу SSH и не переносить RMM CLI как роутерный экран.
- `/maintenance`: отделить обновления от `startup-config`/прошивки, дать парные «скачать»/«восстановить» с предупреждением о перезагрузке, явное подтверждение сброса. Безопасную настройку — как применение с обратным отсчетом, явными подтверждениями сохранения/отмены и серверным откатом; 180 секунд — референс Keenetic, не автоматически подходящий таймаут для нас.
- `/events`: читаемая лента «время → источник → сообщение», live-обновление, экспорт, Syslog отдельно. Не копировать несуществующие в референсе фильтры severity как «паттерн Keenetic»; наши фильтры, если нужны, проектировать самостоятельно.
- `/diagnostics`: сгруппировать ping/traceroute и расширенные параметры, таблицу соединений, управляемый захват по интерфейсу/направлению/BPF с экспортом `.pcap`; TDR показывать лишь при аппаратной поддержке. `self-test.txt`, Wireshark на ПК и диагностика мобильного приложения не означают готовые встроенные функции vs-router.
