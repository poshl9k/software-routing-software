# Восстановление доступа к мастер-порталу

## Граница и решения

- Почтовое восстановление доступно **только абонентам** `vs_master`. Административный пароль меняется только из локальной консоли сервера; публичных admin-reset API, email-ссылок и Telegram-зависимости для этой операции нет.
- Email для восстановления должен быть подтверждён из авторизованного абонентского кабинета. Старые и новые аккаунты без подтверждённой почты не восстанавливаются через публичную форму; обратиться в поддержку или воспользоваться уже действующей ссылкой входа. Адрес, присланный при регистрации, не становится подтверждённым автоматически.
- Публичная форма запроса даёт одинаковый ответ для существующего и неизвестного адреса. Одноразовые подтверждение адреса и сброс пароля имеют независимые назначения, ограниченный срок, криптографически случайный токен, хеш токена в БД и атомарное погашение. В письмах нет пароля; ссылки используют канонический HTTPS-адрес мастера из доверенной конфигурации, а не `Host` запроса.
- После смены пароля все старые веб-сессии абонента недействительны, в том числе при нескольких воркерах. Событие аудита не содержит пароль, ссылку или токен. Долговременная ссылка кабинета и токены нативных клиентов — **другие учётные данные**, их смена пароля сама по себе не отзывает. При подозрении на компрометацию их необходимо перевыпускать отдельно и сообщать о последствиях для подключённых приложений.
- Для отправки используется только явно настроенный SMTP с TLS и отдельными секретами в защищённой конфигурации сервиса. Отправку следует исполнять вне HTTP-запроса, с повтором при временном сбое и без утечки токенов в журнал. Не создавать в продакшене фиктивные ссылки при отсутствии настройки.

## Публичный контракт абонента

| Действие | Эндпоинт / маршрут | Результат |
| --- | --- | --- |
| Привязка email | `POST /api/portal/email/request`, кабинет | Письмо со ссылкой `/portal/email/confirm#token=…`; текущий подтверждённый email пока не меняется |
| Подтверждение email | `POST /api/portal/email/confirm` | Новый email становится подтверждённым для аккаунта |
| Запрос восстановления | `POST /api/portal/password/forgot`, форма входа | Одинаковое подтверждение независимо от существования адреса |
| Сброс | `POST /api/portal/password/reset`, ссылка `/portal/password/reset#token=…` | Новый Argon2id-хеш и отзыв прежних веб-сессий; обычный вход по новому паролю |
| Смена пароля администратора | `python -m vs_master.change_admin_password` в консоли сервера | Новый Argon2id-хеш; публичный API отсутствует |

Токен передаётся в fragment (`#token=…`) и удаляется из адресной строки сразу после загрузки страницы. Пароль в письме не отправляется. Новый пароль абонента — минимум 12 символов.

## Переменные окружения мастера

- `VS_MASTER_PUBLIC_URL` — канонический публичный HTTPS-адрес без пути, обязателен.
- `VS_MASTER_SMTP_HOST`, `VS_MASTER_SMTP_PORT`, `VS_MASTER_SMTP_SECURITY` (`starttls` или `tls`), `VS_MASTER_SMTP_FROM` — обязательны.
- `VS_MASTER_SMTP_USERNAME` и `VS_MASTER_SMTP_PASSWORD` — указываются вместе, если SMTP требует аутентификацию.
- `VS_ROUTER_SECRET_KEY` — существующий ключ шифрования/master.env; используется и для шифрования тел писем в outbox.

Отправка выполняется `vs-master-worker.service` через `vs_master.mail.process_email_outbox`; при отсутствии конфигурации публичный запрос получает общий `503 portal.email_unavailable` для любого адреса и ничего не отправляет.

## Операционные условия при выпуске

1. Применить новую `alembic-master` миграцию к мастер-БД после резервной копии; не выполнять её на живой системе до отдельного разрешения на развёртывание.
2. Настроить канонический публичный HTTPS URL и SMTP (адрес отправителя, хост, порт, аутентификация/TLS) в закрытом `master.env`; проверить тестовое письмо на отдельном адресе и отсутствие секретов в логах.
3. Проверить сквозной цикл на одноразовой БД и почтовом приёмнике: подтверждение, сброс, повтор токена, истечение, неизвестный email, несколько сессий, ошибки доставки и перезапуск воркера. Unit-тесты не доказывают реальную доставку.
4. Ручная консольная смена пароля администратора требует административного доступа к хосту; не предоставлять эту возможность через абонентский API или прокси.

Статус: код, миграция и тесты реализованы; развёртывание, реальная SMTP-доставка и сквозная проверка на мастере не выполнялись. Никакой отправки реальной почты или изменения живой мастер-БД этот документ не выполняет.
