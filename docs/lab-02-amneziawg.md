## Ключевая находка для панели (важно для генератора конфигов)

**`awg-go` принимает ИМЯ ИНТЕРФЕЙСА, а не путь к конфигу.** Правильный паттерн запуска:

```bash
# 1. Запуск демона (сам создаёт TUN-интерфейс):
WG_PROCESS_FOREGROUND=1 awg-go awg0 &

# 2. Применение конфигурации ПОСЛЕ старта:
awg setconf awg0 /path/to/config.conf
ip link set awg0 up
ip addr add X.X.X.X/XX dev awg0
```

Паттерн `awg-go -f /path/to.conf` из внешних док — не работает как ожидается:
демон трактует путь как **имя интерфейса**, ioctl TUNSETIFF падает с EINVAL
(имя > IFNAMSIZ). Зафиксировано в `lab/awg-setup.sh`, `lab/awg-config.sh`,
`lab/test-awg.sh`.

**Правки конфига на живом демоне**: `awg setconf` применяет изменения
без рестарта демона (например, смена обфускационных параметров на лету —
подтверждено: setconf → туннель восстанавливается).

**Формат конфигурации для setconf**: только ListenPort/PrivateKey +
секция `[Peer]` (без `Address` — адрес интерфейса задаётся ip-link/ip-addr,
не setconf). Строки типа `Address=10.66.66.1/24` в setconf-файле вызывают
`Configuration parsing error`.

## Формат конфига для мобильных клиентов Amnezia (экспорт из панели)

Секция `[Interface]` + `Jc/Jmin/Jmax/S1/S2/H1-H4` + `[Peer]` с PublicKey,
Endpoint, AllowedIPs, PersistentKeepalive — совместим с мобильными клиентами
Amnezia. Формат и семантика подтверждены в этой проверке.

## Критерий этапа 0 (AmneziaWG-часть)

✅ AmneziaWG userspace работает: установка из исходников, параметры обфускации
применяются и защищают от несовпадения, профили клиентского формата совместимы
с форматом наших скриптов (генерируем тот же вид конфига, что в мобильных
клиентах Amnezia).

## Не проверено здесь (следующие шаги)

- Kernel-модуль AmneziaWG (amneziawg-linux-kernel-module) — тест после MVP
  (см. ADR-0001). Userspace подтвердили как достаточный для MVP.
- Массовый тест с более чем 1 peer'ом — вероятно, поведение аналогично WireGuard,
  не блокирует MVP.
