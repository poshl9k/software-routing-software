# Сегменты SSID → VLAN → выход (эксплуатация)

Практическое руководство: как поднять на пограничном роутере схему «несколько
SSID, у каждого свой VLAN и свой выход: РФ-адреса — через указанный вышестоящий
роутер, заблокированное — через AWG». Технические решения и их обоснование —
`docs/router-split-routing-plan.md`, ADR-0019/0023/0028/0029/0031.

Роли в схеме:

| Кто | Что делает | Чего не делает |
|---|---|---|
| Omada (контроллер точек) | SSID, привязка SSID → VLAN, тегирование на точке | не раздаёт DHCP, не маршрутизирует |
| Панель vs-router | L3 между VLAN, DHCP, DNS, firewall, перехват и выбор выхода | не управляет точками и SSID |
| Клиент | получает адрес и DNS по DHCP | — |

SSID в панели **не** хранится: панель видит только VLAN-интерфейс. Переименование
SSID в Omada ничего не ломает.

## 1. Omada: SSID → VLAN

1. Создайте нужное число VLAN на коммутаторе/точках (например 1010, 1020, 1030).
2. Для каждого SSID в профиле WLAN укажите **VLAN ID** и включите «VLAN
   Tagging» (тегированный трафик до порта, где стоит панель).
3. Порт, в который включена панель, должен быть **транком** (в ESXi — портгруппа
   с VLAN ID 4095, Promiscuous/Forged transmits/MAC changes = Accept).
4. DHCP на точках/контроллере **выключите**: адрес выдаёт панель, иначе клиент
   получит адрес от Omada и пройдёт мимо всей политики.

## 2. Панель: адреса VLAN

«Подключения и адреса» → добавить интерфейс типа `vlan`:

- `parent` — транк-интерфейс (например `ens256`);
- `vlan_id` — тот же номер, что в Omada (1010);
- `zone` — `lan`;
- адрес — шлюз сегмента, например `10.10.10.1/24`;
- поле «описание» — свободная метка оператора («гостевая», «IoT», …).

Сегмент без `zone` не участвует в маршрутизации: fail-closed.

## 3. DHCP и DNS для сегмента

- DHCP-подсеть (`DHCPSubnet`) создаётся на интерфейсе сегмента; шлюз и DNS —
  адрес панели в этом VLAN.
- DNS: «DNS» → «Интерфейсы» — добавить интерфейс сегмента (резолвер слушает и
  там), «Кому отвечает резолвер» — добавить подсеть сегмента в `access_control`
  (кнопка «Добавить сети LAN»). Без этого клиенты получат `REFUSED`.
- Доменные правила видят только DNS, который проходит через панель: клиент с
  собственным DoH/DoT обойдёт их, поэтому начинайте с IP-наборов.

## 4. Перехват сегмента

«Маршрутизация» → «Сегменты» → карточка сегмента → тумблер
**«Перехватывать трафик сегмента»**.

Тумблер делает три вещи: включает `tproxy.enabled`, добавляет интерфейс в
`ingress_interfaces` и регистрирует его в `dns.interfaces`. Пока он выключен,
правила сегмента — заготовка: они сохраняются, но трафик через них не идёт.

Перехват работает по IPv4. IPv6 на сегменте с перехватом блокируется, а не
маршрутизируется.

## 5. Источники списков

«Маршрутизация» → «Источники списков» → «Добавить источник»:

| Поле | Значение |
|---|---|
| Имя | `ru-ips` (так на него ссылаются правила) |
| Формат | `json` |
| Адрес | ссылка на IP-набор РФ, например `https://raw.githubusercontent.com/MetaCubeX/meta-rules-dat/sing/geo/geoip/ru.json` |

Допустимы только `json` и `srs`; бинарные `.srs` этот загрузчик пока не
активирует (нужен текстовый формат). Объявление ничего не скачивает: загрузку
запускает кнопка «Обновить» в таблице статусов (действие агента, не сохранение
черновика). Лицензию и допустимость использования списка проверяет оператор —
каталог показывает провенанс и помечает неподтверждённые лицензии.

## 6. Выходы: РФ-интерфейс и AWG

Выход задаётся в правиле сегмента («Изменить политику»):

**РФ-выход** — `интерфейс` + `адрес-источник` + `шлюз`:
- интерфейс — тот, что смотрит в сторону вышестоящего роутера;
- адрес-источник — адрес этого интерфейса, с которого выходить (если у линка
  несколько адресов);
- шлюз — адрес вышестоящего роутера. Обязателен, когда на одном интерфейсе
  несколько роутеров: иначе трафик уйдёт в шлюз по умолчанию.

Панель превращает пару «источник + шлюз» в отдельную таблицу маршрутизации и
правило `from <источник>`.

**AWG-выход** — `туннель` + `адрес-источник`:
- туннель создаётся на странице «Туннели» (роль `client`, протокол `AWG`,
  ключи и обфускация из конфига сервера);
- адрес-источник — адрес туннеля на этом хосте (`10.66.66.5`, из конфига).
  Без него пакеты уйдут с адресом другого маршрута и пир их отбросит.

## 7. Политика сегмента

В редакторе сегмента: список правил сверху вниз, последним — **«Всё остальное»**
(`0.0.0.0/0`), иначе трафик без совпадения провалится к правилам другого
источника. Типовой набор:

| № | Что | Куда |
|---|---|---|
| 1 | набор `ru-ips` | РФ-выход (интерфейс + источник + шлюз) |
| 2 | `0.0.0.0/0` («Всё остальное») | AWG-туннель |

Пресеты в редакторе собирают такой набор одной кнопкой.

## 8. Применение и проверка

1. «Порядок и применение» — прочитать предупреждения (необъявленный выход, шлюз
   не в подсети, туннель без источника, выключенный перехват).
2. «Применить». Первое применение — только в безопасном режиме (безопасная
   версия ждёт подтверждения; перезагрузка её не подтверждает).
3. Проверка с клиента сегмента:

```sh
curl -sk https://1.1.1.1/cdn-cgi/trace | grep -E '^ip=|^loc='   # заблокированное: ждём адрес VPN
curl -s  https://api.ipify.org                                   # РФ-выход: ждём адрес своего провайдера
getent hosts example.com                                         # DNS отвечает панель
```

Разные сегменты должны показывать **разные** адреса РФ-выхода, если у них разные
вышестоящие роутеры.

## 9. Диагностика

| Симптом | Что смотреть |
|---|---|
| Клиент не получает адрес | DHCP-подсеть на интерфейсе сегмента, транк/тегирование, отсутствие DHCP на точках |
| Клиент не получает DNS (`REFUSED`) | подсеть в `dns.access_control`, интерфейс в `dns.interfaces` |
| Сайты открываются, но политика «не работает» | тумблер перехвата сегмента; в «Порядке» предупреждение «перехват выключен» |
| Ничего не открывается, в логах движка пусто | контур перехвата: `nft list tables \| grep tproxy`, `ip rule \| grep fwmark 0x100`, `ip route show table 100` — таблицы и правило должны жить парой |
| Туннель поднят (handshake есть), трафик не идёт | адрес-источник у выхода; на стороне сервера — `awg show <iface>` (счётчики пира) |
| Сегмент «сломался» после неудачного применения | применить заново: контур перехвата ставится и снимается целиком, полуоткрытого состояния быть не должно |

## 10. Ограничения текущей версии

- Перехват и выходы — IPv4; IPv6 на сегментах с перехватом блокируется.
- Per-segment выход работает только у сегментов **с перехватом**: без него
  трафик идёт обычным форвардом по основному маршруту.
- Failover между РФ-выходами не делается: недоступный вышестоящий роутер
  закрывает сегмент, а не переключает его на другой.
- Доменные правила требуют, чтобы DNS клиента шёл через панель.
- Управление Wi-Fi/SSID — только Omada.
