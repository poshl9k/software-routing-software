# Протокол лабораторной проверки №1 — Kea DHCPv4

Дата: 26 сентября 2026 · VM: Debian 13.7 (trixie), ядро 6.12.107+deb13-amd64, 2 vCPU / 4 ГБ
Тестовая среда: Kea привязан к br-test (dummy0 + veth в netns `dhcptest`), подсеть 192.168.50.0/24, пул .100–.200

## Результаты

| Проверка | Результат | Детали |
| --- | --- | --- |
| Версия из пакета Debian | **Kea 2.6.3** (kea-dhcp4-server, kea-ctrl-agent) | 4 пакета kea* |
| Синтаксис-валидация | ✅ `kea-dhcp4 -t` | запуск под `_kea` (служба делает то же) |
| Резервация **внутри пула** | ✅ | MAC aa:bb:cc:00:00:01 → получил 192.168.50.110 (внутри .100–.200), а не из пула |
| Резервация вне пула | ✅ (конфиг) | .10 (nas) вне пула принята, конфиг валиден |
| Клиент БЕЗ резервации не получает зарезервированный адрес | ✅ | MAC aa:bb:cc:00:00:99 → получил .100 из пула; .110 за резервированным клиентом закреплена |
| Аренды через ctrl-agent | ✅ `lease4-get-all` | требует hook **lease_cmds** в `hooks-libraries` |
| Статистика | ✅ `statistic-get`/`statistic-get-all` | hook **stat_cmds** (cumulative-assigned-addresses, pkt4-ack-sent…) |
| `config-reload` без рестарта | ✅ | новый hash, сервис не рестартовал |
| Ctrl-agent | ✅ | HTTP Basic auth, 127.0.0.1:8000, юникс-сокет до dhcp4 `/run/kea/kea4-ctrl-socket` |

## Находки и решения

1. **`host_cmds` (резервации через API) в пакете Debian отсутствует** — свободная сборка его не включает.
   → Подтверждает архитектуру из CONTEXT.md: **резервация — конфигурационный объект**, панель генерирует её в конфиг-файл (проверка `-t` + `config-reload`), а не пишет через API. Аренды читаются через ctrl-agent.
2. **Путь kbd:** для hooks в конфиге — ключ `library`, не `hook`.
3. **Unix-сокет dhcp4** — создается только при явном `control-socket` в `kea-dhcp4.conf` (по умолчанию нет).
4. **Auth ctrl-agent** — HTTP Basic (`user: kea-api`, пароль в файле, относительное имя = `/etc/kea/<file>`); нужен непустой `/etc/kea/kea-api-password`, иначе юнит не стартует (ConditionFileNotEmpty).
5. Проверка "-t" от root даёт ложный `Unable to open file` (каталог /etc/kea 750 `_kea:_kea`) — валидатор запускать как `_kea` (служба и делает).
6. Дубли: Kea сам защищает in-pool резервации — другому клиенту резервированный адрес не выдаётся.

## Критерий этапа 3 (часть)

✅ Адрес внутри пула стабильно получает нужный клиент; ✅ не выдаётся другим; ✅ конфликт/аренда видны через API до применения; ✅ `config-reload` без простоя.

## Не проверено здесь (будущие проверки)

- Реальный конфликт резервации с действующей арендой при рестарте (в логах видно предупреждение).
- DHCPv6/RA — вне MVP.
