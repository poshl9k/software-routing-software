# Документация администратора vs-router

Руководство для администратора панели. Семантика терминов — в `CONTEXT.md`.

## Первый запуск

1. Откройте панель. Если пользователи не созданы — мастер первого запуска: учётка администратора (`/api/setup`, работает только пока таблица пуста), базовая сеть, предложение включить «безопасную настройку».
2. Роли: **admin** — полный доступ; **operator** — только чтение (в UI после MVP).

## Цикл применения конфигурации

Все изменения делаются через черновик:

1. **Сохранить черновик** — изменения накапливаются в draft-версии (одна за раз, переживает закрытие браузера).
2. **Проверить** — доменные валидаторы + синтаксис всех сервисов (`nft -c`, `unbound-checkconf`, `kea-dhcp4 -t`, `caddy validate`); конфиг не применяется.
3. **Применить** — конфигурация применяется целиком ко всем сервисам (nftables, networkd, Unbound, Kea, туннели, Caddy, DDNS).
4. **Подтвердить** — только явная кнопка. Перезагрузка не подтверждает.

### «Безопасная настройка»

Параметр (Настройки/onboarding), по умолчанию **выключен**.

При включении каждое применение получает окно подтверждения (по умолчанию 180 с, диапазон 60–600):

- в UI идёт обратный отсчёт; «Подтвердить» фиксирует, «Откатить» — немедленный откат;
- истечение таймера — **автооткат** к последней подтверждённой версии (systemd-таймер на хосте, работает даже если панель недоступна);
- активная проба: если панель перестала отвечать после применения — откат через несколько секунд;
- перезагрузка внутри окна: после загрузки конфиг считается неподтверждённым и будет откатан, если вы не подтвердите.

Правило: применённая, но не подтверждённая конфигурация никогда не остаётся активной после ребута.

## Разделы панели

### Сеть

Интерфейсы (physical/bridge/vlan), зоны (`wan`, `lan`, пользовательские). Интерфейс без зоны — **fail-closed**: транзитный трафик не пропускается. WAN-адреса: первый адрес — основной, дополнительные задаются как /32 (реальные адреса от провайдера) и равноправны во всех правилах. DHCP-клиент на WAN — соглашение «зона wan, адресов нет».

### Firewall

Модель pfSense: правила привязаны к зоне **входа**, first match wins, действия pass/block/reject, disable без удаления, неявный default deny, счётчики пакетов. Anti-lockout: авто-правило на порт панели с LAN (отключаемое).

- **Port forward** — отдельный список; к каждому автоматически создаётся filter-правило; порт-форвард приоритетнее локальных сервисов роутера.
- **Outbound NAT** — режимы: автоматический (masquerade в основной WAN-адрес), гибридный (ручные + авто), только ручные, выключен. Правила: translation address (основной | конкретный WAN-адрес | вручную), флаг «Do not NAT».
- **Псевдонимы** — типы «Адреса» (IP/CIDR/диапазоны) и «Порты» (tcp/udp, диапазоны); вложенность только совместимых типов; циклы запрещены; пересечения — предупреждение. Лимиты: 10 000 элементов — предупреждение, 100 000 — ошибка.

#### Импорт/экспорт псевдонимов

- **JSON** — полный формат со связями (`schema_version: 1`); восстанавливает вложения.
- **TXT** — одна строка = значение: адреса (IP/CIDR/диапазон, `#` — комментарии), порты строго с протоколом (`tcp/80`, `udp/53`).
- **CSV** — `value,description`.
- Импорт сначала показывает **предпросмотр** с ошибками строк и дубликатами; применяется только через подтверждение (создаёт черновик, конфликт имён — replace или skip).

### DHCP (Kea)

Подсети, пулы, роутеры, DNS. Резервации — по MAC, **внутри и вне пула**; резервация — конфигурационный объект (переживает ребут). Дубликаты и адреса интерфейса запрещены. Live-аренды и поиск по MAC/IP/hostname — из ctrl-agent (только чтение; конфиг меняется только через файл).

### DNS (Unbound)

Режим forwarding (рекурсия опцией). Локальные записи (host overrides), per-domain forwards (домен → upstream), выбор интерфейсов прослушивания, upstream-серверы. Журнал запросов — через log_queries (ротация после MVP).

### Туннели

Роль (**сервер**/клиент) выбирается при создании и не меняется; протокол **wg** или **awg**. Для awg обязательны параметры обфускации (Jc, S1, S2, H1–H4). Сервер: пиры + экспорт клиентских конфигов (bundle; QR — после подключения UI). Клиент: endpoint, ключ, AllowedIPs, keepalive. AllowedIPs ≠ маршруты: маршруты выводятся из AllowedIPs (0.0.0.0/0 → default с метрикой 100). Импорт сторонних `.conf` — после MVP.

### Прокси (Caddy)

Сайты: hostname → upstream. Режимы сертификата:

1. **HTTP-01** — авто Let's Encrypt; домен должен резолвиться в выбранный WAN-адрес, порт 80 доступен; конфликт с port forward на 80 — предупреждение.
2. **DNS-01** — через Cloudflare API; wildcard и закрытые порты.
3. **Ручной** — загрузка сертификата+ключа.
4. **Passthrough (SNI)** — TLS не завершается на Caddy, сертификат на внутреннем сервере (L4-модуль).

### DDNS

Провайдеры Cloudflare и RFC 2136; токен/ключ — зашифрованы. Обновление — systemd-таймер каждые 5 минут; статусы per-job.

### Диагностика

ping (выбор интерфейса, парсинг потерь/RTT), traceroute, счётчики правил firewall.

## Бэкап и восстановление

- `GET /api/backup/export` — JSON-архив версий. Без пароля секреты заменяются маркерами; с паролем (`include_secrets=true`) — шифруются (PBKDF2 + Fernet).
- `POST /api/backup/restore` — восстановление версий новыми id; секреты-маркеры остаются пустыми (ввести заново).
- Храните экспорт с секретами только в защищённом месте; без пароля он бесполезен атакующему, но и не восстанавливает секреты вам.

## Аварийные ситуации

- **Потерял доступ после применения** — при включённой «безопасной настройке» конфиг откатится сам (таймер на хосте не зависит от панели). Дождитесь окна.
- **Панель недоступна, «безопасная настройка» выключена** — SSH: `sudo systemctl start vs-router-rollback.service` — немедленный откат к confirmed-версии вручную.
- **Проверка текущего состояния** — `sudo cat /run/vs-router/marker.json` (статус/dedline/фазы), `sudo nft list table inet vs_router`.
- Конфигурации лежат в `/etc/vs-router/applied/` (активные) и `/etc/vs-router/confirmed/` (последняя подтверждённая).
