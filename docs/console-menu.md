# Консоль управления (аналог pfSense console menu)

## Зачем
Сейчас после установки на реальное железо панель ожидает фиксированный `192.168.10.1/24` и
management-провижининг «вручную командой» (`python3 -m vs_router.agent.management_console --mac …`).
На реальной машине это неудобно и неочевидно: адрес по DHCP, панель недоступна, LAN не задать.
pfSense решает это **консольным меню** на физической консоли — сразу после загрузки.

## Эталон pfSense (для ориентира)
Консольное меню pfSense (2.7), пункты:
`0 Logout · 1 Assign Interfaces · 2 Set interface(s) IP address · 3 Reset webConfigurator password ·
4 Reset to factory defaults · 5 Reboot · 6 Halt · 7 Ping host · 8 Shell · 9 pfTop · 10 Filter Logs ·
11 Restart webConfigurator · 12 PHP shell · 13 Update from console · 14 Enable sshd ·
15 Restore recent configuration`.
Ключевые сценарии: **Assign Interfaces** (WAN/LAN/OPT по каждому NIC, затем подтверждение) и
**Set interface IP address** (интерфейс → DHCP или static IP/prefix + gateway, для LAN — DHCP-сервер).
Источник: поведение консоли pfSense (доки netgate по консоли сейчас отдают 404; значение фиксируем
по известному меню, не цитируем как страницу).

## Наше меню (предлагаемое), для локальной root-консоли (TTY/VGA/SERIAL)
```
0) Выход (только по SSH)
1) Назначить интерфейсы (WAN/LAN)
2) Задать IP-адрес интерфейса
3) Сменить пароль администратора
4) Показать состояние
5) Сохранить и применить
6) Перезагрузить
7) Выключить
8) Ping-проверка
9) Оболочка (shell)
```
- **1) Назначить интерфейсы:** по каждому физическому NIC (имя, MAC, link up/down) спросить роль
  `WAN / LAN / пропустить`; подтверждение перед записью. (VLAN — вне объёма v1.)
- **2) Задать IP-адрес:** выбрать интерфейс → `DHCP` или `static (IP/префикс, шлюз, DNS)`; для LAN —
  адрес, по которому откроется панель (по умолчанию `192.168.10.1/24` можно оставить, но он
  **не обязателен** и задаётся здесь, а не молча установщиком).
- **3) Пароль администратора:** задать/сменить (argon2id, через приложение).
- **4) Состояние:** интерфейсы+адреса, зоны, версия, состояние сервисов (agent/web/caddy/sing-box),
  адрес панели `https://<LAN>/` и отпечаток CA.
- **5) Сохранить и применить:** строит/обновляет конфигурацию **через штатный путь приложения**
  (parse/validate/apply), а не правкой SQLite; первое применение с учётом management-guard.
- **6/7) Перезагрузка/выключение**, **8) Ping**, **9) Shell** — служебные.

## Правила и интеграция
- Меню доступно **только на локальной консоли** (root, настоящий TTY, нет `SSH_CONNECTION`) — как
  сейчас у `management_console`; по SSH вместо меню обычный shell.
- Системно: заменить `getty@tty1` на юнит `vs-router-console.service` (и опционально
  `serial-getty@ttyS0`), который запускает `python3 -m vs_router.agent.console_menu`. Если
  подтверждённой конфигурации нет — меню стартует автоматически; когда есть — показывайте статус и
  адрес панели, оставляя возможность изменить настройки.
- Установщик/бутстрап **больше не назначают фиксированный `192.168.10.1`** молча: адрес LAN
  выбирается в меню (можно предложить дефолт). Сообщение бутстрапа указывает на меню, не на CLI.
- Переиспользовать существующее: `agent/management_console.py` (`Console.provision`, `certificates`,
  `Management`, `verify_identity`, генераторы caddy/networkd), `management.py`.
- Безопасность сохранить: fail-closed, никаких секретов в логах, изменения — через штатный путь.

## Границы
VLAN-назначение, DHCP-сервер настройка, multiple OPT — вне v1 (можно далее).
