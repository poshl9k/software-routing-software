# ADR-0023: Туннель-сервер пропускает трафик своих клиентов наружу

**Status:** предложен

**Date:** 2026-10-16

**Deciders:** пользователь, Hermes

## Context

Серверный туннель в панели уже получает **входящее** правило: порт прослушивания
открывается на WAN (`tunnel_<имя>`, только при `open_port`). Исходящего пути у
клиентов не было вовсе.

На живом VPS это проверено: клиент подключается по AWG (handshake проходит),
но интернета нет. В применённом наборе `forward` — политика `drop`,
`firewall_rules: []`, и ни одного `accept` для новых соединений. Правило
masquerade (`oifname eth0 ip saddr 10.66.66.0/24 masquerade`) стояло со
счётчиком **0 packets**: пакеты до NAT просто не доходили.

При этом туннель-клиент (role=client) наружу ничего не несёт — он сам
потребитель чужого выхода.

## Decision

Генератор nftables добавляет для каждого серверного туннеля правило forward:
трафик с интерфейса туннеля в зону WAN — `accept`, с комментарием
`tunnel_<имя>_forward`. Клиентские туннели такого правила не получают.

Правило эмитится **после** правил оператора, поэтому явный `block` по-прежнему
главнее: «разрешить наружу по умолчанию, если оператор не запретил».

Экспорт клиентского конфига отдаёт публичные DNS (`1.0.0.1`/`1.1.1.1`), а не
адрес туннеля: панель пока не обслуживает DNS на туннеле, и выданный адрес, на
котором никто не отвечает, оставляет клиента без разрешения имён (ADR-0020
заменит это resolver'ом абонентов).

## Rationale

- **Оставить как было (оператор добавит правило).** Отвергнуто: продукт с
  «подключился, но не работает» не выполняет своё назначение, а входящее
  правило порта панель уже генерирует сама — асимметрия выглядит как забывчивость.
- **Явный `accept` в начало forward.** Отвергнуто: тогда оператор не мог бы
  запретить выход туннеля своим правилом, и «first-match» стал бы ложью.
- **`policy accept` в forward.** Отвергнуто: ломает документированный
  default-deny (AGENTS.md) и открывает транзит между зонами.
- **Рекламировать DNS туннеля.** Отвергнуто: `unbound` на хосте слушает только
  `127.0.0.1` с `local-zone "." refuse` — адрес туннеля никем не обслуживается.

## Consequences

- Интернет у клиента появляется сразу после применения, без ручных правил.
- Появляется видимое исключение в default-deny; оно печатается в сгенерированном
  наборе рядом с прочими авто-правилами и покрыто тестом (в т.ч. на приоритет
  операторского `block`).
- Позже, когда появится политика выхода на туннель (ADR-0019: `sing-box` как
  маршрутизатор), это правило станет основой захвата, а не носителем решения.
- Раздача DNS абонентам остаётся незакрытой: до ADR-0020 клиент использует
  публичный resolver, и это записано явно, а не спрятано.

Связанные: ADR-0019 (маршрутизация), ADR-0020 (DNS абонентов), ADR-0022 (экспорт).
