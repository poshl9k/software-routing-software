# ADR-0034: Обфусцированные входящие абонентов (sing-box inbound-серверы)

**Status:** предложен

**Date:** 2026-10-24

**Deciders:** пользователь, Hermes

## Context

Сегодня единственный вход абонента — AWG-туннель (ADR-0016/0024): идентичность
устройства определяется адресом в туннеле. ADR-0019 сознательно отложил решение
«VLESS как вход абонента»: это отдельное решение, потому что идентичность
абонента меняется с адреса в туннеле на учётные данные (UUID/пароль), и оно не
следует из выбора маршрутизатора.

Запрос пользователя: наряду с AWG нужны **входящие**, к которым клиенты
подключаются по обфусцированным протоколам (VLESS/Reality и т.п.) — для сред,
где WireGuard-трафик блокируется DPI. Выход (маршрутизация sing-box,
ADR-0019/0029) уже спроектирован и не является предметом этого ADR.

Факт из кода: `ProxyOutbound` (`schema.py`) уже несёт полный словарь клиентских
протоколов (vless/reality/flow/uTLS, trojan, hysteria2+obfs, tuic, naive,
mieru) — но это **выходы**. Серверные (inbound) сущности в контракте нет.
Генератор `generators/singbox.py` уже рендерит inbounds (tproxy-перехват,
DNS-stub) — расширение того же списка, а не новая механика.

## Decision

`sing-box` (единственный маршрутизатор по ADR-0019) на профиле `panel` поднимает
**серверные инбаунды абонентов**. Трафик инбаундов входит в ту же таблицу
маршрутизации, что и трафик AWG-устройств; nftables по-прежнему только захват и
содержание.

Первый набор протоколов (слайс 1):

- **VLESS + Reality + XTLS-Vision** (TCP) — основной сценарий маскировки.
- **Hysteria2** (UDP, опционально с salamander-obfs) — сценарий потери пакетов/QUIC.

Trojan, TUIC, Shadowsocks и остальные — не отвергнуты, а отложены: каждый новый
тип = модель инбаунда + ветка генератора + валидатор + экспорт клиентской
ссылки, и они добавляются по enum без изменения архитектуры.

### Идентичность и маршрутизация

- Каждое **устройство** абонента может получить учётные данные инбаунда (UUID
  для VLESS, пароль для Hy2). Имя пользователя в sing-box детерминировано
  (`<subscriber>-<device>`-форма, строятся генератором из имён контракта).
- Правила маршрутизации определяют субъекта по `auth_user` (sing-box умеет
  матчить `auth_user` в route.rules — подтвердить на закреплённом бинарнике до
  реализации). Тема правила `RoutingSubject` расширяется этим соответствием;
  адрес-в-туннеле остаётся механизмом только для AWG.
- Выход трафика инбаундов — обычные `RoutingRule`/`Exit` (ADR-0029): прямое
  подключение, outbound, блок. Правило с недоступным выходом не откатывается
  молча на прямой интернет (ADR-0019).

### Порты и содержимое

- **Режим по умолчанию — 443 (Reality-fronting).** sing-box занимает 443 и
  терминирует VLESS+Reality; весь остальной TLS-трафик на 443 (не
  Reality-рукопожатие — включая браузер оператора с SNI панели и щупальца
  цензоров) Reality прозрачно пробрасывает на настоящий сайт-dest, которым
  служит **панель на Caddy, переведённая на loopback-порт**. Панель продолжает
  отвечать на 443 снаружи, ACME-продление по HTTP-01 не затронуто (порт 80
  остаётся у Caddy, правило `management_acme` уже обязано открываться
  генератором nftables).
- **Стоимость режима (принимается осознанно):** доступность панели зависит от
  живого sing-box. Обязательные ограждения: systemd `Restart=on-failure` с
  ускоренным перезапуском, probe панели при применении учитывает новый путь
  (упавший sing-box = недоступная панель, это отражается в статусе применения),
  rollback применяет предыдущий конфиг sing-box тем же путём, что и обычный.
- **Высокий порт — фолбэк.** Экспертная опция: выделенный порт вместо 443, для
  хостов, где 443 занят чем-то посторонним или оператор не хочет зависеть от
  sing-box в пути управления. По умолчанию не включается.
- Hysteria2 слушает выделенный UDP-порт всегда (UDP/443 не отдадим Caddy-пути).
- nftables-генератор открывает приём ровно тех портов, которые объявлены
  инбаундами конфигурации (TCP 443 в режиме fronting, UDP-порт Hy2); без
  инбаундов порты закрыты (fail-closed сохраняется), а 443-TCP остаётся
  за прежним владельцем — Caddy.
- Reality получает `handshake`-dest по умолчанию = публичное имя панели
  (`management.json`), чтобы неаутентифицированные щупальца видели настоящий
  сайт; оператор может переопределить.

### Данные и выдача клиентам

- Новый раздел контракта (набор моделей `inbounds` + учётные данные на
  устройстве). Секреты хранятся зашифрованными (`secrets.py`), из GET не
  возвращаются в открытом виде.
- Генератор I/O-free: секреты рендерятся `PLACEHOLDER_*`, подстановка — на
  применении (существующий механизм).
- Клиент получает готовую share-ссылку (`vless://…`, `hy2://…`) и QR в
  портале устройства — тот же путь, что Amnezia-экспорт (ADR-0022), плюс
  подписка (URL формата sing-box) как следующий слайс.

### Профиль и границы

- Инбаунды — только профиль `panel`: запись в `MODULE_PROFILES` в том же
  коммите (`router` конфигурацию с инбаундами отвергает — `profile.*` код).
- Системные footprint-требования из ADR-0021: всё, что ставит панель, снимается
  поимённо; новый юнит не появляется — работает закреплённый бинарник
  sing-box (`/usr/local/lib/vs-router/sing-box`), меняется только его конфиг.
- Удаление учётных данных устройства = отзыв доступа: при следующем применении
  юзер исчезает из конфига инбаунда.

## Rationale

- **Отдельные процессы на каждый протокол (xray, trojan-go, hysteria).**
  Отвергнуто: ещё N бинарников и юнитов на хосте, ADR-0019 назначил sing-box
  единственным движком, а он умеет все выбранные протоколы inbound'ами.
- **Выделенный высокий порт как единственный режим.** Отвергнуто: для клиента
  443 — самый безопасный порт (DPI блокирующих сетей доверяет ему по умолчанию,
  высокие порты режет или помечает). Вилка «два владельца одного порта» решается
  Reality-fronting: sing-box занимает 443, не-VLESS TLS пробрасывает в панель на
  loopback. Цену (панель зависит от живого sing-box) принимаем с ограждениями,
  а высокий порт оставляем фолбэком.
- **Сначала только VLESS+Reality.** Отвергнуто как слишком узко: Hy2 закрывает
  UDP/потери пакетов, которых TCP-протоколы не решают; вместе два протокола
  покрывают сценарии без роста архитектуры.
- **Идентичность по логину вместо адреса** — именно это ADR-0019 назвал ценой
  решения; принимаем её: учётные данные устройства, отзыв = удаление учётных
  данных, а не смена адреса.

## Consequences

- sing-box на панели впервые становится лицом наружу (сейчас он только
  перехват и выход). Проверки: закреплённый бинарник `sing-box check` на
  сгенерированном JSON с инбаундами — обязательный гейт; живая приёмка на
  одноразовой VM (подключение реального клиента vless/hy2).
- Правила маршрутизации для инбаунд-сессий тестируются иначе, чем AWG: субъект
  выводится из `auth_user`, а не из адреса — нужна фиксация соответствия
  «учётные данные ↔ устройство» как инварианта (аналог «адрес ↔ устройство»).
- Порт-факты хоста (какие порты слушает sing-box) появляются в записи управления
  — иначе панель показывает конфигурацию, которой на хосте нет.
- Подписки абонентов (фаза F) и инбаунды независимы: инбаунд не требует
  подписок и наоборот.
- ADR-0027 пункт 2 (`tunnel_*_forward`) по-прежнему ждёт движка sing-box — этот
  ADR ничего в нём не меняет.

## Реализация

Статус «предложен»; слайсы:

1. Контракт + валидаторы + генератор + golden + `sing-box check` закреплённым
   бинарником (VLESS+Reality, Hy2).
2. Применение: фаза генерации/установки конфига инбаундов, открытие портов в
   nftables, факт портов в записи управления.
3. Выдача клиентам: share-ссылки/QR в портале, отзыв при удалении устройства.
4. Подписка-URL как отдельный слайс после базовой выдачи.
