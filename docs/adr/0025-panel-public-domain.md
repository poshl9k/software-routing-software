# ADR-0025: Публикация панели по домену из самой панели

**Status:** предложен

**Date:** 2026-10-16

**Deciders:** пользователь, Hermes

## Context

ADR-0017 публикует панель на адресе аплинка (`<ip>.nip.io`) и прямо записывает:
**перенос самого endpoint (имя/адрес/порт) запрещён, а не реализован как
безопасная миграция**. То есть оператор, у которого есть собственный домен, не
может его указать — ни из панели, ни иначе.

Второе следствие того же ADR: после первого применения генерируемый набор
nftables закрывает всё, кроме 443/22, а `:80` нужен для HTTP-01 — без него
сертификат не выпустить и не продлить. Значит публикация по имени требует не
только смены записи управления, но и согласованного изменения firewall.

Наблюдаемые факты (эта сессия): панель на VPS работает по `https://<ip>.nip.io`
с сертификатом Let's Encrypt; `nft list ruleset` на живом хосте не содержит
правила для `:80`, потому что `management.hostname` в применённом наборе еще не
влиял на генератор.

## Decision

Панель публикуется по домену **из панели**, транзакционно:

- `PUT /api/host/panel-domain` — только администратор; тело `{hostname}` или
  `null`, имя проверяется контрактом управления (`HOSTNAME_PATTERN`).
  Агентский RPC — `set_panel_domain` (`PanelDomainParams`).
- **Разрешение до публикации**: имя, которое хост не может разрешить, отвергается
  (`management.domain_unresolved`) — по имени, которое не резолвится, ACME не
  выпустит сертификат, а публикация без сертификата равносильна потере доступа.
- **Согласованный firewall**: nftables пересобирается из применённой версии и
  **новой** записи управления, проверяется `nft -c -f` и загружается. При
  появлении имени открывается `:80` (`management_acme`) для HTTP-01, при снятии
  имени правило уходит.
- **Caddy перезапускается** (не reload): смена слушателя не гарантирует
  применения иначе; предварительно `caddy validate`.
- **Проверка результата**: имя должно ответить по HTTPS (до 60×2 с, проверка по
  системному хранилищу, не по локальному CA). Любая неудача — неразрешимое имя,
  отвергнутый Caddy конфиг, невыпущенный сертификат — **восстанавливает прежнюю
  запись и конфиг** и завершается `management.domain_unverified`. Плохой домен
  не может «отрезать» оператора от панели.
- `null` возвращает панель к адресу по IP с локальным CA.
- UI: «Обслуживание» → вкладка «Домен панели»; коды отказа объясняются
  человеческим текстом (`management.domain_unresolved` / `domain_unverified`),
  а не показываются как есть.

## Rationale

- **Разрешить миграцию endpoint только вручную/по SSH.** Отвергнуто: ADR-0017
  оставил это как незакрытое требование, а оператор с доменом остаётся без пути.
- **Сменить только запись управления, firewall оставить.** Отвергнуто: без `:80`
  сертификат не выпустится (а продление сломается позже, уже незаметно).
- **Применить изменение без проверки ответа.** Отвергнуто: единственная копия
  панели находится за этим же адресом; непроверенная публикация — потеря доступа.
- **Перезагрузка Caddy вместо перезапуска.** Отвергнуто: смена слушателя не
  гарантирует применения.

## Consequences

- Требование ADR-0017 «транзакционная миграция endpoint» закрыто для случая
  публичного имени; смена адреса IP по-прежнему не мигрируется.
- Публикация **перегенерирует живой firewall** из применённой конфигурации.
  Отсюда риск: если в применённой конфигурации нет интерфейсов SSH
  (`ssh.interfaces` пуст), пересобранный набор содержит `tcp dport 22 drop`, и
  доступ по SSH закроется. На живом хосте список `{ eth0, tun0 }` присутствует,
  поэтому там это безопасно; для конфигураций без SSH-интерфейсов это надо
  закрыть отдельно.
- Сертификат по имени выпускается ACME; приватный ключ CA не используется для
  публичного имени.
- Проверка публикации — изнутри хоста (panel probe). Внешняя проверка с другого
  клиента по-прежнему отдельный шаг, а не часть этого решения.

Связанные: ADR-0017 (single-uplink и онлайн-установка), ADR-0002 (первый LAN).
