# ADR-0031: Rule-set destinations in product routing rules

## Статус

Принят (2026-10-22). Реализация: схема, валидатор, генератор sing-box, мастер маршрутизации.

## Контекст

Каталог сервисов (`/api/presets/catalog`, порт из awg-manager) содержит наборы,
чья ценность — готовый rule-set (`.srs`/json), а не статический список доменов:
«Adult content (18+)» (`geosite-category-porn`), «Заблокировано в РФ»
(`geosite-rkn`), реклама (`geosite-category-ads-all`), «Недоступно из РФ» и др.
Продуктовая модель `RoutingRule` (ADR-0029) допускает только `ip_cidr`,
`domain_suffix`, `domain_exact`, поэтому эти сервисы недостижимы из мастера
маршрутизации. Кроме того, генератор sing-box никогда не отдаёт движку
декларации `route.rule_set`: матчеры, ссылающиеся на наборы, остались от
легаси-модели и не имеют источника определения — конфигурация с ними не прошла
бы проверку закреплённого движка.

## Решение

1. `RoutingRule.rule_sets: tuple[EngineTag, ...]` — четвёртое семейство
   назначения, равноправная альтернатива в дизъюнкции назначения (ADR-0029:
   списки — альтернативы). Правило только с наборами валидно.
2. Валидатор (`validate_routing`): каждый тег `rule.rule_sets` должен быть
   объявлен в `configuration.rule_sets` (`routing.ruleset_unavailable`).
   Объявленный источник, на который ссылается правило, обязан иметь формат,
   который движок принимает нативно (`srs`, `json`); текстовые форматы
   (`text-domain`, `text-cidr`, `geosite`, `geoip`) требуют материализации
   агентом, которая не реализована, и ссылка на них отклоняется
   (`routing.ruleset_format`), а не молча не совпадает.
3. Генератор sing-box: (а) семейство `rule_set` входит в дизъюнкцию назначения
   наравне с `ip_cidr`/`domain_suffix`/`domain_exact`; (б) `generate_singbox`
   отдаёт `route.rule_set` — декларации `{"type": "remote", "tag", "format",
   "url"}` для объединения тегов, на которые ссылаются продуктовые правила и
   легаси-правила TProxy (`srs` → `binary`, `json` → `source`); (в) условие
   системного `sniff` учитывает продуктовые правила с доменными и rule-set
   назначениями — матчинг по домену без sniff не срабатывает (ADR-0020).
4. Мастер маршрутизации: плитка сервиса с rule-set выбирается в «Что
   маршрутизировать» наравне с доменными сервисами; при сохранении черновика
   объявленные источники выбранных наборов дописываются в
   `configuration.rule_sets` (additive; уже объявленные источники не удаляются
   и не перезаписываются — ими управляет вкладка «Источники списков»).
5. Выход правила остаётся выбором оператора: каталог подсказывает действие
   (`action`), но не задаёт исходящий путь — «18+» и RKN по умолчанию имеют
   смысл туннеля, реклама — блокировки; это подсказка UI, не контракт.

## Не входит

- Материализация текстовых источников (text-domain/text-cidr) в rule-set.
- Подписочные наборы (`subscriptionUrl` в каталоге) — отдельный механизм.
- Автообновление деклараций при смене версии списка — уже существует
  (агент, расписание источников).
