# ADR-0007: Независимые проверяемые версии внешних наборов TProxy

**Статус:** принят (решение, реализация ожидается)
**Дата:** 2026-10-02
**Участники:** владелец продукта и Hermes Agent

## Контекст

Списки доменов, IP, geoip и geosite меняются быстрее выпуска приложения и общей конфигурации роутера. Полный черновик → применение → подтверждение при каждом обновлении лишил бы расписание смысла; загрузка новейшего списка прямо в работающий процесс может сломать маршрутизацию или незаметно изменить её из-за повреждения источника. У нас уже есть целые конфигурационные snapshots и безопасный apply/rollback, которые нельзя обходить неограниченным сторонним кодом.

## Решение

Состав правил, разрешённые источники и расписание входят в общую конфигурацию и меняются через обычный черновик и применение. Содержимое уже выбранных внешних наборов является отдельно версионируемым операционным состоянием: скачать → проверить/скомпилировать → проверить итоговую конфигурацию → атомарно заменить рабочую версию → проверить готовность. Ошибка любого шага оставляет или восстанавливает последнюю рабочую версию. История, происхождение и ручной откат набора видны администратору. Автоматические и ручные обновления не выполняются одновременно с общим apply/rollback; последнее подтверждённое состояние однозначно ссылается на используемые идентификаторы источников, а не случайные пути файлов. Расписание: выбираемый периодический режим (по умолчанию 6 часов) либо один запуск в суточном окне (исходно 00:00–05:00 по времени сервера); ручная проверка доступна всегда.

## Рассмотренные варианты

- Включать каждый новый список в полную конфигурационную версию: единый журнал изменений, но частые обновления требуют ручных подтверждений и создают риск конфликта с черновиком администратора.
- Отдавать обновления непосредственно sing-box из плавающего URL: просто, но сложнее проверять целостность, диагностировать смену содержимого и возвращать рабочую версию при сбое.
- Независимые проверенные версии с сериализованной активацией: выбранный компромисс между скоростью обновлений и контролем изменений.

## Последствия

Нужны ограниченный загрузчик, проверка формата/размера/источника, атомарный указатель на рабочую версию, журнал и правила хранения. Восстановление после reboot или отката общей конфигурации обязано разрешать только существующие проверенные наборы и не подменять ссылки новейшими без проверки. Отказ загрузки не должен отключать работающий прокси. Сторонние данные не равны проверенному выпуску бинарника из ADR-0005; обновление самого sing-box остаётся привязанным к выпуску. Вопрос лицензий и перераспространения содержимого каждого источника проверяется до упаковки данных в продукт.
