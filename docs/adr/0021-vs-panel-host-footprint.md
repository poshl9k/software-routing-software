# ADR-0021: Границы владения хостом и автоматизация установки `vs-panel`

**Status:** предложен

**Date:** 2026-10-16

**Deciders:** пользователь, Hermes

## Context

Сегодняшний продукт владеет хостом целиком: файлы `networkd` с привязкой по MAC,
nftables, Kea, Unbound, SSH, а политика по умолчанию — fail-closed
(«интерфейс не назначен → дропаем всё»). На роутере это оправдано: рядом есть
локальная консоль и LAN.

На VPS это же поведение неприемлемо, и это проверено на практике: в этой сессии
доступ по SSH терялся дважды — один раз из-за drop-in для `sshd` с условием на
`/run`-маркер, другой раз из-за таблицы, закрывающей порт 22, которую агент
поднимал до появления записи управления. Оба раза восстанавливать приходилось
через консоль провайдера.

Дополнительный аргумент — стоимость поддержки двух дистрибутивов: на Ubuntu
сетевая конфигурация описывается netplan, который рендерит `networkd`. Владея
адресами, продукт обязан поддерживать netplan, `systemd-networkd` и
ifupdown-совместимость.

## Decision

`vs-panel` владеет только **своей зоной** на хосте: собственная таблица
nftables (захват, анти-утечка, kill-switch), собственные правила маршрутизации с
собственной меткой и собственная таблица маршрутов, собственные службы.

Он **не** владеет адресами интерфейсов, маршрутом по умолчанию, системным DNS и
SSH. **Маршрут по умолчанию хоста панель не заменяет никогда** — он принадлежит
провайдеру и оператору.

Из профиля не ставятся: Kea/DHCP, `networkd`-файлы и выдача адресов, валидация
management-LAN, консольное меню, ISO-установщик.

Установка — по сети, автоматическая: зависимости, сборка, юниты, первый
провизионинг, публикация панели по HTTPS с настоящим сертификатом, самопроверка
по итогу (панель отвечает снаружи, `sshd` активен, порт 22 слушает, таблиц
fail-closed нет) и идемпотентность повторного запуска.

Обновления — **не молчаливые**: панель сама проверяет и скачивает выпуск,
проверяет подпись и пин версии, показывает его администратору; применение — по
подтверждению или в окно обслуживания, с автоматическим откатом, если после
обновления панель или SSH недоступны.

Поддерживаемые системы: Debian 13 и Ubuntu LTS.

## Rationale

- **Полное владение хостом, как у роутера.** Отвергнуто: на машине без локальной
  консоли это класс необратимых отказов, уже реализованный дважды.
- **Только службы, без firewall и маршрутов вообще.** Отвергнуто: без захвата
  трафика из туннеля маршрутизация `sing-box` не работает, а без анти-утечки
  мёртвый выход выпускает трафик напрямую (ADR-0019).
- **Полностью автоматические обновления без подтверждения.** Отвергнуто: на VPS
  нет второго пути внутрь, поэтому «обновились и не заметили» становится
  необратимым. Не-молчаливое обновление с автооткатом даёт автоматизацию без
  этой цены.
- **Шире, чем LTS.** Отвергнуто: промежуточные релизы дают разъезжающиеся версии
  systemd и OpenSSL без выгоды для эксплуатации.

## Consequences

- Всё, что ставит панель, она обязана уметь снять поимённо: идемпотентность и
  откат — не пожелание, а требование к установщику.
- Различия дистрибутивов изолируются в тонкий слой «пакеты и способ поставить
  службу»; логика панели от дистрибутива не зависит.
- Появляется обязанность CI: прогон установки на чистых машинах Debian 13 и
  Ubuntu LTS, потому что проверка на одной системе не доказывает вторую.
- Отсутствие Kea означает, что панель не раздаёт адреса; маленькая сеть за VPS —
  это профиль `vs-router`, а не расширение панели.
