# ADR-0017: Режим одного аплинка (VPS) и онлайн-установка

**Статус:** предложен (ожидает подтверждения модели публикации и привязки адреса)
**Дата:** 2026-10-15
**Участники:** владелец продукта и Hermes Agent

## Контекст

Роутер задумывался как устройство с отдельным physical LAN-портом: ADR-0002
требует явно назначенный LAN, `management.verify_identity`/`Console.provision`
требуют **≥2 проводных порта** и маркеров ISO-пути
(`/var/lib/vs-router-bootstrap/installer-uplink`, `/etc/vs-router/networkd-manifest.conf`),
а `bootstrap.sh` рассчитан на DHCP-аплинк из ISO и **маскирует SSH**.

Продукт должен также работать на VPS с **одним** сетевым интерфейсом и
ставиться **поверх SSH** (онлайн), без ISO и без локальной консоли. Проверка на
реальном VPS (`92.51.36.131`, Debian 13 cloud): один `eth0`, адрес по DHCP,
1 vCPU / ~1 ГБ RAM. Текущий код там не провизионится
(`management.separate_wired_port_required`).

## Решение (предлагаемое)

1. **Режим management.** Добавить в `Management` поле `mode`:
   `separate-lan` (как сейчас) | `single-uplink` (VPS). В `single-uplink`:
   - управляющий интерфейс — это **аплинк** (зона `wan`), отдельного LAN-порта нет;
   - `verify_identity` проверяет MAC существующего порта (не требует ≥2 портов);
   - `Console.provision` для `single-uplink` не требует `installer-uplink`
     и `networkd-manifest.conf`: запись создаётся онлайн-установщиком.
2. **Адрес панели.** Панель публикуется на адресе аплинка, порт **443** через Caddy
   с локальным CA (`generate_caddy_json` уже принимает `management`). Адрес
   закрепляется по MAC; при DHCP-адресе запись хранит текущий lease-адрес, и при
   смене адреса boot-restore/агент пересобирают listener и правила
   (`management.address_changed` — явная диагностика, а не тихий сдвиг).
3. **Firewall.** Явный, opt-in флаг публикации панели: разрешить `tcp/443` на
   аплинке, **сохранить SSH** (порт 22 не маскировать и не закрывать) и оставить
   default-deny на остальное. Первый apply обязан сохранять доступ к панели и SSH
   (HTTPS-probe входит в условия, ADR-0003).
4. **Онлайн-установщик** `backend/packaging/online-install.sh` (Debian 13, по SSH,
   идемпотентный, с `--dry-run`):
   - не маскирует SSH, не требует `installer-uplink`;
   - сам определяет аплинк (`ip route`), режим адреса (DHCP/static) и Python 3.13;
   - ставит зависимости, собирает `wg-go`/`amneziawg`/`caddy`, UI+wheel, `install.sh`;
   - создаёт management-запись в режиме `single-uplink` **без TTY**;
   - ставит firewall-правила (443 + SSH), включает сервисы, печатает проверки.
5. **Совместимость.** Режим `separate-lan` и ISO-путь не меняются; `single-uplink`
   включается явно (флаг установщика / `--single-uplink`), по умолчанию — как сейчас.

## Открытые решения (нужно подтверждение)

- **D1. Публикация.** Панель на публичном `IP:443` (с локальным CA, allow tcp/443)
  **или** только через SSH-туннель к loopback? Предлагается: публичный 443 + SSH,
  с возможностью выключить публикацию.
- **D2. DHCP-адрес.** Требовать **статический** адрес у провайдера (панель
  прибита к адресу) **или** поддерживать DHCP с перепривязкой по MAC (сложнее:
  нужен hook на смену lease и пересборка правил)? Предлагается: поддерживать оба,
  но статический — рекомендованный.

## Последствия

- Появляется второй профиль развёртывания (VPS/один порт) с менее строгой, но всё
  ещё явной моделью доступа; ADR-0002/0003 остаются в силе для `separate-lan`.
- Требуется расширить `Management`, `validate_management`, `management_console`,
  генерацию firewall и boot-restore; покрыть тестами и проверить на реальном VPS.
- RAM VPS ниже минимума доки: без swap сборки Caddy/AWG/npm могут падать —
  установщик должен это проверять и сообщать.

Связанные: ADR-0002 (первичный LAN), ADR-0003 (безопасность первого apply),
ADR-0004 (SSH по интерфейсам), ADR-0005 (пиннинг выпуска).
