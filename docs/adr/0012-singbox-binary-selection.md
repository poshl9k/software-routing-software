# ADR-0012: Закреплённый бинарник sing-box — официальный `SagerNet/sing-box` v1.14.2, AWG-выходы через интерфейсы vs-router

**Статус:** принят
**Дата:** 2026-10-07
**Участники:** владелец продукта и Hermes Agent

## Контекст

План `docs/sing-box-tproxy-plan.md` требует закрепить совместимый бинарник
sing-box по правилам ADR-0005 (проверенный набор версий, фиксированный артефакт,
проверяемая загрузка, отсутствие `latest` и плавающих зависимостей). Исходный
проект-образец `hoaxisr/awg-manager` закрепляет **форк** `hoaxisr/amnezia-box`
`1.15.0-alpha.9-awgm.30`, который добавляет собственный outbound `type: awg`
для AmneziaWG внутри sing-box. Однако карта бинарников этого форка содержит
только `mipsel`/`mips`/`aarch64` — **сборки под `linux/amd64` upstream нет**;
адреса загрузки форка — HTTP со встроенным в код SHA256. Нельзя ни объявить
готовый проверенный amd64-бинарник, ни перенести хеш другой архитектуры.

Проверенная ранее (только как тестовый артефакт, не как выбор) альтернатива —
официальный `SagerNet/sing-box` v1.14.2 `linux/amd64`, чей сгенерированный конфиг
с IPv4 TCP/UDP TProxy прошёл `sing-box check` и ограниченную пакетную пробу на
одноразовой Debian 13 VM (`docs/lab-05-singbox-tproxy.md`), а сам бинарник
использовался в пробах lab-08/09/24/26.

AmneziaWG (AWG) уже реализован в продукте как системный интерфейс: vs-router
сам управляет WG/AWG-интерфейсами. Отсутствие `type: awg` в официальном
sing-box не мешает отправлять выбранный трафик через уже существующий
WG/AWG-интерфейс роутера.

## Решение

**Продуктовый бинарник TProxy — официальный `SagerNet/sing-box` v1.14.2,
`linux/amd64`, из ассета GitHub Release** (теги сборки включают
`with_wireguard`, `with_quic`, `with_gvisor`, `with_dhcp`, `with_clash_api` и
др.; тега `with_awg` нет). AWG-выходы обеспечиваются **существующими
WG/AWG-интерфейсами vs-router**, а не форковым outbound `type: awg`. Форк
`hoaxisr/amnezia-box` **не берём**: у него нет amd64-сборки upstream, а его
`type: awg` и форковые поля в официальный sing-box не переносятся.

Закрепляемый артефакт (проверено фактически, см. ниже):

- Репозиторий/тег: `SagerNet/sing-box`, тег `v1.14.2` (релиз опубликован
  2026-09-24T11:47:08Z).
- Ассет: `sing-box-1.14.2-linux-amd64.tar.gz`.
- URL:
  `https://github.com/SagerNet/sing-box/releases/download/v1.14.2/sing-box-1.14.2-linux-amd64.tar.gz`
- Размер: `31 680 686` байт.
- SHA256:
  `a684484d7477d1437282ee411f4d131d0340aaad60a7868841ebd5d87dd8a0c6`.
- Внутри архива: `sing-box` (ELF x86-64, stripped, 81 297 637 байт),
  `libcronet.so`, `LICENSE` (GPL-3.0-or-later).
- `sing-box version` → `1.14.2`, `go1.26.8 linux/amd64`, `CGO: disabled`;
  `Revision: af6e64c3b69e6132ebaee0e1a3d24e93903f6709`.

**Доверие к артефакту строится на трёх независимых опорах** (ADR-0005):

1. **HTTPS + SHA256.** Хеш скачанного архива сверяется с опубликованным
   значением. Отдельного ассета `SHA256SUMS` в релизе нет; опубликованный
   дайджест доступен через GitHub API (`.assets[].digest` =
   `sha256:a684484d…a0c6`) и через манифест выпуска.
2. **Подпись через sigstore (GitHub artifact attestations).** Для этого blob
   существует **проверяемая** аттестация: `gh attestation verify
   sing-box-1.14.2-linux-amd64.tar.gz --repo SagerNet/sing-box` возвращает
   **успех (exit 0)**. Проверено: предикат `https://slsa.dev/provenance/v1`,
   сертификат Fulcio с идентификатором
   `https://github.com/SagerNet/sing-box/.github/workflows/build.yml@refs/heads/stable`
   и издателем `https://token.actions.githubusercontent.com` (GitHub Actions
   OIDC). Это доказывает, что артефакт собран workflow `build.yml` из ветки
   `stable` репозитория SagerNet из коммита
   `af6e64c3b69e6132ebaee0e1a3d24e93903f6709`. Дополнительно GitHub публикует
   release-аттестацию (`https://in-toto.io/attestation/release/v0.2`).
   Отдельных отсоединённых файлов подписи (`.sig`/`.pem`/`.asc`/`.gpg`) или
   `cosign`-блоба в ассетах **нет** — подпись существует только в форме
   GitHub-аттестаций.
3. **Фиксация по тегу и коммиту.** Закрепляются точный тег `v1.14.2` и
   провенанс-коммит `af6e64c3…`; `latest` и ветки не используются.

**Стратегия обновления.** Смена версии sing-box — отдельный проверенный выпуск
по ADR-0005: скачать новый архbив → сверить SHA256 с опубликованным → проверить
sigstore-аттестацию → исполнять пробную матрицу протоколов → закрепить в
манифесте выпуска новый URL/тег/SHA256/коммит. Хеш берётся только из
опубликованного дайджеста релиза; хеши других архитектур переносить нельзя.

**Если подписи/аттестации окажутся недоступны** (нет сети до Fulcio/GitHub,
аттестация отсутствует у нового релиза): закрепление **не отменяется молча**.
Полномочие доверия понижается до HTTPS + SHA256, и это явно документируется как
ограничение в манифесте выпуска; для версии с обязательной проверкой подписи
релиз не подтверждается, пока аттестация не проверена.

## Рассмотренные варианты

- **Форк `hoaxisr/amnezia-box` с `type: awg`:** даёт AWG-выход внутри sing-box
  без внешнего интерфейса, но amd64-сборки upstream нет, доставка идёт по HTTP
  со встроенным хешем. Отвергнуто.
- **Официальный sing-box + существующие WG/AWG-интерфейсы vs-router (принято):**
  есть amd64-артефакт, sigstore-аттестация и совместимость с уже управляемыми
  интерфейсами; AWG не дублируется внутри движка.
- **Собрать amd64-бинарник форка самостоятельно:** требует владения тулчейном
  и fork-специфичным кодом, воспроизводимость и происхождение слабее, чем у
  официального GitHub-релиза с аттестацией. Отвергнуто для продуктовой поставки.

## Последствия

- В продуктовом дереве и в манифесте выпуска фиксируются **точный URL, тег,
  SHA256 и провенанс-коммит** этого ассета; проверка целостности — всегда.
- Проверка подписи — через GitHub artifact attestation (`gh attestation verify`
  либо эквивалент Sigstore); если проверяющий инструмент недоступен, доверие
  понижается до HTTPS + SHA256 и это обозначается как ограничение, а не
  выдаётся за проверенную подпись.
- Обновление sing-box не «следит за `latest`»: оно идёт через новый проверенный
  выпуск (ADR-0005/0010) с перепроверкой SHA256, аттестации и матрицы
  протоколов. Rule-set'ы и подписки обновляются независимо от этого (ADR-0007).
- AWG-выходы реализуются как маршрутизация в уже существующий WG/AWG-интерфейс
  vs-router; форковые `awg`-поля в конфиг не вносятся, что снимает вопрос
  совместимости форка.
- Лицензия бинарника — GPL-3.0-or-later (copyright nekohasekai); при
  распространении в составе продукта это обязательство учитывается (ср.
  ADR-0007 по правам на переупаковку содержимого).
- **Вне этого решения:** открытие публичного gate `tproxy.not_available`,
  реализация перехвата/apply/boot и матрица протоколов — это отдельные условия
  из `docs/sing-box-tproxy-plan.md` и не подтверждаются ни фактом закрепления
  бинарника, ни его аттестацией.

### Фактическая проверка (выполнена 2026-10-07, артефакт вне репозитория)

- Скачан ассет по URL выше; `sha256sum` дал `a684484d…a0c6`, совпав с
  `.assets[].digest` GitHub API и с ожидаемым значением.
- `gh attestation verify sing-box-1.14.2-linux-amd64.tar.gz --repo
  SagerNet/sing-box` → exit 0; предикат `https://slsa.dev/provenance/v1`,
  issuer `https://token.actions.githubusercontent.com`, SAN
  `…/build.yml@refs/heads/stable`.
- `sing-box version` → `1.14.2`, `linux/amd64`, `Revision:
  af6e64c3b69e6132ebaee0e1a3d24e93903f6709`; в тегах есть `with_wireguard`,
  нет `with_awg`.

### Зафиксировано как ограничение

- У релиза **нет** отдельного файла `SHA256SUMS` и **нет** отсоединённых
  `.sig`/`.pem`/`.asc`/`.gpg` — подпись существует только как GitHub
  artifact attestation (sigstore). Проверка требует доступа к GitHub API и
  доверия публичному Sigstore/Fulcio; в полностью офлайн-сценарии доступна
  только сверка SHA256.
- Аттестация подтверждает происхождение сборки (репозиторий/workflow/коммит),
  но не является гарантией отсутствия уязвимостей или корректности кода.
- Факт закрепления бинарника **не** является доказательством готовности
  TProxy: gate остаётся закрытым.
