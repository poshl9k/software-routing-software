# ADR-0030: Маршрут по умолчанию клиентского туннеля — только явное согласие

**Status:** реализован в исходном коде и тестах; проверка на живой машине — нет
**Date:** 2026-10-22
**Deciders:** пользователь, Hermes

## Context

`AllowedIPs = 0.0.0.0/0, ::/0` в импортированном клиентском WG/AWG-профиле означает, что пир принимает трафик всех адресов. До этого решения генератор также автоматически ставил из этих значений маршруты по умолчанию хоста с метрикой 100. На машине с панелью за NAT маршрут может перехватить путь к самой панели, SSH, DNS и endpoint туннеля до завершения handshake. Потеря управления VPS без локальной консоли требует восстановления через консоль провайдера. Криптографический фильтр пира и маршрут хоста — разные вещи (CONTEXT.md, «AllowedIPs ≠ маршрут»). Для `vs-panel` это узкое явное исключение из общего правила ADR-0021/CONTEXT.md: маршрут по умолчанию обычно принадлежит провайдеру, а не панели.

## Decision

1. `Tunnel.default_route: bool = False` означает только для туннеля-клиента согласие на установку маршрутов хоста `0.0.0.0/0` и/или `::/0`, если соответствующие сети есть в его `allowed_ips`. Старый документ без поля читается как `False`. На туннель-сервер и маршруты его пиров флаг не влияет.
2. При `False` обе сети по умолчанию исключаются только из `manifest.json.routes`; все не-default сети (например, `10.8.1.0/24`) остаются. Содержимое `AllowedIPs` в `.conf` не меняется в обоих режимах. При `True` маршруты по умолчанию снова включаются в manifest, как до этого решения. Адаптер применяет их через `ip route replace ... dev <интерфейс> metric 100` и удаляет прежние маршруты при выключении флага; отсутствие уже удалённого маршрута не делает применение неуспешным, остальные ошибки остаются ошибками.
3. Режим «весь трафик через туннель» в UI требует отдельной явно включённой галочки (не выводится автоматически из `AllowedIPs`) и предупреждения: может пропасть доступ к панели/SSH и самому endpoint. Галочка «Использовать туннель как маршрут по умолчанию» и предупреждение реализованы в форме туннеля (`frontend/src/pages/ConnectionEditors.tsx`), выключены по умолчанию и сохраняются в документе явным `true`/`false`. Без явного согласия маршрут хоста по умолчанию не изменяется.
4. Не расширять право панели на адресацию аплинка, SSH или произвольные маршруты: исключение действует только на default-маршруты собственного клиентского туннеля после явного выбора оператора. Без безопасного пути восстановления этот режим рискован даже при подтверждении.

## Rationale

Сохранение полного `AllowedIPs` позволяет использовать импортированные профили без потери контракта WireGuard, а opt-in не забирает управление у провайдера при обычном импорте. Отдельное поле делает опасный переход видимым в сохранённой конфигурации и обратимым при применении предыдущей версии.

## Рассмотренные варианты

- **Ставить default-маршрут автоматически из `AllowedIPs`.** Отвергнуто: дефолтный импорт может перехватить управление до handshake.
- **Удалять default из `.conf`.** Отвергнуто: изменяет криптографический контракт с пиром и ломает ожидаемый полный туннель даже при явном включении.
- **Игнорировать все ошибки удаления маршрута.** Отвергнуто: ошибка прав или сломанный интерфейс оставила бы хост в непроверенном состоянии.

## Consequences

- Старые документы со списком default `AllowedIPs` после обновления больше не устанавливают default-маршрут хоста до явного включения `default_route`. Это намеренная смена поведения, а не прозрачная миграция; данные хранятся в JSON-конфигурации без новой колонки БД.
- Тесты без root/сети проверяют JSON старого документа, оба семейства адресов, `.conf`, серверные маршруты, переходы адаптера и повтор применения после `rollback_failed`. Они не доказывают доступность панели/SSH, порядок реальных маршрутов, NAT или восстановление после reboot.
- Живая проверка после выката выполнена на VPS rg4 (панель, Debian 13, `ens192` под ifupdown): документ со старым `AllowedIPs = 0.0.0.0/0, ::/0` и БЕЗ поля `default_route` применён успешно, маршруты хоста туннеля в манифесте — `[]`, `.conf` сохранил `AllowedIPs = 0.0.0.0/0, ::/0`, `default via 10.15.15.1 dev ens192` уцелел, туннель поднялся и handshake прошёл. Не проверено вживую: включение режима «весь трафик через туннель» (`default_route = true`), откат на живом хосте и поведение после перезагрузки — для этого нужен отдельный прогон на одноразовой Debian 13 VM.
- Frontend-галочка и предупреждение поставлены вместе с backend; до их поставки режим включался только через API-документ, и оператор не видел предупреждения в форме.
