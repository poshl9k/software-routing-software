# ADR-0004: SSH по выбранным интерфейсам с условным парольным доступом из WAN

**Статус:** принят
**Дата:** 2026-10-01
**Участники:** владелец продукта и Hermes Agent

## Контекст

Образ устанавливает SSH ещё до первого применения правил роутера. Интерфейс установщика получает сетевой адрес, а системной учётной записи выдавалось `sudo NOPASSWD`; в автоматическом режиме пароль был известен заранее. Администратору нужен контроль SSH из панели, в том числе возможность использовать пароль на WAN.

## Решение

В обычной установке системный пароль выбирает администратор, а `sudo` требует его повторного ввода. До явного разрешения SSH недоступен на интерфейсе установки. В web UI доступ включается по конкретным интерфейсам, не по зонам; исходно список пуст. Включение, выключение и смена интерфейсов участвуют в общем применении конфигурации и его откате. Парольный вход на явно выбранном WAN допускается, но только при действующей защите от перебора и отдельном подтверждении риска в UI. Лабораторная автоматическая установка отделена от обычной и выбирается явно.

## Рассмотренные варианты

- Открывать SSH на интерфейсе установки: упрощает удалённое обслуживание, но выставляет сервис до настройки доступа.
- Разрешать SSH только по ключам на WAN: снижает риск перебора, но не отвечает выбранному сценарию администратора.
- Разрешать пароль на WAN без дополнительных ограничений: проще, но повышает риск подбора. Принят вариант с явным выбором и обязательной защитой.

## Последствия

Изменения доступа к SSH должны быть согласованы с сетевыми правилами и откатом. Если защита от перебора отсутствует или не работает, парольный SSH на WAN не включается. До настройки SSH обслуживание обычной установки требует локальной консоли. Известный пароль и `NOPASSWD` недопустимы на пути обычной установки.
