# ADR-0024: Туннель AWG создаётся с полным профилем обфускации и не на дефолтном порту

**Status:** предложен

**Date:** 2026-10-16

**Deciders:** пользователь, Hermes

## Context

ADR-0016 вынес за скобки генерацию полного набора AWG 3 для серверных туннелей,
создаваемых в панели, и оставил keygen на классическом ядре
(`Jc/Jmin/Jmax/S1/S2/H1–H4`) — «чтобы не менять поведение». Следствие
обнаружилось на живом клиенте: приложение Amnezia оценило выданный конфиг как
**«Базовая обфускация» (35/100)** — `Header protection: выключен`, `CPS: нет`,
и отдельно предложило **сменить порт сервера с 51820/51821**: порт по умолчанию
сам является отпечатком.

То есть панель, обещающая обфускацию, по умолчанию выпускала конфиг, который
инструмент самой Amnezia называет базовым.

## Decision

`POST /keygen/tunnel` для `protocol=awg` возвращает **полный профиль AWG 3+**,
а не только ключи:

- `S3`/`S4` (паддинги cookie/transport), `Jc`, `Jmin`, `Jmax`;
- `I1`–`I5` — сигнатурные пакеты (грамматика тегов `amneziawg-go`);
- `HeaderProtectionKey` (32 случайных байта, base64);
- `ContentPaddingAddition`, `RekeyAfterTime`, `RekeyTimeout`, `RejectAfterTime`,
  `KeepaliveTimeout`, `MaxHandshakeAttempts` — диапазонами `min-max`;
- `RandomTrailers` и `DisableCookies` включены.

Все значения **случайны на каждый туннель**: два сервера не должны иметь общий
отпечаток — в этом смысл протокола. `S1–S4 ≥ 12` обязательно: header protection
по документации требует этого минимума.

Порт серверного туннеля выбирается случайно в `20000–60000`, исключая
`51820`/`51821`, и возвращается как `listen_port`.

## Rationale

- **Оставить классическое ядро.** Отвергнуто: это и есть дефолт, который
  демаскирует AWG под DPI, а инструмент Amnezia называет его базовым.
- **Фиксированные «красивые» значения (как в собственном экспорте приложения:
  `Jc=5`, `S1=28`, `H1..H4=1..4`).** Отвергнуто: одинаковая обфускация у всех
  установок — приглашение к обнаружению; значения случайны в документированных
  диапазонах.
- **`I1`–`I5` не генерировать** (в экспорте приложения они пусты). Отвергнуто:
  это доступная часть протокола, и по документации они не обязаны совпадать на
  сторонах. Синтаксис проверен живым `awg setconf` до включения.
- **Оставить порт 51820.** Отвергнуто: рекомендация приходит от самой Amnezia.
- **Сделать полный набор обязательным в схеме для `awg`.** Отвергнуто сейчас:
  это отвергло бы уже применённый живой туннель. `AWG_CORE` не меняется;
  требование к полноте профиля — предмет отдельного решения.

## Consequences

- Новый туннель AWG сразу проходит как «продвинутая» обфускация: header
  protection включён, CPS есть, порт нестандартный.
- Профиль проверен на живом хосте: сгенерированный набор, включая `I1`–`I5` и
  `HeaderProtectionKey`, принят `awg setconf` версии **v3.1.20260812** и прочитан
  обратно дословно (`setconf rc=0`).
- Фронт применяет ответ keygen целиком (кнопка «Сгенерировать ключи» и создание
  туннеля), поэтому ручная правка полей обфускации остаётся доступной, но не
  обязательной.
- Уже созданные туннели не меняются: профиль генерируется при создании и при
  явной регенерации ключей.
- `I1`–`I5` попадают и в серверный конфиг устройства: по документации это
  допустимо (сигнатуры «client-side», совпадение не требуется).
