# ADR-0009: Явный режим адресации интерфейса вместо эвристики DHCP

**Статус:** принят
**Дата:** 2026-10-06
**Участники:** владелец продукта и Hermes Agent

## Контекст

DHCP был неявным: `generate_networkd` включал `DHCP=ipv4` только для
интерфейса `physical` в зоне `wan` без статических адресов. Это ломает реальный
сценарий: WAN может приходить в **VLAN** (несколько провайдеров) или в мост, а
правило по типу/зоне этого не выражает. Панель при этом показывала «—» вместо
«DHCP», и было непонятно, как задать получение адреса. Отдельно: сгенерированный
firewall **не разрешал** DHCP-ответы (в отличие от пред-apply `bootstrap.nft`),
то есть продление аренды WAN после первого apply не гарантировалось. Наконец,
потребность «в теории использовать и внешний DHCP на LAN» делает неявное
правило ещё и неоднозначным: из зоны больше нельзя вывести, кому DHCP разрешён.

## Решение

Режим адресации становится **явным полем интерфейса**:
`addressing: "static" | "dhcp"` (по умолчанию `static`). `dhcp` разрешён для
интерфейса **любого типа и зоны**, кроме структурно несовместимых случаев.

Запрещено (код ошибки):
- `management.dhcp_forbidden` — управляющий LAN (endpoint закреплён статически);
- `dhcp.client_conflict` — интерфейс с подсетью Kea (сервер одновременно и клиент);
- `interface.dhcp_on_member` — участник моста;
- `interface.dhcp_on_trunk` — транк-родитель с VLAN-детьми;
- `interface.dhcp_with_addresses` — DHCP вместе со статическими адресами;
- `interface.dhcp_unassigned` — DHCP на интерфейсе без зоны.

Сгенерированный firewall разрешает DHCP-ответы на всех интерфейсах-клиентах
(`udp sport 67 udp dport 68`) **до** проверок conntrack. Разовая миграция данных
помечает существующие безlадресные WAN-интерфейсы как `dhcp`. Панель в редакторе
даёт селектор режима, а в просмотре показывает **фактически полученный** адрес
(новый read-only контур агент → API → UI).

## Рассмотренные варианты

- **Расширить неявное правило** (без изменения схемы): дешевле, но
  «нет адресов = DHCP» после снятия ограничения по зоне начинает срабатывать
  молча везде, а UI не может честно показать/выбрать режим. Отвергнуто.
- **Явное поле `addressing`** (принято): устраняет неоднозначность, даёт дом для
  внешнего DHCP и будущего мульти-WAN, делает режим видимым и проверяемым.
- **Оставить DHCP только для зоны `wan`**: отвергнуто — нужен внешний DHCP и на
  LAN; ограничение зоной выражало не задачу, а прежнюю реализацию.

## Последствия

- Схема получила поле (default `static`); `schema_version` остаётся `1`, миграция
  `0003` проставляет `dhcp` безlадресным WAN — поведение существующих установок
  не меняется.
- Появляются валидации режима и правило firewall; тесты/golden обновлены.
- Firewall-правило заодно устраняет дефект продления аренды WAN (P0).
- «Второй WAN и переключение» остаются после MVP, но зафиксированы в плане как
  явные работы; этот ADR — их фундамент, а не их реализация.
- DHCPv4 only: IPv6 RA/SLAAC не входят.
