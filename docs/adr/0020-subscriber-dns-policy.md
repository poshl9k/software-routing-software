# ADR-0020: DNS абонентов в `vs-panel` и режим «свой DNS»

**Status:** предложен

**Date:** 2026-10-16

**Deciders:** пользователь, Hermes

## Context

Правила маршрутизации по домену требуют, чтобы маршрутизатор видел DNS-запрос:
домен не равен адресу, и один CDN-адрес обслуживает множество сайтов. Значит
`vs-panel` обязан быть resolver'ом своих абонентов — иначе «выборочная
маршрутизация по сайтам» не реализуется, а по адресам бесполезна на практике.

Против этого есть реальный сценарий: у абонента есть **внутренний DNS** с
локальными именами (офисная зона, домашние имена, Split-DNS). Панель этот
resolver запросить не может: он доступен только из локальной сети абонента, а
панель в ней не находится. Попытка «условного форвардинга» таких зон на сторону
панели — самообман, при котором внутренние имена ломаются молча.

## Decision

Resolver абонентов — это `vs-panel`, и он является DNS по умолчанию у устройств,
для которых нужны доменные правила.

Устройству доступен режим **«свой DNS»**: в его конфигурацию попадают resolver'ы
абонента, доменные правила к такому устройству **не применяются** (маршрутизация
только по адресам), а локальная сеть абонента **выводится из туннеля** списком
исключений в `AllowedIPs`.

Панель не форвардит запросы к зонам, до которых у неё нет маршрута, и не
отправляет их через прокси. Отказ resolver'а абонентов виден в health-контуре и
сообщается честно, а не маскируется под работающие правила.

## Rationale

- **Только адресные правила (без доменов).** Отвергнуто: продукт перестаёт
  выполнять своё обещание, а именно доменные правила и есть смысл «выборочной
  маршрутизации» для пользователя.
- **Гибрид: перехват только у тех, у кого есть доменные правила.** Отвергнуто:
  поведение различается от устройства к устройству, а диагностика «почему у него
  не тот выход» превращается в гадание.
- **Серверный условный форвардинг зон абонента.** Невозможен по маршрутизации:
  панель не находится в сети абонента. Разбор локальных зон на клиенте (NRPT,
  scoped resolvers) остаётся клиентским ПО и панелью не обещается.

## Consequences

- Генератор клиентских конфигураций обязан уметь: несколько resolver'ов в одной
  записи (это уже поддержано живой конфигурацией) и список исключений локальной
  сети в `AllowedIPs`.
- Панель обязана показывать следствие выбора: «свой DNS» означает отказ от
  доменных правил для этого устройства, а не «всё сразу».
- Появляется требование к health-контуру resolver'а: упавший DNS абонентов —
  это видимая авария, а не тихая деградация.
- Доменные правила и чужой внутренний DNS несовместимы **в пределах одного
  устройства** — это следствие того, что панель находится вне сети абонента, и
  записано как осознанная граница, а не как недоделка.
