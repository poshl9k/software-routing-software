# Подключение ноды к мастер-порталу без SSH

Мастер хранит записи абонентов, подписок и устройств; нода исполняет только назначенные ей операции. Регистрация ноды **не переносит** существующие туннели, пиры или локальные учётные записи и не меняет подписки. Для миграции нужна отдельная сверка.

## Перед началом

- На мастере (`my.poshl9k.ru`) и на ноде должны быть доступны админ-панели по HTTPS с действительными сертификатами.
- DNS и IPv4/IPv6 ноды должны вести на эту ноду. В мастере указывайте её публичный HTTPS URL без `/internal`.
- Подготовьте внешний IP мастера, с которого он обращается к ноде. Это значение ограничивает опубликованный bridge-маршрут; оно должно совпадать с фактическим адресом исходящего соединения.
- Путь `/internal/master/*` публикуется только для точного TLS hostname ноды и разрешённого IP мастера. Прочие источники не получают доступ к master-only API. Локальный subscriber portal и туннели не останавливаются и не изменяются самим onboarding.

## Подключение через веб-интерфейсы

1. На `https://my.poshl9k.ru` откройте «Ноды» → «Добавить ноду». Введите имя, HTTPS Bridge URL ноды и ёмкость. HTTP URL, userinfo, query и fragment не принимаются.
2. Мастер создаст запись и один раз покажет bearer-токен. Он зашифрован в базе мастера; список нод его не возвращает. Не помещайте токен в чат, URL, команду, заметку или скриншот. Если диалог потерян, не создавайте дубль: для ещё не связывавшейся ноды используйте «Переиздать токен» — прежний токен сразу станет недействительным.
3. По кнопке «Открыть панель ноды» перейдите на HTTPS-панель ноды и войдите как администратор. Откройте «Обслуживание» → «Мастер».
4. Вставьте токен, введите hostname мастера (например, `my.poshl9k.ru`) и внешний IP мастера. Нажмите «Сохранить и подключить». Токен передаётся только в теле same-origin API-запроса, хранится на ноде зашифрованным и не возвращается в ответе или статусе.
5. Дождитесь состояния «Мастер подтвердил токен». До аутентифицированного запроса мастера интерфейс показывает ожидание, а не завершённое подключение. Состояние маршрута Caddy отображается отдельно: «конфигурация содержит ожидаемый маршрут» само по себе не подтверждает доступность мастера.

Ввод токена повторно разрешён только пока credential ожидает проверки; он нужен для исправления/замены токена до первого успешного запроса мастера. После подтверждения установка блокируется. Для ротации уже используемого токена применяйте отдельную операцию «Сменить токен» на мастере при доступной ноде.

## Границы и восстановление

- Переиздание недоступно после первого успешного обращения ноды к мастеру или при наличии устройств в master DB. Если состояние не соответствует этому условию, сначала проверьте карточку ноды и её устройства, не создавайте вторую запись.
- Onboarding не подтверждается одним HTTP 200 от панели, наличием токена или записью конфигурации на диске: требуется аутентифицированный probe мастера.
- Не вставляйте bearer-токен в URL или командную строку и не проверяйте bridge, открывая его без авторизации из браузера.
- Self-service unlink/откат публикации пока не предоставлен этим экраном. Не редактируйте Caddy JSON и host-owned marker вручную; используйте согласованную административную процедуру восстановления. Не останавливайте subscriber portal или туннель как способ проверки onboarding.
