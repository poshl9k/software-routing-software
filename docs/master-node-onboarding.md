# Подключение `rg3` к мастер-порталу

`rg3.poshl9k.ru` остаётся действующей панелью с собственным туннелем. Регистрация ноды **не переносит** её существующих пиров и абонентов, не меняет их подписки и не включает Telegram/Stars. Для их миграции нужна отдельная сверка.

## Подготовка хоста

На ноде установлен сервис `vs-router-web-master`, слушающий **только** Unix-сокет `/run/vs-router/web/master.sock`. Он обслуживает лишь `/internal/master/*`; локальные `/internal/portal/*` в этом приложении отсутствуют. Caddy публикует этот сокет под `https://rg3.poshl9k.ru/internal/master/*` только для исходного IP мастера `85.209.159.130`. Для остальных источников этот путь отвечает 403; панель и её `/health` остаются доступны как прежде.

Root-owned `/etc/vs-router/master-bridge-publication.json` задаёт точный TLS hostname и разрешённый IP. `CaddyReloader.install()` добавляет правила к применяемому файлу и при boot restore, поэтому обычный apply/rollback не стирает публикацию. Нельзя добавлять этот путь через временный Caddy admin route: он исчезнет при перезапуске/применении панели.

На мастере отдельный ключ `/root/.ssh/vs-master-rg3` разрешён на `rg3` **только** с forced command `/usr/local/libexec/vs-router/master-bridge-token-bootstrap` и `restrict`; он не даёт общего SSH shell. Перед его установкой отпечаток ED25519 ноды сверяют с консолью провайдера. Не переносите существующий личный приватный SSH-ключ на мастер.

## Самостоятельное подключение

1. Откройте `https://my.poshl9k.ru` → «Ноды» → «Добавить ноду». Имя: `rg3`. Bridge URL: **`https://rg3.poshl9k.ru`**, без `/internal` (клиент сам добавляет маршрут). Ёмкость задайте по планируемому числу *новых* активных устройств; существующие пиры не появляются в учёте мастера автоматически.
2. Скопируйте одноразовый токен из диалога **не в чат**. На мастер-ноде откройте интерактивный root shell и выполните команду, показанную в том же диалоге. `read -s` принимает токен из терминала без записи значения в историю shell; SSH передаёт его через stdin на restricted command. После `Node bridge token installed` токен зашифрован в router DB ноды, а повторная установка запрещена.
3. Обновите список нод после цикла опроса worker. Проверка с мастер-ноды: `curl -sS -o /dev/null -w '%{http_code}\n' https://rg3.poshl9k.ru/internal/master/state` без токена должна вернуть **403** (не `200 text/html`); мастер использует свой токен. Для проверки авторизованного состояния используйте состояние ноды в интерфейсе, не вставляйте токен в URL или командную строку.

Если создание записи прошло, но токен не установлен, сохраните показанный токен до закрытия диалога и повторите только SSH-команду. Не создавайте вторую запись и не меняйте токен кнопкой ротации до первой установки.

## Откат публикации

При проблемах с маршрутом сначала отключите ноду в мастере, затем на `rg3` удалите **только** `/etc/vs-router/master-bridge-publication.json` и повторно установите `/etc/vs-router/applied/caddy.conf` через штатный привилегированный `CaddyReloader` с проверкой `caddy validate` и `/health`. Не правьте генератор, туннели или подтверждённую конфигурацию ради отката маршрута. Сервис `vs-router-web-master` можно остановить отдельно от панели/туннеля. Токен в router DB при откате маршрута остаётся зашифрованным и должен отзываться отдельной операцией.
