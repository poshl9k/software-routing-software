# План устранения для «живых» тестов

Цель этапа (**scope A**): пройти сквозной путь на чистой Debian 13 VM из
собранного ISO — установка → bootstrap без ручных догонов → назначение
management LAN → onboarding → первый apply → WG-туннель (kernel) → reboot с
сохранением конфигурации и доступа.

Решения, принятые в сессии грилла:

- **Довоз кода (B):** ISO самодостаточен (исходники в образе), после установки
  панель **предлагает онлайн-обновление** до зафиксированного проверенного
  выпуска — только после сверки текущего выпуска.
- **Идентификатор выпуска** = `commit id` + `semver`, записывается при установке
  (`/etc/vs-router/version.json`) и отдаётся read-only `GET /api/release`.
  В `CONTEXT.md` «версия» в UI панели = **версия конфигурации**; продукт =
  **выпуск установки**.
- **`update.sh`** обязан тянуть зафиксированный выпуск, а не `git pull` ветки
  (сейчас нарушает ADR-0005).

Статусы: `[ ]` открыто, `[~]` в работе, `[x]` выполнено.

## P1 — Установочный путь несамодостаточен и молча падает

Факт: preseed клонирует репо с GitHub и делает `checkout @VS_ROUTER_REVISION@`.
Если коммит не запушен (наш случай `c574b4c`) — `late_command` падает,
`installer-prepare.sh` не выполняется, firstboot-сервис не включается → VM без
bootstrap и без сигнала об ошибке.

- [x] B: `make-iso.sh` вкладывает исходники зафиксированного коммита в ISO;
      preseed распаковывает их локально вместо сетевого clone.
      Комментарий: `git archive` выпуска → `/vs-router/source.tar.gz`; preseed
      копирует файлы из `/cdrom/vs-router/` и запускает `install-source.sh`.
      Проверено реальной сборкой ISO (файлы в образе, sha256 OK, clone убран).
- [x] Проверка целостности вложенных исходников (sha256 + commit id).
      Комментарий: `sha256sum -c` в таргете; `REVISION` пишется рядом и
      фиксируется install.sh в `version.json`.
- [x] Явный **маркер незавершённой установки** + причина на локальную консоль +
      явный повтор (`--retry`); без бесконечных автоповторов.
      Комментарий: `installer/install-source.sh` пишет
      `/var/lib/vs-router-bootstrap/incomplete` и печатает причину в
      `/dev/console`; тарбол и скрипт остаются для повтора
      `sh /opt/vs-router/install-source.sh`; маркер снимается при успехе.
      Осталось: связать маркер с firstboot-сервисом (не запускать bootstrap при
      незавершённой установке).
- [x] Связь маркера с firstboot: bootstrap не запускается при `incomplete`.
      Комментарий: `firstboot-bootstrap.sh` проверяет маркер и отказывается
      работать, печатая причину на консоль; тест
      `test_firstboot_refuses_incomplete_install`.
- [x] `install.sh` пишет `/etc/vs-router/version.json` (commit + semver + source).
      Комментарий: commit берётся из `.git`, иначе из вендоренного `REVISION`;
      источник проставляется `iso` (bootstrap) / `online` (update).

## P2 — Нет консольного доступа на установленной системе

Факт: установленный grub не имеет `console=ttyS0`; `virsh console` молчит, доступ
только через VNC. ADR-0002 требует локальную консоль.

- [ ] Добавить serial console (grub `console=ttyS0,115200n8`) в установленную
      систему для headless-доступа.
- [ ] Документировать путь VNC/console как резервный.
