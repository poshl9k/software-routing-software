## Fail-closed: граница доказанного

После reboot `nft list table inet vs_router_tproxy_guard` → `iifname "enp2s0" counter packets 0 bytes 0 drop comment "tproxy_containment"`; в `inet vs_router_tproxy_preauth` цепь `transit` → `counter packets 0 bytes 0 drop`. Значит guard-правила **есть**, но не было подтверждённого выбранного транзитного пакета: счётчики нулевые. WAN origin/положительный контроль/сравнение после остановки outbound **не выполнялись**. Поэтому нельзя объявлять fail-closed packet-proof: отсутствие перехвата и неработающий resolver мешают положительному контролю, а timeout недоступного origin сам по себе ничего не доказывает. Риск безопасности: до reboot при `confirmed` guards вообще отсутствовали, при этом sing-box и policy route запущены; не считать продукт защищённым по marker. Лабораторные namespace-пробы lab-27…33 не заменяют этот недостающий продуктовый packet-proof.
