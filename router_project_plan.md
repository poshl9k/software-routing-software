## Цель и границы MVP

Создать устанавливаемый на выделенную Linux-машину или VM роутер с современной веб-панелью. В MVP администратор может настроить сеть, DHCP/DNS, firewall, два типа VPN-туннелей, входящие сайты и DDNS без ручного редактирования конфигурационных файлов. Ошибочное изменение сетевых параметров можно откатить из панели или автоматически по таймеру.

За визуальный референс принят концепт главного экрана из обсуждения: тёмное левое меню, светлая рабочая область, компактные таблицы, явные состояния сервисов, умеренные синие и зелёные акценты. Рабочее имя продукта — **vs-router**; финальное имя/бренд — отдельное решение перед пилотом.

**Не входит в MVP:** маршрутизация по доменам/IP/CIDR как пользовательский конструктор политик, полноценный магазин модулей, динамические протоколы маршрутизации, HA-кластер, собственный установочный образ ОС, второй WAN и переключение, 2FA, роль оператора в UI. Архитектурные точки расширения для них закладываются заранее. Псевдонимы firewall и их импорт/экспорт, напротив, входят в MVP.

## Принятые решения (сводка сессии проектирования)

| Область | Решение |
| --- | --- |
| Пользователь | Продвинутый домашний/prosumer-админ или админ малого офиса; один администратор. Панель — только из LAN/VPN, HTTPS всегда, 2FA после MVP |
| Применение конфигурации | Черновик (persisted-версия) применяется целиком; подтверждение — явное действие; перезагрузка не подтверждает конфиг; один активный цикл применения |
| «Безопасная настройка» | Параметр панели, по умолчанию выключен; включает окно подтверждения (60–600 с, дефолт 180), маркер с дедлайном на диске, автооткат по таймеру через механизм на хосте и пробу доступности панели; предлагается включить в onboarding-мастере |
| Архитектура | Непривилегированный FastAPI-бэкенд + привилегированный агент; канал — unix socket с проверкой peer-credentials; whitelist RPC-методов; агент — источник истины аудита |
| Платформа | Debian 13 stable (Ubuntu — следующий поддерживаемый дистрибутив; ADR-0001); AmneziaWG userspace в MVP, kernel-модуль — целевая форма после MVP |
| DNS | Unbound: forwarding по умолчанию, рекурсия опцией; per-domain forwards, host overrides, привязка к интерфейсам, журнал запросов с ротацией |
| DHCP | Kea DHCPv4: конфиг-файл — источник истины (`kea-dhcp4 -t` + config-reload); ctrl-agent (unix socket) — чтение аренд/статистики; резервации внутри и вне пула |
| Firewall | Модель pfSense: правила на зоне входа (вкладки зон), first match wins, pass/block/reject, неявный default deny, anti-lockout, счётчики правил; зоны wan/lan/router, неназначенный интерфейс fail-closed |
| NAT | Port forward — отдельный список с автогенерируемыми filter-правилами; outbound NAT в режимах pfSense (авто/гибрид/ручные/выкл) с выбором translation address и флагом «Do not NAT» |
| WAN-адреса | Упорядоченный список реальных адресов на WAN-интерфейсе: основной + дополнительные (/32), равноценны в правилах; без типов VIP |
| Псевдонимы | Типы «Адреса» и «Порты»; вложенность только совместимых типов, циклы запрещены; пересечения — предупреждение; лимиты 10 000 (warn) / 100 000 (error) |
| Туннели | Туннель = интерфейс + роль (сервер/клиент, не меняется после создания) + протокол (wg/awg); AllowedIPs ≠ маршрут; импорт сторонних .conf; экспорт сервера — пакет клиентских конфигов/QR |
| Caddy | Режимы сертификата: Auto HTTP-01 (привязка к WAN-адресу), Auto DNS-01 (если провайдер поддерживает), ручной, TLS passthrough (по результату проверки L4); `caddy validate` + graceful reload |
| DDNS | Cloudflare + RFC 2136; адаптерная архитектура; журнал обновлений и ошибок |
| Бэкап | Экспорт — зашифрованный архив (пароль админа; без него секреты не восстанавливаются); локальный автобэкап по расписанию с секретами |
| Безопасность панели | Собственный CA роутера + серверный сертификат при первом старте; argon2id; локальные учётки; rate limit на login; CSRF/origin-защита |
| Масштаб MVP | До 20 интерфейсов / 10 зон; 10 подсетей / 500 аренд; 500 правил; 100 алиасов (10 000 элементов); 10 туннелей / 50 пиров; 20 сайтов; 1 Гбит/с NAT; min 2 vCPU / 2 ГБ RAM / 16 ГБ |
| Обновления | Ядро Linux — только при уязвимостях; компоненты — фиксированные версии, обновления по безопасности/блокирующим дефектам; после обновления ядра обязательная проверка туннелей и сетевого стека |
| Локализация | i18n с первого дня; русский по умолчанию; общепризнанные термины на латинице; системные идентификаторы фиксированы на латинице |

## Предлагаемая техническая основа

| Область | Базовый выбор | Особенность интеграции |
| --- | --- | --- |
| Платформа | Debian 13 stable; Ubuntu — следующий поддерживаемый дистрибутив (ADR-0001) | Фиксируемые версии пакетов; установщик проектируется с учётом добавления второго дистрибутива без смены архитектуры |
| Сетевые интерфейсы | `systemd-networkd`, netlink/iproute2 | Физические порты, мосты, VLAN, адреса (в т.ч. дополнительные WAN-адреса /32), статические маршруты |
| Firewall и NAT | `nftables` | Центральный генератор правил (модель pfSense), псевдонимы → nftables-sets, проверка `nft -c` перед применением |
| DHCP | Kea DHCPv4 | Конфиг-файл — источник истины; ctrl-agent для чтения аренд и статистики; резервации внутри и вне пула |
| DNS | Unbound | Forwarding по умолчанию; per-domain forwards, host overrides, привязка к интерфейсам; `unbound-checkconf` перед применением |
| Туннели | WireGuard и AmneziaWG (userspace `amneziawg-go`) | Единая модель маршрутов/состояний; явная роль сервер/клиент; kernel-модуль AmneziaWG — после MVP |
| Входящий прокси | Caddy | HTTP/HTTPS, 4 режима сертификата; TLS passthrough через L4-модуль — по результату лабораторной проверки |
| Backend и UI | FastAPI + React/TypeScript + MUI | Backend хранит желаемое состояние; привилегированный агент применяет его через unix socket RPC |
| Хранилище панели | SQLite на одной машине для MVP | Шифрованный бэкап и миграции схемы; ротация журналов; секреты не возвращаются API открытым текстом |

Контроллер остаётся единственным владельцем сетевых настроек. Внешние модули в будущем запрашивают операции через ограниченный API, а не меняют firewall и маршруты напрямую.

### Поведение псевдонимов в MVP

Псевдоним — именованный типизированный объект, а не текстовая подстановка. Начальные типы: `Адреса` (IPv4/IPv6 хосты, CIDR, диапазоны) и `Порты` (отдельные порты и диапазоны TCP/UDP). Группы могут содержать элементы и другие псевдонимы совместимого типа. UI показывает раскрытое содержимое, количество итоговых элементов, места использования и ошибки компиляции. Вложение с циклом запрещено; пересечения содержимого алиасов допустимы и показываются как предупреждение.

Импорт JSON переносит имена, описания, типы, элементы и связи между группами; версия схемы формата фиксируется. CSV/TXT предназначены для обмена простыми списками адресов или портов; экспорт выдаёт файл того же уровня сложности. Импорт не применяет изменения сразу: сначала проверка и предпросмотр, затем подтверждение с обычным механизмом отката конфигурации.

Возможное расширение после MVP: FQDN-псевдонимы, списки по URL с расписанием обновления, готовые наборы RFC-сетей, географические и ASN-группы. FQDN означает динамический набор полученных DNS-адресов и не гарантирует соответствия каждому соединению по доменному имени; его следует вводить вместе с диагностикой DNS-обновлений. Для внешних URL-источников нужны ограничения размера, частоты и доступных адресов загрузки.

## После MVP

1. Policy routing по источнику/назначению IP и CIDR, порту, интерфейсу и выбранному туннелю; приоритеты и исключения.
2. Правила по доменам через DNS-ответы и адресные наборы: показывать фактически выбранные IP, время жизни и ограничения при стороннем DNS, CDN и общих IP.
3. Второй WAN, проверки доступности и переключение; параллельно — Ubuntu как второй поддерживаемый дистрибутив.
4. AmneziaWG как kernel-модуль (производительность туннелей); пулы outbound NAT и EIM-NAT; 2FA (TOTP); роль оператора в UI.
5. Публичный SDK модулей: манифест, права, страницы UI, миграции, установка/обновление/удаление и разрешение конфликтов.
6. Расширенные IPv6, DHCPv6/RA, динамическая маршрутизация и HA по реальным сценариям использования.
